# Session 11 Implementation Plan — Folder Sync & Compare Engine

## Overview

Implement the `FeaturesSync` module: a folder comparator that walks two
`FileSystemProvider` roots concurrently, produces typed `Difference` rows,
feeds those rows into a pure plan builder, and provides a unit-testable sync
engine that executes the plan via a protocol-shaped collaborator.

**Dependency constraint:** `Package.swift` is frozen. `FeaturesSync` declares
`extraDependencies: []` — it imports only `Core`. The test target (`FeaturesTests`)
imports both `FeaturesOperations` and `FeaturesSync`, so tests may use both.

## Type Design

All enums that live inside actors or structs are lifted to module-level
(SwiftLint `nesting` rule; confirmed by Session 10 decisions).

### Difference.swift

```swift
// Module-level — not nested
public enum DifferenceStatus: Sendable, Hashable, Codable {
    case matched      // within tolerance on both sides
    case modified     // exists on both sides but differs (size, mtime, or hash)
    case leftOnly     // exists only on left
    case rightOnly    // exists only on right
}

public struct Difference: Sendable, Identifiable {
    public typealias ID = UUID
    public let id: ID                    // synthetic, for list diffing
    public let relativePath: FilePath    // relative to each root (scheme = left root's scheme)
    public let status: DifferenceStatus
    public let leftItem: FileItem?       // nil when rightOnly
    public let rightItem: FileItem?      // nil when leftOnly
    
    public init(id: ID = UUID(), relativePath: FilePath, status: DifferenceStatus,
                leftItem: FileItem?, rightItem: FileItem?)
}
```

`relativePath` uses the left root's scheme as convention; its components
are the path segments relative to either root (e.g., `["src", "foo.swift"]`).

### SyncOptions.swift

```swift
// Module-level enums
public enum SyncMode: String, Sendable, Codable, Hashable, CaseIterable {
    case oneWayMirror       // left → right; extras on right are deleted
    case oneWayContribute   // left → right; extras on right are kept
    case twoWay             // bidirectional; conflicts resolved by strategy
}

public enum ConflictResolutionStrategy: String, Sendable, Codable, Hashable, CaseIterable {
    case newerWins   // compare modificationDate; left wins on tie
    case largerWins  // compare sizeInBytes;       left wins on tie
    case manual      // surfaces via SyncEngine continuation per conflict
}

public struct SyncOptions: Sendable {
    public let mode: SyncMode
    public let ignoreGlobs: [String]    // GlobMatcher patterns; empty = no exclusions
    public let sizeTolerance: Int64     // bytes; files ≤ this delta are "same size"
    public let mtimeTolerance: TimeInterval  // seconds; 0 = exact match required
    public let conflictResolution: ConflictResolutionStrategy
    public let useDeepHash: Bool        // false = fast path (size+mtime only)
    
    public static let `default`: SyncOptions   // oneWayMirror, no globs, 0 tolerance, newerWins, fast
    
    public init(mode: SyncMode = .oneWayMirror,
                ignoreGlobs: [String] = [],
                sizeTolerance: Int64 = 0,
                mtimeTolerance: TimeInterval = 0,
                conflictResolution: ConflictResolutionStrategy = .newerWins,
                useDeepHash: Bool = false)
}
```

### HashStrategy.swift

Provides the sha256 streaming helper and the readable-provider protocol.
`CryptoKit` is a system framework; no `Package.swift` change needed.

```swift
import Core
import CryptoKit
import Foundation

// Protocol for providers that support content reading (used by deep compare).
// Defined here, not in FeaturesOperations, to avoid a cross-module dependency.
// LocalFileSystemProvider / RemoteProviders add conformance in their sessions.
public protocol SyncReadableProvider: FileSystemProvider {
    func readChunks(
        at path: FilePath,
        chunkSize: Int
    ) -> AsyncThrowingStream<Data, any Error>
}

// Namespace for hash utilities
public enum HashStrategy {
    public static let defaultChunkSize: Int = 256 * 1024   // 256 KB

    /// Computes a streaming SHA-256 digest from `stream`.
    ///
    /// Calls `Task.checkCancellation()` between chunks so parent-task
    /// cancellation halts the hash mid-stream.
    public static func sha256(
        reading stream: AsyncThrowingStream<Data, any Error>
    ) async throws -> SHA256Digest {
        var hasher = SHA256()
        for try await chunk in stream {
            try Task.checkCancellation()
            hasher.update(data: chunk)
        }
        return hasher.finalize()
    }
}
```

### FolderComparator.swift

```swift
import Core
import Foundation

/// Walks two `FileSystemProvider` roots concurrently and emits `Difference` rows.
///
/// Enumeration of both sides runs in parallel via `withThrowingTaskGroup`.
/// The comparator is an actor so `compare` can be called from any async context.
/// All blocking work is I/O via the provider, which already dispatches off-actor.
public actor FolderComparator {
    private let leftProvider: any FileSystemProvider
    private let rightProvider: any FileSystemProvider
    private let options: SyncOptions

    public init(
        leftProvider: any FileSystemProvider,
        rightProvider: any FileSystemProvider,
        options: SyncOptions = .default
    )

    /// Walk both roots and return the full difference list.
    ///
    /// The caller must pass absolute root paths compatible with each provider.
    /// Ignore globs are matched against relative POSIX paths.
    public func compare(
        leftRoot: FilePath,
        rightRoot: FilePath
    ) async throws -> [Difference]
}

// Private helpers (non-public):
// - enumerate(root:provider:) → [FileItem]  (recursive, includes hidden)
// - relativePosix(of:relativeTo:) → String?
// - isIgnored(_ relativePosix: String) → Bool  (GlobMatcher)
// - isFastDifferent(left:right:) → Bool  (size + mtime within tolerance)
// - isDeepDifferent(leftPath:rightPath:) async throws → Bool  (sha256)
```

**Concurrent enumeration pattern:**
```swift
// Uses withThrowingTaskGroup to collect both sides simultaneously.
let (leftItems, rightItems) = try await withThrowingTaskGroup(of: (Bool, [FileItem]).self) { group in
    group.addTask { (true, try await Self.enumerate(root: leftRoot, on: leftProvider)) }
    group.addTask { (false, try await Self.enumerate(root: rightRoot, on: rightProvider)) }
    var left: [FileItem] = []
    var right: [FileItem] = []
    for try await (isLeft, items) in group {
        if isLeft { left = items } else { right = items }
    }
    return (left, right)
}
```

**Relative-path keying:**
`FilePath.relative(to:)` returns `[String]?`. Build a dictionary keyed by
`relativePosix` (`String`) for O(1) lookup. Re-construct `FilePath(scheme:components:)`
for `Difference.relativePath` using the left root's scheme.

**Ignore-glob filtering:**
Call `GlobMatcher.matches(pattern:path:caseSensitive:)` on each relative POSIX
string. If any pattern in `options.ignoreGlobs` matches, exclude the item from
comparison. Apply the filter to both sides independently.

**Deep compare path:**
If `options.useDeepHash` is `true`, cast both providers to `any SyncReadableProvider`.
If either cast fails, throw `StevedoreError.unsupported("deep compare requires SyncReadableProvider conformance")`.
Hash both files, compare `SHA256Digest` equality.

### SyncPlan.swift

```swift
import Core

// Module-level (SwiftLint nesting rule)
public enum SyncStep: Sendable {
    case copyToRight(relativePath: FilePath, left: FileItem)
    case copyToLeft(relativePath: FilePath, right: FileItem)
    case deleteFromRight(relativePath: FilePath)
    case deleteFromLeft(relativePath: FilePath)
    case replaceRight(relativePath: FilePath, left: FileItem)  // right overwritten with left
    case replaceLeft(relativePath: FilePath, right: FileItem)  // left overwritten with right
    case conflict(relativePath: FilePath, left: FileItem, right: FileItem)  // manual only
}

/// A derived, pure plan. No I/O. Fully deterministic for a given input.
public struct SyncPlan: Sendable {
    public let differences: [Difference]
    public let steps: [SyncStep]

    /// Build a plan from comparator output and sync options.
    ///
    /// Pure: no I/O, no async. Testable in isolation.
    public static func build(from differences: [Difference], options: SyncOptions) -> SyncPlan
}
```

**`build` logic per (DifferenceStatus, SyncMode):**

| Status   | oneWayMirror     | oneWayContribute | twoWay (newerWins/largerWins/manual) |
|----------|------------------|------------------|--------------------------------------|
| matched  | no step          | no step          | no step                              |
| leftOnly | copyToRight      | copyToRight      | copyToRight                          |
| rightOnly| deleteFromRight  | (no step)        | copyToLeft                           |
| modified | copyToRight      | copyToRight      | newerWins/largerWins → replace*; manual → conflict |

*newerWins: compare `modificationDate`; if left.mtime ≥ right.mtime → replaceRight,
else → replaceLeft. If either mtime is nil → conflict.
*largerWins: compare `sizeInBytes`; if left.size ≥ right.size → replaceRight,
else → replaceLeft. If either size is nil → conflict.

**Exit criterion:** `build(from: allMatched, options: ...)` returns `.steps.isEmpty == true`.

### SyncEngine.swift

```swift
import Core
import Foundation

// Module-level types (SwiftLint nesting rule)

/// Outcome of a manual conflict resolution.
public enum SyncConflictResolution: Sendable, Equatable {
    case keepLeft
    case keepRight
    case skip
}

/// Protocol for the file executor the SyncEngine delegates to.
///
/// The production implementation wires into FeaturesOperations.FileOperationQueue
/// (assembled at the UI layer). Tests supply a lightweight recording fake.
public protocol SyncFileExecutor: Sendable {
    func copy(
        from source: FilePath,
        on sourceProvider: any FileSystemProvider,
        to destination: FilePath,
        on destinationProvider: any FileSystemProvider
    ) async throws

    func delete(at path: FilePath, on provider: any FileSystemProvider) async throws
}

/// Actor that executes a `SyncPlan` against two providers.
///
/// - Suspends on `conflict` steps when `ConflictResolutionStrategy == .manual`,
///   awaiting `resolveConflict(at:with:)` from the UI layer.
/// - Reports per-step progress to `SyncProgressTracker`.
public actor SyncEngine {
    private let leftProvider: any FileSystemProvider
    private let rightProvider: any FileSystemProvider
    private let executor: any SyncFileExecutor
    private let progressTracker: SyncProgressTracker
    private var pendingConflicts: [FilePath: CheckedContinuation<SyncConflictResolution, Never>]

    public init(
        leftProvider: any FileSystemProvider,
        rightProvider: any FileSystemProvider,
        executor: any SyncFileExecutor,
        progressTracker: SyncProgressTracker = SyncProgressTracker()
    )

    /// Execute a plan. Returns when all steps complete or an error is thrown.
    ///
    /// `leftRoot` and `rightRoot` are used to resolve absolute paths from
    /// each step's `relativePath` components.
    public func execute(
        plan: SyncPlan,
        leftRoot: FilePath,
        rightRoot: FilePath
    ) async throws

    /// Unblock a suspended conflict step. No-op if path is not waiting.
    public func resolveConflict(at relativePath: FilePath, with resolution: SyncConflictResolution)
}
```

**Conflict suspension pattern** (mirrors ConflictResolver from Session 10):
```swift
// Inside execute, when step == .conflict:
let resolution = await withCheckedContinuation { [relativePath] continuation in
    pendingConflicts[relativePath] = continuation
}
// Apply resolution: .keepLeft → replaceRight, .keepRight → replaceLeft, .skip → continue
```

### SyncProgress.swift

```swift
import Core
import Foundation

public struct SyncProgress: Sendable, Equatable {
    public let rowsCompared: Int   // total differences found
    public let rowsPending: Int    // steps not yet started
    public let rowsDone: Int       // steps completed (success or skip)

    public var fraction: Double? {
        guard rowsCompared > 0 else { return nil }
        return min(1.0, Double(rowsDone) / Double(rowsCompared))
    }

    public init(rowsCompared: Int, rowsPending: Int, rowsDone: Int)
}

/// Actor that collects sync step progress and broadcasts snapshots to subscribers.
public actor SyncProgressTracker {
    private(set) public var current: SyncProgress
    private var continuations: [UUID: AsyncStream<SyncProgress>.Continuation]

    public init()

    public func setTotal(rowsCompared: Int) async
    public func stepStarted() async
    public func stepCompleted() async

    public nonisolated func progressStream() -> AsyncStream<SyncProgress>
}
```

## Key Design Decisions

### 1. `FeaturesSync` imports only `Core`
`Package.swift` is frozen. `SyncEngine` cannot import `FeaturesOperations` directly.
It defines `SyncFileExecutor` as its own protocol; the wiring to
`FileOperationQueue` happens at the UI layer (Session 21).

### 2. `SyncReadableProvider` is Sync-local, not shared with `DataReadableProvider`
Both protocols have the same semantic shape (`read(at:chunkSize:)`), but they live
in different modules. Providers conform to both independently. This avoids any
cross-module type coupling.

### 3. Plan generation is pure and synchronous
`SyncPlan.build(from:options:)` is a `static func` with no `async`, no I/O, no
actor isolation. This makes the plan deterministic and freely unit-testable.

### 4. `withThrowingTaskGroup` for concurrent enumeration
Both sides are enumerated in parallel. If one side throws (e.g., permission denied),
the `TaskGroup` propagates the error and cancels the other side automatically.

### 5. Conflict continuation pattern mirrors Session 10's `ConflictResolver`
`pendingConflicts: [FilePath: CheckedContinuation<SyncConflictResolution, Never>]`
in `SyncEngine`. `resolveConflict(at:with:)` resumes the continuation. UI layer
listens for `SyncProgress` stream to know when a conflict needs resolution.

### 6. Ignore globs applied to relative POSIX paths
`GlobMatcher.matches(pattern:path:caseSensitive:)` is called on each item's
relative path string (e.g., `"src/foo/.DS_Store"`). Items matching any glob in
`SyncOptions.ignoreGlobs` are excluded from both sides before comparison.

### 7. `DifferenceStatus` at module level (not nested)
Follows the SwiftLint `nesting` rule established by Session 10.

### 8. Relative path uses left root's scheme as convention
`Difference.relativePath` and `SyncStep` payloads use the left provider's scheme.
The components are relative; the scheme is used only as a technical requirement
of `FilePath`. Engine resolves absolute paths as:
- left abs = `leftRoot.appending(step.relativePath.components)`
- right abs = `rightRoot.appending(step.relativePath.components)`

### 9. mtimeTolerance via `TimeInterval` arithmetic
`abs(left.modificationDate.timeIntervalSince(right.modificationDate)) <= mtimeTolerance`
where `mtimeTolerance` defaults to 0. FAT/exFAT filesystems round to 2s so
a tolerance of 2.0 is common; the API lets callers set it.

## Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| SwiftLint `nesting` rule violations | All enums declared at module level |
| `function_parameter_count` violations for SyncFileExecutor.copy (5+ params) | Use `// swiftlint:disable function_parameter_count` regions if needed |
| CryptoKit `SHA256Digest` not equatable across Swift versions | `SHA256Digest` conforms to `Digest` which has `==`; confirmed available macOS 14+ |
| `withThrowingTaskGroup` task leak if cancelled before both tasks start | `addTask` is structured; group cancellation is implicit when the closure returns |
| InMemorySyncProvider.enumerate must match InMemoryFileSystemProvider semantics | Copy the snapshotChildren logic pattern, adapt for `[FilePath: Data]` backing |
| `swiftlint:disable function_parameter_count` in `SyncEngine.execute` | Mirror the Session 10 approach for parameter-heavy methods |
| `SyncProgressTracker.progressStream()` unstructured Task for registration | Mirror `TransferProgressTracker.progressStream()` pattern exactly |

## API Contract for the Sync Dialog (Session 21)

The `SyncDialog` (Session 21) should expect:

```swift
// 1. Build a comparator
let comparator = FolderComparator(leftProvider: lProv, rightProvider: rProv, options: opts)
let differences = try await comparator.compare(leftRoot: lRoot, rightRoot: rRoot)

// 2. Build a plan
let plan = SyncPlan.build(from: differences, options: opts)
// Inspect plan.steps to show a preview to the user

// 3. Execute
let engine = SyncEngine(leftProvider: lProv, rightProvider: rProv, executor: myExecutor)
for await progress in await engine.progressTracker.progressStream() { /* update UI */ }
try await engine.execute(plan: plan, leftRoot: lRoot, rightRoot: rRoot)

// 4. Manual conflict (if strategy == .manual)
// The engine suspends; the dialog presents the conflict row.
// User picks resolution:
await engine.resolveConflict(at: conflictRelPath, with: .keepLeft)
```

The `myExecutor` in production connects to `FileOperationQueue` from `FeaturesOperations`
(assembled in Session 21). For now, any `SyncFileExecutor` conformer works.
