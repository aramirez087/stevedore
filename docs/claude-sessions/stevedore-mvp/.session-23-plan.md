# Session 23 Implementation Plan — Connect-to-Server Dialog

## Overview

Build the `UIConnectDialog` module: a modal SwiftUI view that lets the user create or edit a remote
connection (SFTP, FTP, WebDAV, S3, SMB), validate fields, test the connection via an injected
`RemoteConnector`, save credentials via an injected `CredentialStore`, and invoke host callbacks
for save and connect. All credential material is protocol-injected; no Keychain or real network I/O
occurs in tests.

## Key Design Decisions

### 1. Protocol-only dependencies in source; DesignSystem for UI

`ConnectDialogViewModel` imports only `Core` (for `CredentialStore`, `RemoteConnector`,
`RemoteHostDescriptor`, `Credential`, `ConnectionScheme`). Concrete implementations
(`KeychainCredentialStore`, `RemoteProviderRegistry`) are never imported in the library target.
`DesignSystem` is imported for `SDButton`, `SDTextField`, `SDLabel`, `Spacing`, `Theme`.

This keeps the module footprint small and the tests fast (no Citadel/Soto compilation).

### 2. `@Observable` on macOS 14+

`ConnectDialogViewModel` uses `@Observable` (requires macOS 14.0, which matches the deployment
target). No `ObservableObject` / `@Published` pattern needed.

### 3. NSOpenPanel behind an injected closure

`ConnectDialogViewModel` accepts a `keyPickerHandler: @MainActor @Sendable () async -> URL?` at
init time. The default implementation calls `NSOpenPanel.runModal()` on the main actor. Tests pass
a closure that returns a pre-baked URL immediately without touching the UI. This avoids any real
panel interaction in the test suite.

### 4. Validation is synchronous; no partial saves

`validate()` returns `Bool` and populates `validationErrors: [ValidationError]`. The save/connect
paths call `validate()` first and abort on failure. Each `ValidationError` carries a `Field`
discriminator so views can display the error inline with `.accessibilityValue(error.message)`.

### 5. Test-connection failure messages are sanitized at the call site

`testConnection()` never interpolates the raw password, PEM, or passphrase into any failure string.
All failure cases use static strings or only safe values (hostname, scheme name). The
`RedactionTests` suite verifies every `ConnectionTestResult.Status` case with a credential
containing a known sentinel string ("REDACT-ME") and asserts the sentinel is absent from the
`testStatus` failure message.

### 6. `ValidationError.Field` as a top-level type

To avoid SwiftLint's `nesting` rule (which rejects types nested 1+ levels under a `struct`), the
`Field` enum is declared at file scope, not nested inside `ValidationError`.

### 7. Auth mode availability per scheme

```
sftp:   [.password, .sshKey, .anonymous]
ftp:    [.password, .anonymous]
webdav: [.password, .anonymous]
s3:     [.iam, .password]          // .password = access key + secret
smb:    [.password, .anonymous]
```

When the user switches scheme, `AuthSelector` resets `authMode` to the first available option for
the new scheme if the current mode is not in the new set.

### 8. S3 field mapping

For S3, "username" stores the AWS Access Key ID and "password" stores the AWS Secret Access Key.
The region is a separate `s3Region: String` field defaulting to `"us-east-1"`. The bucket is
`s3Bucket: String`. The `hostname` field is optional (empty = default AWS endpoint).

### 9. Port defaults and validation

| Scheme | Default port | Valid range |
|---|---|---|
| sftp | 22 | 1–65535 |
| ftp | 21 | 1–65535 |
| webdav | 443 | 1–65535 |
| smb | 445 | 1–65535 |
| s3 | (none) | (none) |

Port is stored as `portString: String` so the text field can be empty (uses default). Validation
rejects non-numeric or out-of-range values.

### 10. `buildDescriptor()` uses a stable UUID

When creating a new connection, the UUID is generated once in `ConnectDialogViewModel.init` and
reused across save/connect calls. When editing an existing descriptor, the existing `id` is
preserved. This ensures credential store writes and descriptor identity are consistent.

### Step 2 — Delete Placeholder, write ConnectDialogModule.swift

Keep the `UIConnectDialogModule.moduleName` sentinel intact so the existing smoke test continues
to pass.

### Step 3 — Write supporting value types (no imports needed beyond Core)

In order:
1. `AuthMode.swift` — `public enum AuthMode: String, Sendable, Hashable, CaseIterable`
2. `TestConnectionStatus.swift` — `public enum TestConnectionStatus: Sendable`
3. `ValidationError.swift` — `ValidationErrorField` enum at file scope + `ValidationError` struct

Full `@MainActor @Observable` class with:
- All form fields as stored properties
- `validate() -> Bool` populating `validationErrors`
- `buildDescriptor() -> RemoteHostDescriptor`
- `buildCredential() -> Credential?`
- `testConnection() async`
- `save() async throws`
- `connect() async throws`
- Scheme-change side effect resetting `authMode` if needed

### Step 5 — Write AuthSelector.swift

Pure view; reads `@Binding var authMode: AuthMode` and `let availableModes: [AuthMode]`.
Segments for mode picker (using `Picker` with `.segmented` style or button group).
Renders correct credential fields per mode. SSH key picker triggers the injected handler.

### Step 6 — Write TestConnectionButton.swift

Drives `viewModel.testConnection()` on a `Task`. Renders `ProgressView` during `.testing`,
then a labeled icon (`checkmark.circle` / `xmark.circle`) with a success/failure string.

### Step 7 — Write per-scheme form files

Each form: `SFTPForm`, `FTPForm`, `WebDAVForm`, `S3Form`, `SMBForm`.
Each binds to the `ConnectDialogViewModel`. Shows only the fields relevant to its scheme.
Inline error display: when `viewModel.validationErrors` contains an error for a field, show
a `Text(error.message)` in red below the field with `.accessibilityValue(error.message)`.

### Step 8 — Write ConnectDialog.swift

Top-level modal. Contains:
- Scheme selector (`Picker` or segmented control)
- `Group { if ... }` or `switch` to show the correct form
- `TestConnectionButton`
- Footer with Cancel / Save / Connect buttons

### Step 9 — Write tests

Order: `ConnectDialogViewModelTests` → `TestConnectionTests` → `SaveFlowTests` →
`RedactionTests` → `ConnectDialogRenderTests`.

Each test file uses `@MainActor`. Async tests use `async throws`.

## Risks & Mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| `@Observable` + `@MainActor` concurrency friction in tests | Medium | Mark all test classes `@MainActor`; wrap async calls in `async throws` test methods |
| SwiftLint `nesting` violation for `Field` inside `ValidationError` | High | Declare `ValidationErrorField` as a top-level type in `ValidationError.swift` |
| `wrapMultilineStatementBraces` vs `opening_brace` conflict | Medium | Extract multi-line boolean conditions into `let` bindings before `if`; `.swiftformat` already has `--disable wrapMultilineStatementBraces` from Session 04 |
| Package.swift "frozen" concern | Low | The constraint is against new *third-party* packages; adding an intra-package module dep is routine and required for compilation |
| NSOpenPanel in test environment shows real UI | High | Mitigated by injectable `keyPickerHandler` closure; never call real NSOpenPanel in tests |
| S3 "IAM" credential: `RemoteHostDescriptor` has no IAM flag | Low | Pass `credential: nil` for IAM mode; the remote provider infers from missing credential that it should use ambient IAM credentials |
| `swift test --filter ConnectDialogTests` might match zero tests if class names don't contain the exact string | Low | All new test class names contain "ConnectDialog" (e.g., `ConnectDialogViewModelTests`, `TestConnectionTests` won't match but that's OK — use `--filter ConnectDialog`) |
| swiftformat `--lint` arg order bug (session spec has wrong order) | Low | Plan documents the correct form; executor should apply paths-before-flag |

## ConnectDialogViewModel Public API (contract for tests)

```swift
@MainActor
@Observable
public final class ConnectDialogViewModel {
    // Scheme
    public var selectedScheme: ConnectionScheme

    // Common fields
    public var displayName: String
    public var hostname: String
    public var portString: String
    public var username: String
    public var initialPath: String

    // Auth
    public var authMode: AuthMode
    public var password: String
    public var showPassword: Bool
    public var sshKeyURL: URL?
    public var sshKeyPassphrase: String

    // S3-specific
    public var s3Bucket: String
    public var s3Region: String

    // State
    public var validationErrors: [ValidationError]
    public var testStatus: TestConnectionStatus
    public var isSaving: Bool

    // Callbacks
    public var onSave: (@MainActor (RemoteHostDescriptor) -> Void)?
    public var onConnect: (@MainActor (RemoteHostDescriptor) -> Void)?

    public init(
        credentialStore: any CredentialStore,
        connector: any RemoteConnector,
        keyPickerHandler: @escaping @MainActor @Sendable () async -> URL? = ConnectDialogViewModel.defaultKeyPickerHandler(),
        editing: RemoteHostDescriptor? = nil
    )

    public static func availableModes(for scheme: ConnectionScheme) -> [AuthMode]
    public static func defaultPort(for scheme: ConnectionScheme) -> Int?

    @discardableResult
    public func validate() -> Bool

    public func buildDescriptor() -> RemoteHostDescriptor      // uses stable UUID
    public func buildCredential() -> Credential?

    public func testConnection() async
    public func save() async
    public func connect() async
    public func pickSSHKey() async
    public func cancel()
}
```

## Save / Connect Callback Contracts

Both callbacks receive the **final** `RemoteHostDescriptor` (after validation, with the stable UUID
that was used for the credential store `store(_:for:)` call). Callers must not assume the UUID
changes between save and connect.

```
save() flow:
  1. validate() → abort if false
  2. buildDescriptor() → descriptor
  3. buildCredential() → credential?
  4. if credential != nil: credentialStore.store(credential!, for: descriptor.id)
  5. onSave?(descriptor)

connect() flow:
  1–4. Same as save()
  5. onSave?(descriptor)
  6. onConnect?(descriptor)
```

`cancel()` clears `validationErrors` and does nothing else (the host is responsible for dismissing
the sheet / modal on receiving the cancel signal — this module only fires `onSave`/`onConnect`).
