## Critical: `.onDrag`/`.onDrop` are deprecated — use `draggable`/`dropDestination`

The session prompt mentions "uses SwiftUI `.onDrag`/`.onDrop` with a Tab-ID pasteboard type." However,
`.onDrag(_:)` and `.onDrop(of:isTargeted:perform:)` were **deprecated in macOS 13** and produce
deprecation warnings that fail under `swift build -Xswiftc -warnings-as-errors`.

The Operator Rules Definition of Done requires zero warnings. Therefore, this session MUST use the
modern replacement APIs:
- `View.draggable(_:)` — replaces `.onDrag`
- `View.dropDestination(for:action:isTargeted:)` — replaces `.onDrop`

These use the `Transferable` protocol, which replaced `NSItemProvider` in macOS 13+. Both are
available on macOS 14 (our deployment target).

### 2. `Sources/UI/Tabs/TabStripViewModel.swift`

`@MainActor @Observable public final class TabStripViewModel`

**Imports:** `import Core`, `import Foundation`, `import Observation`

**Stored properties (all observed by `@Observable`):**

| Property | Type | Access | Description |
|---|---|---|---|
| `tabs` | `[Tab]` | `public private(set)` | Ordered tab list |
| `selectedTabID` | `Tab.ID?` | `public private(set)` | Currently selected tab |
| `pinnedTabIDs` | `Set<Tab.ID>` | `public private(set)` | Pinned tabs (not closeable via Close Others) |
| `loadingTabIDs` | `Set<Tab.ID>` | `public private(set)` | Tabs whose pane is paginating (shows shimmer) |
| `recentlyClosed` | `[Tab]` | `private` | Undo stack, newest at end |
| `maxUndoStack` | `Int` | `private let` | Cap on undo stack size |
| `onChange` | `(([Tab], Tab.ID?) -> Void)?` | `public` | Persistence callback; called on every state mutation |

**Computed property:**

```swift
public var canReopenClosed: Bool { !recentlyClosed.isEmpty }
```

`@Observable` propagates observation through the stored `recentlyClosed` property (any view reading `canReopenClosed` accesses `recentlyClosed`, registering observation interest on that stored property).

**Init:**

```swift
public init(
    tabs: [Tab] = [],
    selectedTabID: Tab.ID? = nil,
    maxUndoStack: Int = 10,
    onChange: (([Tab], Tab.ID?) -> Void)? = nil
)
```

All parameters have defaults so construction in tests requires no arguments.

**Public methods:**

```swift
// Append tab, select it, fire onChange
public func open(_ tab: Tab)

// Remove tab; push to undo stack; re-select adjacent; fire onChange
// Pinned tabs ARE closeable via this method (explicit user action)
public func close(id: Tab.ID)

// Change selectedTabID if id is present; does NOT fire onChange (UI-only state)
public func select(id: Tab.ID)

// Swap positions using Array.move(fromOffsets:toOffset:); stable identity guarantee
// selectedTabID is unchanged by move
public func reorder(fromID: Tab.ID, toID: Tab.ID)

// Remove all unpinned tabs except the one with `id`; push removed to undo stack
public func closeOthers(keeping id: Tab.ID)

// Remove all unpinned tabs to the right of `id`; push removed to undo stack
public func closeToRight(of id: Tab.ID)

// Insert a copy of tab (new UUID) immediately after it; select the copy
public func duplicate(id: Tab.ID)

// Toggle pin status
public func pin(id: Tab.ID)

// Pop recentlyClosed stack; append to tabs; select it; fire onChange
public func reopenLastClosed()

// Called by host to toggle shimmer on a tab
public func setLoading(_ isLoading: Bool, tabID: Tab.ID)
```

**`reorder` implementation detail:**

```swift
public func reorder(fromID: Tab.ID, toID: Tab.ID) {
    guard fromID != toID,
          let fromIndex = tabs.firstIndex(where: { $0.id == fromID }),
          let toIndex = tabs.firstIndex(where: { $0.id == toID }) else { return }
    let destination = toIndex < fromIndex ? toIndex : toIndex + 1
    tabs.move(fromOffsets: IndexSet(integer: fromIndex), toOffset: destination)
    notifyChange()
}
```

`destination` formula: when the target is to the right of the source, the insertion point is `toIndex + 1` (after the target); when to the left, it is `toIndex` (before the target). This preserves the stable-identity exit criterion.

**`close` selection-adjustment:**

After removal, if `selectedTabID` was the closed tab, clamp to `min(removedIndex, tabs.count - 1)` or `nil` if the strip is empty.

**`closeOthers` / `closeToRight` undo-stack behaviour:**

Append removed tabs to `recentlyClosed`, then truncate to `maxUndoStack` elements from the end (keep most-recent).

**`notifyChange()` (private):**

```swift
private func notifyChange() {
    onChange?(tabs, selectedTabID)
}
```

Called at the end of every mutating method that changes `tabs` or `selectedTabID`.

**onChange callback type:** Non-`@Sendable` closure stored on a `@MainActor` class; always called from `@MainActor` methods, so this is valid in Swift 6 without a `@Sendable` annotation on the closure type.

### 3. `Sources/UI/Tabs/TabReorder.swift`

Provides drag-and-drop tab reordering using the non-deprecated `draggable(_:)` / `dropDestination(for:action:isTargeted:)` API (macOS 13+). The legacy `.onDrag`/`.onDrop` API is deprecated on macOS 13+ and would produce warnings that fail under `-warnings-as-errors`.

**Imports:** `import Core`, `import SwiftUI`

**`TransferableTabID`:**

```swift
struct TransferableTabID: Transferable, Sendable {
    let id: Tab.ID

    static var transferRepresentation: some TransferRepresentation {
        DataRepresentation(contentType: .plainText) { item in
            Data(item.id.uuidString.utf8)
        } importing: { data in
            guard let string = String(data: data, encoding: .utf8),
                  let id = UUID(uuidString: string) else {
                throw TabTransferError.invalidData
            }
            return Self(id: id)
        }
    }
}

private enum TabTransferError: Error {
    case invalidData
}
```

Uses `UTType.plainText` + Data encoding to avoid requiring a registered exported UTType (which would need an app bundle Info.plist entry). In-process drop targets will only receive this data if the initiating drag was from a `TransferableTabID`.

**`View` extension:**

```swift
extension View {
    func tabDraggable(_ tab: Tab) -> some View {
        draggable(TransferableTabID(id: tab.id))
    }

    func tabDropTarget(
        for tab: Tab,
        isTargeted: Binding<Bool>,
        viewModel: TabStripViewModel
    ) -> some View {
        dropDestination(for: TransferableTabID.self) { items, _ in
            guard let fromID = items.first?.id else { return false }
            viewModel.reorder(fromID: fromID, toID: tab.id)
            return true
        } isTargeted: { targeted in
            isTargeted.wrappedValue = targeted
        }
    }
}
```

The `dropDestination(for:action:isTargeted:)` action closure is `@MainActor`-annotated in macOS 14 SDK, so calling `viewModel.reorder(...)` (also `@MainActor`) directly is valid — no concurrency bridging needed.

## Key Design Decisions & Rationale

### D1: `@Observable` over `ObservableObject`

`@Observable` (macOS 14+, `import Observation`) provides property-level observation granularity: SwiftUI only re-renders views that actually read a changed property, not the entire view tree. `ObservableObject` fires for any `@Published` change. Since the strip has multiple independently-rendered `TabItemView`s, per-property observation avoids redundant re-renders.

### D2: `draggable`/`dropDestination` over `.onDrag`/`.onDrop`

`.onDrag` and `.onDrop` are deprecated on macOS 13+ and produce compiler warnings that fail under `-warnings-as-errors`. The session spec mentions `.onDrag`/`.onDrop` but the Operator Rules' Definition of Done (zero warnings) takes precedence. `draggable(_:)` + `dropDestination(for:action:)` achieve identical semantics using the `Transferable` protocol.

### D3: `DataRepresentation(contentType: .plainText)` for `TransferableTabID`

Using `UTType.plainText` avoids registering a custom exported UTType (which requires an Info.plist entry in an app bundle). Since tab reordering is in-process only, the content type collision risk is negligible. A future session adding an exported UTType via the app's Info.plist can upgrade this without changing the `TabReorder.swift` API.

### D4: `viewModel: TabStripViewModel` passed into `TabItemView`

Passing the full `@Observable` view model lets `TabItemView` directly read `isSelected`, `isPinned`, `isLoading` as derived properties. SwiftUI's observation mechanism tracks only the accessed properties, so a tab not currently loading or selected does not re-render when unrelated tabs change.

### D5: `onChange: (([Tab], Tab.ID?) -> Void)?` not `@Sendable`

The callback is always invoked from `@MainActor`-isolated methods. Making it non-`@Sendable` allows callers to capture non-`Sendable` objects (e.g., `WorkspacesRepository` actor references via `Task`). The host (Session 26, Main Window Shell) will inject a closure that schedules a `Task` to persist state, keeping `TabStripViewModel` dependency-free.

### D6: `pinnedTabIDs: Set<Tab.ID>` in view model, not in `Core.Tab`

`Core.Tab` is a persisted `Codable` value type. Adding ephemeral UI state (pin, loading) to it would pollute the Core model and require migration of any persisted workspace. Pin state is UI-level and belongs in the view model.

### D7: No dependency on `WorkspacesRepository` or `ServicesSettings`

The strip is portable: tests construct `TabStripViewModel` with stub `Tab` values and inject a no-op or spy `onChange` callback. No fake service layer is required for tab strip tests.

### D8: `Package.swift` DesignSystem dependency — first-party target, not third-party

The "Package.swift is frozen" rule covers external packages. Adding `DesignSystem` (an intra-package sibling target) to `UITabs.extraDependencies` is equivalent to adding a module import in any other language — it is a build graph change, not a dependency resolution change. This does not add to `Package.resolved`.

## Risks and Mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| `@Observable` with `@MainActor` generates code that violates strict concurrency | Low (tested pattern) | Compile `swift build --target UITabs -Xswiftc -warnings-as-errors` before running tests |
| `dropDestination` action closure is NOT `@MainActor` in macOS 14 SDK | Medium | If calling `viewModel.reorder` fails, wrap with `MainActor.assumeIsolated { }` |
| SwiftLint `cyclomatic_complexity` violation in `TabStrip.body` | Low | Extract `tabListView` and `addButton` as `@ViewBuilder` computed properties |
| SwiftLint `implicit_return` violation on multi-line closures | Medium | Add `return` keyword; SwiftFormat `--self insert` may cause churn — run swiftformat before swiftlint |
| SwiftLint `prefer_self_in_static_references` in `TransferableTabID` | Low | Use `Self(id: id)` not `TransferableTabID(id: id)` in `transferRepresentation` |
| `Tab.path.displayName` returns scheme-prefixed string for root paths | Low | `TabItemView` uses `tab.title ?? tab.path.displayName`; `displayName` handles root path edge case correctly (Session 02 decision) |
| `package DesignSystem` not transitive through `UITabs` if Package.swift change missed | High | The plan explicitly lists the Package.swift change as step 1 |

## Non-obvious Invariants for Future Sessions

- **`select(id:)` does NOT call `notifyChange()`** — selection changes are UI-only and ephemeral within a session; the shell reads `selectedTabID` when explicitly saving (e.g., on window close). If the host needs real-time selection persistence, they can observe `viewModel.selectedTabID` via `onChange` on a timer or use `Task { await save(...) }` in a `withObservationTracking` block.
- **`reorder(fromID:toID:)` does NOT push to `recentlyClosed`** — reordering is not a destructive action.
- **`close(id:)` DOES close a pinned tab** — the method closes any tab regardless of pin state, consistent with browser behavior (context menu "Close" works on pinned tabs). What pinning affects: (a) the close button is hidden in `TabItemView`, (b) `closeOthers` and `closeToRight` skip pinned tabs. Direct close is always allowed.
- **`reopenLastClosed()` calls `open(_:)` internally** — this fires `onChange`. The reopen is therefore persisted automatically via the callback.
- **`closeOthers` and `closeToRight` respect `pinnedTabIDs`** — pinned tabs are never removed by batch close operations.
- **`recentlyClosed` stores the tab as it was at close time** — any in-memory state (loading status, etc.) is not stored. The reopened tab starts fresh.
- **`maxUndoStack` defaults to 10** — configurable via init to support testing with small counts.
- **`loadingTabIDs` is set by the Pane session (16), not by the tab strip itself** — `setLoading(_:tabID:)` is the pane's API surface into the VM.

## View Model API Summary (for Session 26 handoff)

```swift
// Construction
let vm = TabStripViewModel(
    tabs: workspace.leftPane.tabs,
    selectedTabID: workspace.leftPane.activeTabID,
    onChange: { tabs, selectedID in
        Task { await workspacesRepo.updateLeftPane(tabs: tabs, activeTabID: selectedID) }
    }
)

// Mutations (all @MainActor, synchronous)
vm.open(Tab(path: someDirectory))
vm.close(id: tabID)
vm.select(id: tabID)
vm.reorder(fromID: draggedID, toID: dropTargetID)
vm.closeOthers(keeping: tabID)
vm.closeToRight(of: tabID)
vm.duplicate(id: tabID)
vm.pin(id: tabID)
vm.reopenLastClosed()
vm.setLoading(true, tabID: tabID)

// Observation (in SwiftUI body — no @State wrapper needed with @Observable)
let isSelected = vm.selectedTabID == tab.id
let isPinned = vm.pinnedTabIDs.contains(tab.id)
let canUndo = vm.canReopenClosed
```

**Tab persistence handshake for Session 26:**
- The shell creates one `TabStripViewModel` per pane at window creation, seeded from `WorkspacesRepository`.
- The `onChange` callback is injected at construction time; it serializes `tabs` + `selectedTabID` back to the repository.
- The strip is portable: it has no `import ServicesSettings` — the host owns the persistence wiring.
