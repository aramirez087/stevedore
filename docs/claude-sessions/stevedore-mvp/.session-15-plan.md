## Type Designs

### `UninstallerError`

```swift
public enum UninstallerError: LocalizedError, Sendable {
    case notAnApp(URL)           // path extension != "app"
    case invalidBundle(URL)      // Contents/Info.plist missing
    case missingPlistKey(String) // CFBundleIdentifier absent
}
```

### `AppMetadata`

```swift
public struct AppMetadata: Sendable, Hashable {
    public let appURL: URL
    public let bundleID: String       // CFBundleIdentifier
    public let bundleName: String     // CFBundleName (falls back to app filename stem)
    public let executableName: String // CFBundleExecutable (falls back to bundleName)
}
```

`URL` is `Sendable` and `Hashable` — no wrapper needed.

### `AppMetadataReader`

Namespace `enum` (stateless, no instances). Single public entry point:

```swift
public enum AppMetadataReader {
    public static func read(from appURL: URL) throws -> AppMetadata
}
```

Algorithm:
1. Assert `appURL.pathExtension == "app"` → throw `.notAnApp`
2. Build `plistURL = appURL/Contents/Info.plist`; assert exists → throw `.invalidBundle`
3. Decode via `PropertyListDecoder` into a private `InfoPlist: Decodable` struct
   (keys: `CFBundleIdentifier`, `CFBundleName`, `CFBundleExecutable`)
4. `CFBundleIdentifier` required → `.missingPlistKey("CFBundleIdentifier")` on absence
5. `CFBundleName` falls back to `appURL.deletingPathExtension().lastPathComponent`
6. `CFBundleExecutable` falls back to `bundleName`
7. Returns `AppMetadata`

Uses `PropertyListDecoder` instead of `PropertyListSerialization` to avoid `Any`
crossing Sendable boundaries. Synchronous — plist parsing is < 1 ms.

### `MatchReason`

```swift
public enum MatchReason: Sendable, Hashable, CaseIterable {
    case bundleIDExact        // strippedName == bundleID
    case bundleIDPrefix       // strippedName.hasPrefix(bundleID + ".")
    case bundleIDComponent    // strippedName.lowercased().contains(bundleID.lowercased())
    case bundleNameSubstring  // strippedName.lowercased().contains(bundleName.lowercased())
    case executableName       // strippedName.lowercased().contains(executableName.lowercased())
}
```

Where `strippedName = url.lastPathComponent` with common suffixes removed
(`.plist`, `.savedState`).

### `MatchScorer` + `MatchResult`

Both in `MatchScorer.swift` (tightly coupled):

```swift
public struct MatchResult: Sendable {
    public let score: Double
    public let reasons: [MatchReason]
    public var isMatch: Bool { !reasons.isEmpty }
}

public struct MatchScorer: Sendable {
    public let confidenceCutoff: Double  // default 0.6

    public init(confidenceCutoff: Double = 0.6)
    public func score(url: URL, metadata: AppMetadata) -> MatchResult
    public func isHighConfidence(_ result: MatchResult) -> Bool { result.score >= confidenceCutoff }
}
```

Scoring table (evaluated in order; first match wins for score; all matching reasons accumulated):

| Condition (on `strippedName`) | Score | Reason |
|---|---|---|
| `strippedName == bundleID` | 1.0 | `.bundleIDExact` |
| `strippedName.hasPrefix(bundleID + ".")` | 0.9 | `.bundleIDPrefix` |
| `strippedName.lowercased().contains(bundleID.lowercased())` | 0.8 | `.bundleIDComponent` |
| `bundleName.count >= 3 && strippedName.lowercased().contains(bundleName.lowercased())` | 0.6 | `.bundleNameSubstring` |
| `executableName.count >= 3 && strippedName.lowercased().contains(executableName.lowercased())` | 0.5 | `.executableName` |
| no match | 0.0 | `[]` |

Score is the **maximum** matched rule; all matching reasons are accumulated.
The `count >= 3` guard on name/executable prevents single-character app names from
matching every directory that contains that letter.

**False-positive guard:** A directory named e.g. `"TextEdit"` will not match an app
with `bundleID = "com.example.TestApp"` / `bundleName = "TestApp"` / `executableName =
"TestApp"` because `"textedit"` does not contain `"testapp"`. Score = 0.0.

### `AssociatedFile`

```swift
public struct AssociatedFile: Sendable {
    public let url: URL
    public let score: Double
    public let reasons: [MatchReason]
    public let sizeInBytes: Int64?
    public let modificationDate: Date?
    public let requiresAdmin: Bool
}
```

### `AssociatedFilesScanner`

```swift
public actor AssociatedFilesScanner {
    public init(scorer: MatchScorer = MatchScorer(), searchPaths: [SearchPath] = SearchPaths.all())
    public func scan(metadata: AppMetadata) async throws -> [AssociatedFile]
}
```

Algorithm:
1. Launch one child task per search path via `withThrowingTaskGroup`
2. Each child task (in `Task.detached` for blocking I/O):
   a. Skip if path does not exist (`FileManager().fileExists(atPath:)`)
   b. Call `FileManager().contentsOfDirectory(at:includingPropertiesForKeys:[.fileSizeKey,.contentModificationDateKey]:)` — catch and skip on permission error
   c. For each item URL, call `scorer.score(url:metadata:)`
   d. Include item if `result.score >= scorer.confidenceCutoff`
   e. Read `sizeInBytes` and `modificationDate` from `URLResourceValues`
   f. Build `AssociatedFile(url:score:reasons:sizeInBytes:modificationDate:requiresAdmin: searchPath.isSystemOwned)`
3. Gather all results; sort by score descending, then URL path ascending for stability
4. Return array

Only **immediate children** of each search path are checked (no recursion). This matches
ForkLift behavior and avoids false positives from `~/Library/Application Support/OtherApp/SubDir`.

Concurrency: creating fresh `FileManager()` per child task follows the Session 03 pattern.

### `UninstallPlan`

```swift
public struct UninstallPlan: Sendable {
    public let metadata: AppMetadata
    public let selectedFiles: [AssociatedFile]

    public var totalSizeInBytes: Int64 {
        selectedFiles.compactMap(\.sizeInBytes).reduce(0, +)
    }
}
```

Pure value type — no I/O. The `.app` bundle is accessed via `metadata.appURL`.

### `UninstallExecutor` + `UninstallResult`

Both in `UninstallExecutor.swift`:

```swift
public struct UninstallResult: Sendable {
    public let trashedURLs: [URL]
    public let skippedAdminPaths: [URL]
    public let errors: [(url: URL, error: any Error)]
}

public actor UninstallExecutor {
    public init()
    public func execute(plan: UninstallPlan) async throws -> UninstallResult
}
```

Algorithm inside `execute`:
1. Iterate `plan.selectedFiles`:
   - If `requiresAdmin: true` → append to `skippedAdminPaths`, skip
   - Otherwise → `try FileManager().trashItem(at: url, resultingItemURL: nil)` in `Task.detached`
   - On success → append to `trashedURLs`
   - On error → append `(url, error)` to `errors`, continue (best-effort)
2. Trash the `.app` bundle itself (`metadata.appURL`) last, same pattern
3. Return `UninstallResult`

**The executor NEVER calls `removeItem`.** Verified at test time by a grep assertion.
`Task.detached` is used for each `trashItem` call to keep blocking I/O off the actor executor.

## Key Design Decisions

1. **`AppMetadataReader` as `enum` namespace.** Reading a plist is synchronous and fast.
   No actor isolation needed. Matches the `RenamePlanner`, `CollisionResolver`,
   `ImagePreviewRenderer` pattern established in prior sessions.

2. **`SearchPath` is a top-level struct, not a nested type inside `SearchPaths`.**
   SwiftLint's `nesting` rule rejects nested types beyond one level under `--strict`.
   Consistent with the decision in Session 01 to lift `WorkspacePane` and `CredentialMaterial`
   to top-level types.

3. **`MatchResult` in `MatchScorer.swift`.** Tightly coupled — the scorer's return type.
   Follows the one-public-type-per-file rule *except* when types are tightly coupled
   (same exception used for `UninstallResult` / `UninstallExecutor`).

4. **`AssociatedFilesScanner` as `actor`.** Holds configurable `scorer` and `searchPaths`;
   performs async I/O. Actor isolation prevents concurrent partial-state reads. Consistent
   with `GitStatusService` (Session 14).

5. **`UninstallExecutor` as `actor`.** Async I/O with potential future state (progress
   reporting). Consistent with `LocalFileSystemProvider` (Session 03).

6. **`UninstallPlan` as pure `struct`.** No behavior, no async. Matches `SyncPlan`
   (Session 11) and `RenameRecipe` (Session 12).

7. **`UninstallResult` embedded in `UninstallExecutor.swift`.** Tightly coupled
   (executor's return type). Mirrors `ConflictDescriptor` living alongside
   `LocalFileSystemProvider` in Session 03.

8. **Scoring cutoff default = 0.6 (bundle-name substring level).** Admits apps whose
   associated files are identified only by name (not reverse-DNS). Callers can raise to
   0.8 or 1.0 for stricter matching.

9. **`count >= 3` guard on name/executable matching.** Prevents a two-letter app name
   or executable (e.g. `"vi"`) from matching every folder that contains those letters.

10. **`Task.detached` for all `FileManager` I/O.** `FileManager` is not `Sendable`;
    creating a fresh instance per `Task.detached` call is the established project pattern
    (see Session 03 `LocalFileOperations`).

11. **`TaskGroup` for parallel search-path scanning.** One child task per search path
    yields ~10× speedup vs. sequential. Each task creates its own `FileManager()`.

12. **System paths returned but never trashed.** The executor checks
    `AssociatedFile.requiresAdmin`; all files derived from `SearchPaths.system()` carry
    `requiresAdmin: true` (propagated by `AssociatedFilesScanner`). The executor adds
    them to `skippedAdminPaths`, never calls `trashItem` on them.

13. **`#file`-relative path navigation for grep-assert test.** Test file lives at
    `Tests/FeaturesTests/UninstallerTests/UninstallExecutorTests.swift`; three
    `.deletingLastPathComponent()` calls yield the repo root; append
    `Sources/Features/Uninstaller/UninstallExecutor.swift` to get the source path.

14. **`FeaturesUninstallerModule.swift` replaces `Placeholder.swift`.** Preserves
    `moduleName = "FeaturesUninstaller"` so the existing smoke test remains green
    without modification.

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| `FileManager.trashItem` silently fails on non-APFS volumes in CI | Test against `tmp` dir (always writable on macOS); check source URL existence as success signal via `!FileManager().fileExists(atPath: url.path)` |
| Permission denied on `/Library` paths in CI | `AssociatedFilesScanner` wraps each `contentsOfDirectory` in a catch-and-skip per path |
| `URL(fileURLWithPath: "~/Library")` does NOT expand tilde | Use `FileManager().homeDirectoryForCurrentUser.appending(...)` — documented in Cerebrum after this session |
| `PropertyListDecoder` on binary plists | `Data(contentsOf:)` + `PropertyListDecoder` handles both XML and binary plist formats automatically |
| Swift 6 `FileManager` `Sendable` warning | Use fresh `FileManager()` per `Task.detached` call; never store as actor/struct property |
| SwiftLint `nesting` rule for nested types | `SearchPath` is top-level (not nested); `MatchResult` is top-level; `UninstallResult` is top-level |
| SwiftLint `missing_docs` on public surface | All public types and methods need doc comments |
| `URL` equality vs. `realpath` in tests | Use `FileManager().fileExists(atPath: url.path)` for existence checks, never `URL ==` after trashing |
| `trashItem` thread requirements | No main-thread requirement per Apple docs on macOS 14; `Task.detached` is safe |
| Typed throws (`throws(SomeType)`) compatibility | Use untyped `throws` — typed throws require Swift 5.10+ features not needed here; keep compatibility surface simple |
