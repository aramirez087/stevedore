# Session 15 Implementation Plan — Uninstaller Engine

## Overview

Build the Application Uninstaller Engine under `Sources/Features/Uninstaller/` and
`Tests/FeaturesTests/UninstallerTests/`. The engine mirrors ForkLift's "Application Deleter":
scan macOS support directories for files associated with a given `.app` bundle, score matches,
build a plan, and execute via Trash only (never `removeItem`). System-owned paths are reported
but never modified.

## Key Design Decisions and Rationale

### 1. `AppMetadata` is a separate value type file (`AppMetadata.swift`)
Following the one-public-type-per-file rule. `AppMetadataReader` is a pure stateless `enum`
namespace (same pattern as `RenamePlanner`, `CollisionResolver`, `ImagePreviewRenderer`).
`read(from:) throws` — synchronous since plist parsing is cheap and non-blocking.

### 2. `SearchPaths` returns `URL`, not `FilePath`
All Foundation filesystem APIs (`FileManager.enumerator`, `trashItem`) work with `URL`.
Avoiding a `FilePath` wrapper here keeps the Uninstaller module self-contained and avoids a
conversion layer. The `AssociatedFile.url` is also `URL` for the same reason.

### 3. `MatchScorer` scoring algorithm
Score = weighted sum of three binary/partial matches, normalized to `0.0–1.0`:

```
score = (bundleID_weight * bundleID_score)
      + (bundleName_weight * bundleName_score)
      + (execName_weight  * exec_score)
```

Weights: bundleID = 0.60, bundleName = 0.25, executableName = 0.15. Scores are:
- **1.0** if the path's last component equals the token exactly (case-insensitive)
- **0.7** if the path's last component *contains* the token (case-insensitive)
- **0.0** otherwise

`highConfidenceThreshold` defaults to `0.60` (bundleID exact = passes alone).

False-positive guard: common dictionary words ("Data", "Library", "Logs") score 0.0 unless
they also match bundleID or executableName. This is enforced by requiring at least one
token match to be with the bundleID component — e.g., a path that only matches the
bundleName "Music" should not score ≥ threshold unless the bundleID also matches.
Implementation: after computing the weighted sum, if `bundleID_score == 0.0` and
`bundleName_score > 0 && bundleID.components.count < 3` (i.e., a very short bundleID like
"com.apple.Music"), apply a dampening factor of 0.5.

### 4. `AssociatedFilesScanner` is an `actor`
Scanning involves async `FileManager` enumeration dispatched via `Task.detached` (same
pattern as `LocalFileSystemProvider`). The actor serialises the scan call; concurrent calls
are naturally queued.

### 5. `UninstallPlan` is a pure `struct`
No I/O. Aggregates `AppBundle URL` + scored `[AssociatedFile]`. Computes
`totalSizeInBytes` as a sum in `init`. Pure value type matches the pattern of `SyncPlan`,
`RenameRecipe`.

### 6. `UninstallExecutor` uses `FileManager.trashItem` exclusively
Exit criterion: no call to `removeItem` anywhere in production source. The executor:
1. Skips items with `requiresAdmin = true` (records them in `UninstallResult.skipped`).
2. Calls `try FileManager().trashItem(at: item.url, resultingItemURL: nil)` for each eligible item.
3. Also calls `trashItem` on the `.app` bundle itself last (after associated files).

`UninstallResult` is a small struct with `trashed: [URL]`, `skipped: [URL]`, `failed: [(URL, Error)]`.

### 7. Module sentinel preserved
`FeaturesUninstallerModule.swift` preserves `public enum FeaturesUninstallerModule { public static let moduleName: String = "FeaturesUninstaller" }` so the Session 01 smoke test at `Tests/FeaturesTests/UninstallerTests/` (actually in `Tests/FeaturesTests/`) continues to pass without modification.

## Type Designs (detailed)

### `AppMetadata`
```swift
public struct AppMetadata: Sendable {
    public let bundleID: String        // CFBundleIdentifier
    public let bundleName: String      // CFBundleName
    public let executableName: String  // CFBundleExecutable
    public let bundleURL: URL          // canonical .app bundle URL
}
```

### `AppMetadataReader`
```swift
public enum AppMetadataReader {
    public enum ReadError: Error, Sendable {
        case notABundle             // path does not end in .app or is not a directory
        case missingInfoPlist       // Contents/Info.plist not found
        case missingKey(String)     // required plist key absent
        case plistDecodingFailed(any Error)
    }
    public static func read(from bundleURL: URL) throws(ReadError) -> AppMetadata
}
```

Implementation: check `bundleURL.pathExtension == "app"`, confirm
`bundleURL/Contents/Info.plist` exists, parse with `PropertyListSerialization`, extract three
keys. `throws(ReadError)` is Swift 6's typed throws.

### `SearchPaths`
```swift
public enum SearchPaths {
    public struct SearchPath: Sendable {
        public let url: URL
        public let requiresAdmin: Bool
    }
    public static var all: [SearchPath] { get }
    public static var user: [SearchPath] { get }    // ~/Library/...
    public static var system: [SearchPath] { get }  // /Library/...
}
```

User paths (10):
- `~/Library/Application Support`
- `~/Library/Caches`
- `~/Library/Containers`
- `~/Library/Group Containers`
- `~/Library/Preferences`
- `~/Library/Saved Application State`
- `~/Library/LaunchAgents`
- `~/Library/Logs`
- `~/Library/HTTPStorages`
- `~/Library/WebKit`

System paths (3, `requiresAdmin = true`):
- `/Library/Application Support`
- `/Library/Caches`
- `/Library/Preferences`

Implementation uses `FileManager.default.homeDirectoryForCurrentUser` for `~` expansion
(not `URL(fileURLWithPath: "~/Library/...")` which doesn't expand tilde).

### `AssociatedFile`
```swift
public struct AssociatedFile: Sendable {
    public let url: URL
    public let score: Double
    public let sizeInBytes: Int64
    public let modificationDate: Date?
    public let reason: String        // human-readable match reason, e.g. "bundleID match"
    public let requiresAdmin: Bool
}
```

### `MatchScorer`
```swift
public struct MatchScorer: Sendable {
    public var highConfidenceThreshold: Double
    public init(highConfidenceThreshold: Double = 0.60)
    public func confidence(for url: URL, metadata: AppMetadata) -> (score: Double, reason: String)
    public func isHighConfidence(_ score: Double) -> Bool
}
```

### `AssociatedFilesScanner`
```swift
public actor AssociatedFilesScanner {
    public init(scorer: MatchScorer = MatchScorer())
    public func scan(
        metadata: AppMetadata,
        searchPaths: [SearchPaths.SearchPath] = SearchPaths.all
    ) async throws -> [AssociatedFile]
}
```

Implementation: for each `searchPath`, create a `Task.detached` that uses
`FileManager().contentsOfDirectory(at:includingPropertiesForKeys:options:)` to get
immediate children, score each, keep those above threshold. Returns sorted by score
descending, then name ascending.

Note: Only immediate children of each search path are checked (not recursive) to avoid
false positives inside e.g. `~/Library/Application Support/OtherApp/SubDir`. This matches
ForkLift's behavior.

### `UninstallPlan`
```swift
public struct UninstallPlan: Sendable {
    public let appBundle: URL
    public let items: [AssociatedFile]
    public let totalSizeInBytes: Int64

    public init(appBundle: URL, items: [AssociatedFile]) {
        self.appBundle = appBundle
        self.items = items
        self.totalSizeInBytes = items.reduce(0) { $0 + $1.sizeInBytes }
    }

    public var eligibleForExecution: [AssociatedFile] {
        items.filter { !$0.requiresAdmin }
    }
    public var requiresAdminItems: [AssociatedFile] {
        items.filter { $0.requiresAdmin }
    }
}
```

### `UninstallExecutor`
```swift
public struct UninstallResult: Sendable {
    public let trashed: [URL]
    public let skipped: [URL]       // requiresAdmin = true
    public let failed: [(URL, any Error)]
}

public actor UninstallExecutor {
    public init()
    public func execute(plan: UninstallPlan) async throws -> UninstallResult
}
```

Implementation:
```
var trashed: [URL] = []
var skipped: [URL] = []
var failed: [(URL, any Error)] = []

// Trash associated files first
for item in plan.items {
    if item.requiresAdmin {
        skipped.append(item.url)
        continue
    }
    do {
        try FileManager().trashItem(at: item.url, resultingItemURL: nil)
        trashed.append(item.url)
    } catch {
        failed.append((item.url, error))
    }
}

// Trash the .app bundle last
do {
    try FileManager().trashItem(at: plan.appBundle, resultingItemURL: nil)
    trashed.append(plan.appBundle)
} catch {
    failed.append((plan.appBundle, error))
}

return UninstallResult(trashed: trashed, skipped: skipped, failed: failed)
```

## Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| `trashItem` requires running on main thread on some macOS versions | Use `FileManager()` freshly in `Task.detached` (same pattern as `LocalFileOperations`); trashItem works from any thread per Apple docs since macOS 10.8 |
| Tilde expansion: `URL(fileURLWithPath: "~/Library")` does not expand | Use `FileManager.default.homeDirectoryForCurrentUser.appendingPathComponent("Library/...")` |
| Typed throws (`throws(ReadError)`) availability | Swift 6 supports typed throws; entire project is Swift 6 (`swiftLanguageModes: [.v6]`) |
| SwiftLint `nesting` rule: avoid nested types more than 1 level | `ReadError` inside `AppMetadataReader` is 1 level deep — acceptable |
| Score dampening formula could be brittle | Test the false-positive rejection case explicitly; document the formula in code comment |
| `contentsOfDirectory` on a non-existent search path | Wrap in `guard FileManager().fileExists(atPath:)` before enumerating; silently skip missing paths |
| Placeholder.swift deletion breaks smoke test | Preserve `FeaturesUninstallerModule.moduleName` sentinel in new `FeaturesUninstallerModule.swift` |
