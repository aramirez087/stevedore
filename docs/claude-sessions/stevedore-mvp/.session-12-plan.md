## Detailed Type Designs

### `RenameStep` — `Sources/Features/Rename/RenameStep.swift`

```swift
public enum RenameStep: Sendable, Hashable, Codable {
    case find(text: String, replace: String, caseSensitive: Bool)
    case regex(pattern: String, replacement: String)
    case `case`(CaseTransform)
    case sequence(start: Int, padding: Int, position: SequencePosition)
    case trim(TrimPosition)
    case insert(text: String, at: InsertPosition)
    case `extension`(ExtensionTransform)
}
```

Supporting enums (same file, each a separate top-level type to satisfy SwiftLint `nesting` rule):

```swift
public enum CaseTransform: String, Sendable, Codable, Hashable, CaseIterable {
    case lower, upper, title, preserve
}
public enum TrimPosition: String, Sendable, Codable, Hashable, CaseIterable {
    case leading, trailing, both
}
public enum SequencePosition: String, Sendable, Codable, Hashable, CaseIterable {
    case prefix, suffix, replace
}
public enum ExtensionTransform: String, Sendable, Codable, Hashable, CaseIterable {
    case lower, upper, preserve
}
public enum InsertPosition: Sendable, Codable, Hashable {
    case prefix
    case suffix
    case beforeExtension   // effectively same as suffix on decomposed stem
    case index(Int)        // 0-based character offset into stem
}
```

`InsertPosition` requires **manual** `Codable` because `case index(Int)` has an associated value.
Use a `"type"` discriminator key consistent with `OperationKind` in Session 01.

#### Step application model

```swift
public extension RenameStep {
    func apply(to stem: inout String, ext: inout String?, index: Int) throws
}
```

Semantics by case:

| Step | Operates on | Behavior |
|---|---|---|
| `find` | full assembled name | `replacingOccurrences`; re-split via `renameSplitStemExt` |
| `regex` | full assembled name | `NSRegularExpression.stringByReplacingMatches`; re-split |
| `case` | `stem` only | `lowercased()` / `uppercased()` / `capitalized` / no-op |
| `trim` | `stem` only | per position using `isWhitespace` character checks |
| `insert` | `stem` | prepend / append / insert at char index (clamped to stem.count) |
| `sequence` | `stem` | `String(format: "%0\(padding)d", start + index)` prepend/append/replace |
| `extension` | `ext` only | `lowercased()` / `uppercased()` / no-op; no-op when ext is nil |

#### Module-internal filename helpers

These functions are **not private** — they live in `RenameStep.swift` with no access modifier,
making them accessible to `RenamePlanner` within the same module without duplication:

```swift
func renameSplitStemExt(_ filename: String) -> (stem: String, ext: String?)
func renameAssembled(stem: String, ext: String?) -> String
```

Hidden files whose name begins with `.` (e.g., `.gitignore`) are treated as having no extension:
the leading dot is at `startIndex`, so the dot check returns `(stem: filename, ext: nil)`.

### `RenamePlanner` — `Sources/Features/Rename/RenamePlanner.swift`

```swift
public enum RenamePlanner {
    public static func plan(
        items: [FileItem],
        recipe: RenameRecipe,
        existingSiblings: Set<String> = [],
        collisionStrategy: CollisionResolver.Strategy = .markInvalid
    ) -> [RenameOutcome]
}
```

#### Algorithm

1. **Regex pre-validation** — scan all steps for `.regex(pattern:_:)` cases; attempt
   `NSRegularExpression(pattern:)`. On failure, return all items as `.invalid(reason:)`.
   This satisfies the exit criterion: malformed patterns rejected at **planning time**.

2. **Per-item transformation** — for each `(item, index)`:
   a. Decompose `item.displayName` via `renameSplitStemExt` → `(stem, ext)`.
   b. Apply each step with `step.apply(to: &stem, ext: &ext, index: index)`.
      Any thrown error → `.invalid(reason: error.localizedDescription)` for that item; continue.
   c. Reassemble via `renameAssembled(stem:ext:)`.
   d. Append `RenameOutcome(item:, targetName:, status: .ok)`.

3. **Collision resolution** — delegate to `CollisionResolver.resolve(outcomes:existingSiblings:strategy:)`.

4. Return resolved outcomes array.

Pure function: no I/O, deterministic given identical inputs.

### `CollisionResolver` — `Sources/Features/Rename/CollisionResolver.swift`

```swift
public enum CollisionResolver {
    public enum Strategy: String, Sendable, Codable, Hashable, CaseIterable {
        case markInvalid
        case autoSuffix
    }

    public static func resolve(
        outcomes: [RenameOutcome],
        existingSiblings: Set<String>,
        strategy: Strategy
    ) -> [RenameOutcome]
}
```

#### Algorithm

Maintain `Set<String> seen` initialized from `existingSiblings`:

- Non-ok outcomes pass through unchanged.
- If `seen.contains(outcome.targetName)`:
  - `.markInvalid` → emit with `.collision` status.
  - `.autoSuffix` → find lowest N ≥ 2 such that `suffixed(name, N)` ∉ `seen`; emit with `.ok`.
- Otherwise → `seen.insert(targetName)`, emit unchanged.

Auto-suffix format (matches macOS Finder):
- With extension: `"foo.txt"` → `"foo 2.txt"` (space + counter before extension)
- Without extension: `"readme"` → `"readme 2"`

First item claiming a name wins (keeps `.ok`). Ordering is deterministic.

### `RenameExecutor` — `Sources/Features/Rename/RenameExecutor.swift`

```swift
public actor RenameExecutor {
    public struct JournalEntry: Sendable {
        public let originalPath: FilePath
        public let renamedPath: FilePath
    }

    public private(set) var journal: [JournalEntry] = []

    public init() {}

    public func execute(
        outcomes: [RenameOutcome],
        in directory: FilePath,
        using provider: any FileSystemProvider
    ) async throws

    public func reset()
}
```

#### Execute algorithm

```
for outcome in outcomes where outcome.status == .ok:
    let source = outcome.item.path
    let destination = directory.appending(outcome.targetName)
    let descriptor = OperationDescriptor(kind: .rename, sources: [source], destination: destination)
    do:
        _ = try await provider.execute(descriptor, progress: nil)
        journal.append(JournalEntry(originalPath: source, renamedPath: destination))
    catch:
        await rollback(using: provider)
        throw error
```

#### Rollback algorithm (best-effort)

```
for entry in journal.reversed():
    let descriptor = OperationDescriptor(kind: .rename,
                                         sources: [entry.renamedPath],
                                         destination: entry.originalPath)
    do { _ = try await provider.execute(descriptor, progress: nil) }
    catch { logger.error("Rollback failed for \(entry.renamedPath.posixString): \(error)") }
```

Use `Logger(subsystem: "com.stevedore", category: "RenameExecutor")` from the `os` framework.
This avoids adding `ServicesLogging` as a dependency while complying with the no-`print()` rule.

### `RecordingRenameProvider`

```swift
final actor RecordingRenameProvider: FileSystemProvider {
    nonisolated let scheme: ConnectionScheme = .local
    private var nodes: [FilePath: FileItem] = [:]
    private(set) var renames: [(from: FilePath, to: FilePath)] = []
    var failAtRenameIndices: Set<Int> = []  // 1-indexed call numbers
    private var renameCallCount = 0

    func seed(_ items: [FileItem])
    func setFailAtRenameIndices(_ indices: Set<Int>)
    func hasNode(at path: FilePath) -> Bool

    // FileSystemProvider conformance:
    func attributes(at:) async throws -> FileAttributes
    nonisolated func enumerate(at:options:) -> AsyncThrowingStream<FileItem, any Error>
    func execute(_:progress:) async throws -> OperationResult
    nonisolated func watch(_:) -> AsyncStream<FilePathChange>
}
```

**Critical design**: `renameCallCount` counts ALL rename calls (forward AND rollback).
`failAtRenameIndices` is a `Set<Int>` of 1-indexed call numbers. This allows tests to inject
failures at specific rollback positions without relying on success-count arithmetic.

`execute(_:progress:)` for `.rename`: increment `renameCallCount` first; if the count is in
`failAtRenameIndices`, throw before mutating state. Otherwise update `nodes` and append to `renames`.

## Key Design Decisions

### 1. EXIF step not implemented
EXIF requires `ImageIO` reads during planning, breaking the pure-function invariant and
requiring new framework dependencies. `Package.swift` is frozen. Deferred to Session 22
(RenameDialog UI) if needed, logged as open issue in handoff.

### 2. `case` step applies to stem only; `extension` step applies to ext only
Matches ForkLift behavior. `find` and `regex` operate on the full assembled name and re-split.

### 3. Regex rejected at plan time, not execution time
`RenamePlanner.validateRecipe` compiles all regex patterns before processing any items.
Satisfies exit criterion without exposing errors at the `FileSystemProvider` layer.

### 4. `InsertPosition` manual Codable
Discriminator key `"type"` with explicit cases. Forward-compatible, consistent with
`OperationKind` from Session 01.

### 5. `RenameExecutor` is an actor
Journal mutation must be safe across async frames. Actor avoids `@unchecked Sendable`.

### 6. Best-effort rollback with `os.Logger`
Rollback failures are non-fatal; logged via `os.Logger`. Avoids adding `ServicesLogging`
dependency while satisfying the no-`print()` operator rule.

### 7. Auto-suffix format matches macOS Finder
`"foo.txt"` → `"foo 2.txt"` (space before counter, inserted before extension).
No-extension: `"readme"` → `"readme 2"`.

### 8. Sequence step uses no separator
`sequence(start:1, padding:3, position:.prefix)` on `"photo.jpg"` → `"001photo.jpg"`.
A separator can be injected via a preceding or following `insert` step.

### 9. Module-internal helpers `renameSplitStemExt` / `renameAssembled`
Declared without access modifier (module-internal) so `RenamePlanner` can reuse them
without duplication. Mirror functions in `RenameTestSupport.swift` have `test` prefixes
(`testSplitStemExt`, `testAssembled`) to avoid name conflicts.

### 10. `failAtRenameIndices: Set<Int>` (not `failAtRenameIndex: Int?`)
Allows injecting failures at specific rollback positions for best-effort rollback tests,
independent of success/failure of prior operations.

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| SwiftLint `nesting` rule rejects nested enums | All supporting enums are top-level, not nested inside `RenameStep` |
| `implicit_return` lint rule | All computed properties use implicit return |
| `RenameStep` Codable for backtick cases (`.case`, `.extension`) | Swift encodes as `"case"`/`"extension"` (no backticks) — verify round-trip in tests |
| `large_tuple` lint violations | Use named structs (`JournalEntry`, `InsertPosition`) |
| `sorted_imports` lint violations | Alphabetize: `Core`, `Foundation`, `FeaturesRename`, `XCTest` |
| `cyclomatic_complexity` in `apply()` | 7 cases is safe; extract per-case helpers into `// MARK: -` extensions |
| SwiftFormat `--lint` argument order (v0.59 bug) | Paths FIRST: `swiftformat Sources/... Tests/... --lint` |
| `prefer_self_in_static_references` lint rule | Use `Self.` in static methods |
| NFC/NFD Unicode: `uppercased()` may change composed form | Tests assert non-empty output; document that steps pass through macOS normalization |
| Sequence padding overflow (e.g., start=10000, padding=2) | No truncation — string exceeds padding width. Correct behavior; test explicitly. |
| Rollback `try?` silently swallows errors | `os.Logger` records each failure. Best-effort is the correct semantic. |
| File basename collision in `FeaturesTests` target | Verify 5 new test file basenames are unique across all `Tests/FeaturesTests/` subdirs |

### Exit criterion — rollback test specifics

```
Setup:  seed RecordingRenameProvider with items a–j (10 items, "/files/a.txt" … "/files/j.txt")
        setFailAtRenameIndices([5])     // 1-indexed call counter
        build 10 .ok outcomes: a→a_new, b→b_new, … j→j_new
Action: try await executor.execute(outcomes:in:using:)
Assert: throws (any error)
Assert: provider.hasNode(at: dir.appending("a.txt")) == true   (rolled back)
Assert: provider.hasNode(at: dir.appending("a_new.txt")) == false
Assert: provider.hasNode(at: dir.appending("e.txt")) == true   (5th item, rename call failed)
Assert: provider.hasNode(at: dir.appending("e_new.txt")) == false
```

Call sequence: a(1✓), b(2✓), c(3✓), d(4✓), e(5✗ throws) → rollback d(6✓), c(7✓), b(8✓), a(9✓).
Items f–j untouched. Items a–d restored. Item e was never moved (throw before node mutation).

### Exit criterion — regex plan-time rejection

```
Setup:  recipe = RenameRecipe(steps: [.regex(pattern: "[unclosed", replacement: "$0")])
Action: let outcomes = RenamePlanner.plan(items: someItems, recipe: recipe)
Assert: outcomes.allSatisfy { if case .invalid = $0.status { return true }; return false }
Assert: 0 calls to any FileSystemProvider (planner is pure; no I/O possible)
```

## Notes for Session Implementer

- `RenameStep` uses keyword identifiers: `` `case` `` and `` `extension` ``. Require backtick
  escaping at every call site. The Codable string keys are `"case"` and `"extension"` (no backticks).

  but test both to confirm they produce the same output.

- The `FeaturesTests` target covers all subdirectories under `Tests/FeaturesTests/`. Verify that
  all 5 new test file basenames are unique against the existing files in `OperationsTests/`,
  `SyncTests/`, `PreviewTests/`, and `GitTests/`.

  mirrors them as `testSplitStemExt` and `testAssembled` to avoid symbol conflicts at link time.
