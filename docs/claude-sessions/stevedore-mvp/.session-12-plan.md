## Detailed Type Designs

### `RenameStep` — `Sources/Features/Rename/RenameStep.swift`

```swift
public enum RenameStep: Sendable, Hashable, Codable {
    case find(text: String, replace: String, caseSensitive: Bool)
    case regex(pattern: String, replacement: String)
    case `case`(CaseTransform)
    case sequence(start: Int, padding: Int, position: SequencePosition)
    case trim(TrimPosition)
    case insert(text: String, at: InsertPosition)
    case `extension`(ExtensionTransform)
}
```

Supporting enums (same file, each a separate type to satisfy SwiftLint `nesting` rule):

```swift
public enum CaseTransform: String, Sendable, Codable, Hashable, CaseIterable {
    case lower, upper, title, preserve
}
public enum TrimPosition: String, Sendable, Codable, Hashable, CaseIterable {
    case leading, trailing, both
}
public enum SequencePosition: String, Sendable, Codable, Hashable, CaseIterable {
    case prefix, suffix, replace
}
public enum ExtensionTransform: String, Sendable, Codable, Hashable, CaseIterable {
    case lower, upper, preserve
}
public enum InsertPosition: Sendable, Codable, Hashable {
    case prefix
    case suffix
    case beforeExtension   // effectively same as suffix on stem
    case index(Int)        // 0-based character offset into stem
}
```

`InsertPosition` requires **manual** `Codable` because `case index(Int)` has an associated value
and `CaseIterable` is not applicable; use a discriminator approach consistent with
`OperationKind` in Session 01.

#### Step application model

Each `RenameStep` has a public `apply(to:ext:index:)` method:

```swift
public extension RenameStep {
    mutating func apply(to stem: inout String, ext: inout String?, index: Int) throws
}
```

Semantics by case:

| Step | Operates on | Behavior |
|---|---|---|
| `find` | full name (stem + "." + ext) | `replacingOccurrences`; reassemble with `splitStemExt` |
| `regex` | full name | `NSRegularExpression.stringByReplacingMatches`; reassemble |
| `case` | `stem` only | `lowercased()` / `uppercased()` / `capitalized` / no-op |
| `trim` | `stem` only | `trimmingCharacters(in: .whitespaces)` per position |
| `insert` | `stem` | prepend / append / insert at char index |
| `sequence` | `stem` | formatted number: `String(format: "%0\(padding)d", start + index)` prepended/appended/replacing |
| `extension` | `ext` only | `.lowercased()` / `.uppercased()` / no-op |

Internal `splitStemExt` helper (private, in same file):

```swift
private func splitStemExt(_ filename: String) -> (stem: String, ext: String?) {
    guard let dot = filename.lastIndex(of: "."), dot != filename.startIndex else {
        return (stem: filename, ext: nil)
    }
    return (stem: String(filename[..<dot]), ext: String(filename[filename.index(after: dot)...]))
}
```

Note: files whose name begins with `.` (hidden files like `.gitignore`) are treated as having
no extension — the whole name is the stem. (The dot at `startIndex` check handles this.)

### `RenamePlanner` — `Sources/Features/Rename/RenamePlanner.swift`

```swift
public enum RenamePlanner {
    public static func plan(
        items: [FileItem],
        recipe: RenameRecipe,
        existingSiblings: Set<String> = [],
        collisionStrategy: CollisionResolver.Strategy = .markInvalid
    ) -> [RenameOutcome]
}
```

#### Algorithm

1. **Regex pre-validation** — scan all steps for `.regex(pattern:_:)` cases.
   Attempt `NSRegularExpression(pattern: pattern)`. On failure, immediately return
   `items.map { RenameOutcome(item: $0, targetName: $0.displayName, status: .invalid(reason: msg)) }`.
   This satisfies the exit criterion: "Regex step rejects malformed patterns at **planning time**."

2. **Per-item transformation** — for each `(item, index)`:
   a. Decompose `item.displayName` via `splitStemExt` → `(stem, ext)`.
   b. Apply each step by calling `step.apply(to: &stem, ext: &ext, index: index)`.
      Any thrown error produces `.invalid(reason:)` for that item; continue processing others.
   c. Reassemble `targetName = ext == nil ? stem : stem + "." + ext`.
   d. Append `RenameOutcome(item: item, targetName: targetName, status: .ok)`.

3. **Collision resolution** — pass outcomes through
   `CollisionResolver.resolve(outcomes:existingSiblings:strategy:)`.

4. Return the resolved outcomes array.

The function is deterministic: same inputs → same output. It imports `Foundation` for
`NSRegularExpression` but performs no I/O.

### `CollisionResolver` — `Sources/Features/Rename/CollisionResolver.swift`

```swift
public enum CollisionResolver {
    public enum Strategy: String, Sendable, Codable, Hashable, CaseIterable {
        case markInvalid
        case autoSuffix
    }

    public static func resolve(
        outcomes: [RenameOutcome],
        existingSiblings: Set<String>,
        strategy: Strategy
    ) -> [RenameOutcome]
}
```

#### Algorithm

Maintain `Set<String> seen` starting from `existingSiblings`:

For each outcome (in order):
- Skip if status is not `.ok` (pass through `.collision` or `.invalid` unchanged).
- If `seen.contains(outcome.targetName)`:
  - `.markInvalid` → replace with `RenameOutcome(... status: .collision)`
  - `.autoSuffix` → find the lowest integer N ≥ 2 such that `suffixed(name, N)` is not in `seen`;
    emit the suffixed name with `.ok`.
- Otherwise → add to `seen`, emit unchanged.

`suffixed(_:_:)` helper:

```swift
private static func suffixed(_ name: String, _ n: Int) -> String {
    guard let dot = name.lastIndex(of: "."), dot != name.startIndex else {
        return "\(name) \(n)"
    }
    let stem = String(name[..<dot])
    let ext = String(name[dot...])   // includes leading dot
    return "\(stem) \(n)\(ext)"
}
```

The first item claiming a name wins (it entered `seen` and keeps `.ok`). Subsequent
items with the same name are either marked `.collision` or suffixed. This makes ordering
deterministic.

### `RenameExecutor` — `Sources/Features/Rename/RenameExecutor.swift`

```swift
public actor RenameExecutor {
    public struct JournalEntry: Sendable {
        public let originalPath: FilePath
        public let renamedPath: FilePath
    }

    public private(set) var journal: [JournalEntry] = []

    public init() {}

    /// Execute all `.ok` outcomes in order.
    /// On any failure, rolls back the completed renames in reverse order, then rethrows.
    public func execute(
        outcomes: [RenameOutcome],
        in directory: FilePath,
        using provider: any FileSystemProvider
    ) async throws

    /// Clears the journal. Call before a new batch.
    public func reset()
}
```

#### Execute algorithm

```
for outcome in outcomes where outcome.status == .ok:
    let source = outcome.item.path
    let destination = directory.appending(outcome.targetName)
    let descriptor = OperationDescriptor(kind: .rename, sources: [source], destination: destination)
    do:
        try await provider.execute(descriptor, progress: nil)
        journal.append(JournalEntry(originalPath: source, renamedPath: destination))
    catch:
        await rollback(using: provider)
        throw error
```

#### Rollback algorithm (best-effort)

```
for entry in journal.reversed():
    let descriptor = OperationDescriptor(kind: .rename, sources: [entry.renamedPath],
                                         destination: entry.originalPath)
    try? await provider.execute(descriptor, progress: nil)
    // Rollback failures are silently ignored (best-effort).
    // A Logger is used to record any rollback failure for diagnostics:
    //   Logger(subsystem: "com.stevedore", category: "RenameExecutor").error(...)
```

Import `os` (system framework) for `Logger`. This avoids adding `ServicesLogging` as a
dependency (Package.swift is frozen) while complying with the "no print()" operator rule.

```swift
actor RecordingRenameProvider: FileSystemProvider {
    nonisolated let scheme: ConnectionScheme = .local
    private var nodes: [FilePath: FileItem] = [:]
    private(set) var renames: [(from: FilePath, to: FilePath)] = []
    var failAtRenameIndex: Int?   // 1-indexed; nil = never fail

    func seed(_ items: [FileItem])

    // FileSystemProvider conformance:
    func attributes(at:) async throws -> FileAttributes
    nonisolated func enumerate(at:options:) -> AsyncThrowingStream<FileItem, any Error>
    func execute(_:progress:) async throws -> OperationResult
    nonisolated func watch(_:) -> AsyncStream<FilePathChange>
}
```

`execute(_:progress:)` handles `.rename`: if `renames.count + 1 == failAtRenameIndex`, throw
`StevedoreError.fileSystem(.permissionDenied(...))` before mutating state. Otherwise, update
`nodes`, append to `renames`, and return `.completed`.

## Key Design Decisions

### 1. EXIF step not implemented
The session spec mentions "EXIF metadata" in the context section but the task list (step 1)
does not include it as an enum case. EXIF requires `ImageIO` framework access and metadata
read from disk — it breaks the pure-function invariant of `RenamePlanner` and requires I/O
during planning. Since `Package.swift` is frozen (no new dependency), EXIF is deferred.
Logged as open issue in handoff.

### 2. `case` step applies to stem only, `extension` step applies to ext only
This matches ForkLift's behavior and prevents the two steps from fighting over the same
string. `find` and `regex` operate on the full assembled name and re-split after.

### 3. Regex validated at plan time, not execution time
`RenamePlanner.plan()` compiles all regex patterns via `NSRegularExpression` before processing
any items. A bad pattern short-circuits and returns `.invalid` for all items. This satisfies
the exit criterion without exposing the error at the `FileSystemProvider` layer.

### 4. `InsertPosition` manual Codable
Swift's synthesized Codable for enums with associated values encodes using a `_0` key for
unlabeled payloads. For forward compatibility and auditability, `InsertPosition` uses
hand-rolled `Codable` with a `"type"` discriminator key (consistent with `OperationKind`
in Session 01).

### 5. `RenameExecutor` is an actor
The journal must be mutation-safe across async frames. Using an actor avoids `@unchecked
Sendable` and satisfies Swift 6 strict concurrency.

### 6. Best-effort rollback with `os.Logger`
Rollback failures are non-fatal: we log them with `Logger(subsystem: "com.stevedore",
category: "RenameExecutor")` from the `os` system framework. This avoids adding
`ServicesLogging` as a dependency (Package.swift frozen) while satisfying the operator
rule of no `print()` calls.

### 7. Auto-suffix inserts before extension
`"foo.txt"` → `"foo 2.txt"`, not `"foo.txt 2"`. Single space before the counter matches
macOS Finder behavior.

### 8. Sequence step uses no separator by default
`sequence(start: 1, padding: 3, position: .prefix)` on "photo.jpg" produces "001photo.jpg",
not "001_photo.jpg". A separator can be injected via an `insert` step. This keeps the enum
simple (3 params as specified).

### 9. Placeholder.swift deleted, sentinel preserved in FeaturesRenameModule.swift
The smoke test at `Tests/FeaturesTests/Rename/FeaturesRenameSmokeTests.swift` asserts
`FeaturesRenameModule.moduleName == "FeaturesRename"`. The new file preserves this declaration.

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| SwiftLint `nesting` rule rejects nested enums | All supporting enums (CaseTransform, etc.) are top-level, not nested inside RenameStep |
| `implicit_return` lint rule | All computed properties and single-expression functions must use implicit return (no `return` keyword) |
| `RenameStep` Codable synthesis fails for keyword-named cases (`.case`, `.extension`) | Swift synthesizes Codable using string literals for case names, not identifiers — backtick cases encode as "case"/"extension"; verify in tests |
| `large_tuple` lint violations | Use named structs (`JournalEntry`, `InsertPosition` instead of `(Int, String)`) |
| `sorted_imports` lint violations | Always alphabetize: `Core`, `Foundation`, `FeaturesRename`, `XCTest` |
| `cyclomatic_complexity` warning in `apply()` switch | If the switch body exceeds 12 branches, extract helpers. With 7 cases it should be fine. |
| SwiftFormat `--lint` command with paths-before-flag | Per cerebrum: `swiftformat Sources/Features/Rename Tests/FeaturesTests/RenameTests --lint` (paths FIRST) |
| `prefer_self_in_static_references` lint rule | Static factory methods use `Self.xyz` instead of `TypeName.xyz` |
| `NFC/NFD` Unicode normalization: `uppercased()` may change composed form | Tests should use exact byte-level comparisons; document that the step passes through macOS string normalization |
| `sequence` padding overflow (e.g., start=10000, padding=2) | No truncation — formatted string exceeds padding width. This is correct behavior; tested explicitly. |
| Rollback with `try?` silently swallows errors | Best-effort is the correct semantic; `os.Logger` records each failure for diagnostics |
| File basename collision in `FeaturesTests` target | All 5 new test files have unique basenames (verified: no match in OperationsTests or SyncTests) |

## Session 22 API Contract (for RenameDialog UI)

The Rename dialog (Session 22) uses this engine as follows:

**Preview flow** (called on every keystroke):
```swift
let outcomes = RenamePlanner.plan(
    items: selectedItems,
    recipe: currentRecipe,
    existingSiblings: siblingsInDirectory,
    collisionStrategy: .markInvalid
)
// Bind outcomes to the preview table
```

**Commit flow** (on user confirmation):
```swift
let executor = RenameExecutor()
try await executor.execute(
    outcomes: outcomes.filter { $0.status == .ok },
    in: currentDirectory,
    using: activeProvider
)
```

The UI does **not** pre-filter outcomes before passing to `execute()` — the executor itself
skips `.collision` and `.invalid` items. But filtering to `.ok` first is valid and slightly
more efficient.

## Notes for Session Implementer

- `RenameStep` uses keyword identifiers: `` `case` `` and `` `extension` ``. Both require
  backtick escaping at every call site. The synthesized Codable encoding string keys are
  `"case"` and `"extension"` (no backticks). Verify round-trip Codable in tests.

- The `sequence` step's `index` parameter is 0-based. Item at position 0 in the batch gets
  `start + 0 = start`. This is the natural array index, not a 1-based counter.

- `title` case via `String.capitalized` uses the system locale. For `capitalized(with: nil)`
  (no locale), behavior may differ from locale-aware `localized(capitalized:)`. Use
  `String.capitalized` (system locale) for consistency with macOS Finder.

- The `FeaturesTests` test target spans all subdirectories under `Tests/FeaturesTests/`.
  All 5 new test file basenames are verified unique against the existing 14 files in that tree.

- `swiftlint --strict` flags `todo` rule as disabled in `.swiftlint.yml` — no need to avoid
  `// TODO:` comments, but project style prefers no comments by default.
