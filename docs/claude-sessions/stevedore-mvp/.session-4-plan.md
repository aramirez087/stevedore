# Session 4 Implementation Plan — Remote Filesystem Providers

> Read-only planning artifact. Source code is **not** modified by this plan.
> Mission: implement SFTP, FTP, WebDAV, and S3 `FileSystemProvider`s behind
> a single `RemoteProviderRegistry`, all conforming to the `Core.FileSystemProvider`
> protocol shipped in Session 01. Tests must run hermetically in <500ms with
> no real network I/O. `Package.swift` is **frozen** — Citadel and SotoS3 are
> already declared on the `FileSystemRemote` target.

2. Keep dependency-touching code confined to one file per scheme, which
   keeps the lint-strict surface narrow.
3. Bring up future schemes (SMB, FTPS) by adding a transport pair without
   touching the provider/protocol layer.

## 4. Key design decisions and rationale

### 4.1 Transport indirection (one protocol per scheme)

**Decision.** Every provider takes `any <Scheme>Transport` rather than
calling Citadel/SotoS3/URLSession directly. The Citadel-, Soto-, and
URLSession-backed transports each live in exactly one file
(`Citadel*Transport.swift`, `Soto*Transport.swift`, `URLSession*Transport.swift`).

**Why.**
- The session prompt mandates "no real network I/O in tests" with
  per-test runtime <500ms. We cannot achieve that with the production
  transports — Citadel needs an SSH peer; URLSession FTP needs a real
  socket; SotoS3 issues real HTTPS calls unless heroically mocked.
- It also confines third-party-API surface to small files, so a Citadel
  major-version bump only requires touching one file per scheme.
- The transport protocol is declared `Sendable` so providers stay actor-
  isolated correctness-wise and Swift 6 strict concurrency stays clean.

### 4.2 Each provider is an `actor`

**Decision.** `SFTPProvider`, `FTPProvider`, `WebDAVProvider`, `S3Provider`
are all actors holding (a) the transport, (b) a `RemoteSession` instance,
and (c) the originating `RemoteHostDescriptor`.

**Why.**
- `Core.FileSystemProvider` requires `Sendable` and async methods.
  `InMemoryFileSystemProvider` is itself an actor — we follow the precedent.
- Actor isolation lets us own the connection's mutable state (cursor
  position, multipart upload IDs, ETag cache) without locks.
- `enumerate(...)` is `nonisolated` because it returns a stream
  synchronously; the body of the stream re-enters the actor via `await self`.
  This matches the existing `InMemoryFileSystemProvider` shape exactly.

### 4.3 `RemoteProviderRegistry` IS the `RemoteConnector`

**Decision.** The registry conforms to `Core.RemoteConnector`. No separate
connector type. Internally it holds a `[ConnectionScheme: any RemoteProviderFactory]`
dictionary populated at init.

```swift
public protocol RemoteProviderFactory: Sendable {
    var scheme: ConnectionScheme { get }
    func test(_ host: RemoteHostDescriptor, credential: Credential?) async throws -> ConnectionTestResult
    func open(_ host: RemoteHostDescriptor, credential: Credential?) async throws -> any FileSystemProvider
}

public actor RemoteProviderRegistry: RemoteConnector {
    public init(factories: [any RemoteProviderFactory] = .productionDefaults)
    public func register(_ factory: any RemoteProviderFactory)  // for tests
    public func test(...) async throws -> ConnectionTestResult
    public func open(...) async throws -> any FileSystemProvider
}
```

**Why.**
- `Core.RemoteConnector` is the only public seam the rest of the app
  uses to obtain providers (cf. architecture.md §10). Forcing every UI
  consumer to know the concrete `RemoteProviderRegistry` would re-couple
  the UI to scheme-specific implementations.
- Tests inject fakes via the same `register(_:)` API — no test-only
  initializer fork.
- `productionDefaults` returns the four factories with their respective
  default transport closures. Each factory closure can be overridden in
  tests to return an in-memory transport.

### 4.4 `RemoteSession` is a generic actor, not per-scheme

**Decision.** A single `RemoteSession<Connection: Sendable>` actor
encapsulates: idle-timeout disconnect, exponential backoff with jitter,
cancellation. It exposes one entry point:

```swift
func withConnection<T>(_ body: @Sendable (Connection) async throws -> T) async throws -> T
```

The `Connection` generic is bound to whatever the scheme's transport uses
(Citadel `SSHClient`, an `InputStream/OutputStream` pair for FTP, a
`URLSession` instance for WebDAV, a `SotoS3.S3` instance for S3).

**Why.**
- Lifecycle policy is identical across schemes. Duplicating it four
  times invites drift.
- A generic actor parameterized over the connection type keeps each
  scheme strongly typed and Sendable-clean without `Any` erasure.
- Tests can use `RemoteSession<Int>` or `RemoteSession<Void>` to verify
  idle/retry behavior without standing up any real transport.

### 4.5 Retry policy: exponential backoff with jitter

**Decision.** `RetryPolicy` is a pure value type:

```swift
public struct RetryPolicy: Sendable, Hashable {
    public let maxAttempts: Int          // default 4
    public let baseDelay: Duration       // default 200ms
    public let maxDelay: Duration        // default 5s
    public let jitter: ClosedRange<Double> // default 0.5...1.5
    public func delay(for attempt: Int, using rng: inout some RandomNumberGenerator) -> Duration
    public static let `default`: RetryPolicy
}
```

**Why.**
- Exposing the RNG as `inout some RandomNumberGenerator` lets tests pass
  a `SeededRandomGenerator` and assert exact delay values, eliminating
  flake.
- We use `Duration` (Swift 5.7+, available on macOS 14) so the value is
  Sendable + Hashable + Codable-compatible without bridging.
- Retries apply to **transient** errors only — `RemoteError.timeout`,
  `RemoteError.connectionFailed`, and idempotent operations.
  `RemoteError.authenticationFailed` is non-retriable and propagates
  immediately. Specific predicates encoded inside `RemoteSession`.

### 4.6 Cancellation strategy

**Decision.** Two layers of cancellation propagation:

1. The provider methods are `async`, so `Task.isCancelled` and
   `try Task.checkCancellation()` are inserted at every yield point —
   especially inside `AsyncThrowingStream` continuations.
2. The transport protocol exposes `cancelInFlight()` (or transport-specific
   equivalents). When the calling Task is cancelled, `RemoteSession.withConnection`
   wraps the body in a child task and forwards cancellation by calling
   the transport's cancel hook before re-throwing `CancellationError`.

**Why.**
- The exit criterion explicitly requires this. Tests will spawn a
  `Task { ... }` and immediately `cancel()` it; the stream/await must
  terminate within ~50ms.
- Failure mode without explicit cancel hooks: URLSession tasks keep
  running in the background even after the parent Task is cancelled,
  blocking server-side resources and skewing test timing. We avoid that
  by holding the URLSession data task handle and calling `cancel()` on it.

### 4.7 SFTP provider — Citadel adapter scope

**Decision.** `SFTPProvider` exposes:

| Operation | How |
|-----------|-----|
| `attributes(at:)` | `transport.stat(path)` → `SFTPMappers.fileAttributes(from:)` |
| `enumerate(at:options:)` | `transport.list(path)`; non-recursive default; recursive walks dispatched via TaskGroup. Hidden filtering applied in the provider, not the transport. |
| `execute(.mkdir/.delete/.rename)` | Direct transport call. |
| `execute(.copy/.move)` | Server-side rename when same-host same-path-prefix; otherwise `read` + `write` streamed in 64KB chunks. |
| Read large files | `transport.openRead(path) -> AsyncThrowingStream<Data, Error>`; supports `restartFrom: Int64` byte offset. |
| Write large files | `transport.openWrite(path, restartFrom: Int64?) -> AsyncWriteHandle`. |
| `chmod` | Custom verb beyond `OperationKind`; surfaced as a typed extension method on `SFTPProvider` only. (`OperationKind` cannot be widened — Core is frozen — and `chmod` is SFTP-specific. Documented as a non-protocol method per architecture.md §10's "if you need to widen, record it" rule.) |

**Citadel surface used.**
- `SSHClient.connect(host:port:authenticationMethod:)`
- `SSHClient.openSFTP() -> SFTPClient`
- `SFTPClient.listDirectory(atPath:)`
- `SFTPClient.getAttributes(at:)`
- `SFTPClient.openFile(filePath:flags:)` for read/write streaming.
- `SFTPClient.createDirectory(atPath:)`, `.rename(at:to:)`, `.remove(at:)`.

**Auth.**
- Password → `SSHAuthenticationMethod.passwordBased(username:password:)`.
- Private key → `SSHAuthenticationMethod.rsa(...)` / `.ed25519(...)` based
  on PEM detection. `RemoteAuth` parses the PEM header to choose.
- Bearer / OAuth not applicable to SFTP.

### 4.8 FTP provider — URLSession with FTP scheme

**Decision.** Use `URLSession` with `ftp://` URLs for transfer (it natively
handles PASV negotiation), and a separate `Network.framework`-based control
channel for commands not exposed by URLSession (LIST/MLSD/EPSV/MKD/RNFR+RNTO/DELE).

**Reality check.** URLSession's FTP support is deprecated upstream
(Apple has been signaling deprecation since macOS 12) and never exposed
LIST as anything ergonomic. **Practical compromise**: implement
`URLSessionFTPTransport` against `Network.NWConnection` for the control
channel and a second `NWConnection` for data, parsing responses
ourselves. This keeps us in pure-Swift / Foundation territory (no new
deps; `Package.swift` stays frozen) and remains testable via the
transport protocol since `FTPTransport` shields the provider entirely.

**FTP listing parser.** Tokenizer accepts:
1. UNIX-style `LIST` output: `-rw-r--r-- 1 owner group 1234 Jan 02 12:34 name`.
2. Windows IIS-style: `01-23-24  12:34PM       1234 name`.
3. MLSD format: `Type=file;Size=1234;Modify=20240102123400; name`.
4. UTF-8 first; fall back to Latin-1 if UTF-8 decode fails.

**Why a hand-rolled parser.** No Swift FTP-listing library exists with a
permissive license + Swift 6 strict-concurrency support; rolling one as
~200 LOC of pure functions is trivially testable and bug-fixable.

### 4.9 WebDAV provider — URLSession + XMLParser

**Decision.** `URLSession.dataTask(with: URLRequest)` handles the HTTP
verbs. PROPFIND requests carry the Depth header (`Depth: 1`), a body
with the XML envelope, and `Content-Type: application/xml`. The 207
Multi-Status body is parsed with `XMLParser` (Foundation, no NIO).

**XMLParser is callback-based and not async.** Wrap it in a
`PROPFINDParser` actor that drives a synchronous `XMLParser` to
completion, then returns the accumulated `[WebDAVResource]`. The actor
isolation lets us hold the mutable accumulator without locks.

**ETag handling.** The provider keeps an in-memory `[FilePath: String]`
ETag cache for last-known revisions. Conditional `PUT` includes an
`If-Match: <etag>` header; a 412 Precondition Failed maps to
`FileSystemError.alreadyExists` (or a new `RemoteError.preconditionFailed`
**only if** Core has it — it does not, so we map to
`StevedoreError.fileSystem(.alreadyExists(path))` with a logged note that
the revision moved. This is documented as a known limitation in the
handoff.).

### 4.10 S3 provider — Soto adapter scope

**Decision.** `S3Provider` consumes `any S3Transport`. The Soto-backed
implementation does:
- `listObjectsV2Paginator` for `enumerate`.
- `headObject` for `attributes`.
- `getObject` for read; chunks streamed via the byte buffer of
  `AWSHTTPBody`.
- `putObject` for objects ≤ 8 MiB; **multipart upload** for > 8 MiB
  (`createMultipartUpload` → `uploadPart` per 8 MiB chunk →
  `completeMultipartUpload` or `abortMultipartUpload` on failure).
- `deleteObject` / `deleteObjects` for delete.
- `listBuckets` for bucket discovery (root-level enumeration).
- `signURL(...)` for presigned URLs.

**Region.** Resolved from the `RemoteHostDescriptor.host` via virtual-host
parsing (`bucket.s3.<region>.amazonaws.com`) with fallback to
`us-east-1`. The bucket is the root component of the FilePath; the rest
is the key.

**Path mapping.**
- `FilePath.root(.s3)` enumerates buckets via `listBuckets`.
- `FilePath(scheme: .s3, components: ["mybucket"])` enumerates keys at
  the bucket root.
- `FilePath(scheme: .s3, components: ["mybucket", "a", "b", "c.txt"])`
  → bucket `mybucket`, key `a/b/c.txt`.

### 4.11 Auth strategy bridging

**Decision.** `RemoteAuth.bridge(_ credential: Credential?, for scheme: ConnectionScheme) throws -> RemoteAuthStrategy`
returns the per-scheme strategy. Validates compatibility:

| Scheme | password | privateKey | oauthToken | none |
|--------|----------|------------|------------|------|
| sftp   | ✅        | ✅          | ❌         | ❌ (unsupported) |
| ftp    | ✅        | ❌          | ❌         | ✅ (anonymous)   |
| webdav | ✅        | ❌          | ✅ (bearer)| ❌                |
| s3     | ❌ (use access-key/secret-key encoded as `password("AK:SK")`) | ❌ | ✅ (STS session token) | ❌ |

- Incompatible combos throw `StevedoreError.invalidArgument(...)`.
- `Credential.material == .password("AK:SK")` (a colon-delimited pair) is
  the encoding for AWS access-key + secret-key. **This is a deviation**
  from a clean per-scheme credential model and is documented in the
  handoff. (Core's `CredentialMaterial` enum is frozen — adding an
  `awsCredentials(accessKey:secretKey:)` case would require touching Core,
  which is outside the session's `touches:` scope.)

### 4.12 Conformance suite

**Decision.** A single `XCTestCase`-derived class
`RemoteProviderConformanceTests` with non-`final` methods that run
against any `(any FileSystemProvider, ConformanceFakeFactory)` injected
in `setUpWithError`. Each scheme test class subclasses it.

```swift
class RemoteProviderConformanceTests: XCTestCase {
    var provider: (any FileSystemProvider)!
    var fake: ConformanceFakeFactory!
    func setUpProvider() async throws { fatalError("override") }
    override func setUp() async throws {
        try await self.setUpProvider()
    }
    func testEnumerateRoot() async throws { ... }
    func testWriteThenRead() async throws { ... }
    func testMkdir() async throws { ... }
    func testRename() async throws { ... }
    func testDelete() async throws { ... }
    func testCancellationPropagatesToTransport() async throws { ... }
    func testNotFoundMapsToFileSystemError() async throws { ... }
    func testListUnderEmptyDirectory() async throws { ... }
}

final class SFTPConformanceTests: RemoteProviderConformanceTests {
    override func setUpProvider() async throws { ... }
}
// Likewise FTPConformanceTests, WebDAVConformanceTests, S3ConformanceTests.
```

XCTest discovers methods on subclasses by reflection — overrideable
`setUpProvider()` configures the provider once per test method.
**Note:** `setUp` in XCTest is called before each test method, not just
once per class — that's the desired isolation behavior for these tests.

> `fatalError("override")` only triggers if a future subclass forgets
> to override `setUpProvider()`; legitimate per the operator-rules
> exception that test code can use `try!`/`fatalError` for misuse.

### 4.13 Streaming + progress

**Decision.** Provider read/write methods that move bytes accept a
non-protocol `OperationProgressReporting?`. We funnel byte counts through
that. The `Core.FileSystemProvider.execute` signature already accepts a
progress reporter — we honor it for `.copy`, `.move`, and synthetic
read/write.

For raw streaming (e.g., needed by Preview), we add provider-only
methods like `read(at:byteRange:) -> AsyncThrowingStream<Data, any Error>`
that are **not** part of the Core protocol but are exposed on the
concrete actor type. Downstream sessions (Preview, Operations) pull
this in via type-erasure helpers if needed.

| 7 | **`InMemoryFileSystemProvider` (in Core) only stubs copy/move.** Any conformance test that exercises copy/move via `OperationKind` must run against a transport-level fake, not a Core fake. | Low | Low | The conformance suite runs through provider methods, not through the Core fake. | 8 | **Trailing-comma + sorted_imports interaction with Citadel/Soto imports.** Multi-line `import` clauses are uncommon but possible. | Low | Low | Keep imports single-line, alphabetized. |

| 13 | **Test target file_length warning.** Conformance fixtures can balloon. | Low | Low | Keep fixtures in dedicated `*Fixtures.swift` files (already planned). |
