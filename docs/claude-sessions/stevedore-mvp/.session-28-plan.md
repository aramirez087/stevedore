## Design Decisions & Rationale

### Makefile design

Use a standard POSIX-compatible Makefile with `.PHONY` targets.

```makefile
SCHEME      := Stevedore
DESTINATION := platform=macOS,arch=arm64
DERIVED     := .build/DerivedData

.PHONY: format-check lint build test app ci

# NOTE: swiftformat paths MUST precede --lint (swiftformat 0.59 arg-parser quirk)
format-check:
	swiftformat Sources Tests App Package.swift --lint

lint:
	swiftlint --strict

build:
	swift build -Xswiftc -warnings-as-errors

test:
	swift test --parallel

app:
	xcodebuild -scheme $(SCHEME) \
	           -destination '$(DESTINATION)' \
	           -derivedDataPath $(DERIVED) \
	           clean build \
	           CODE_SIGNING_ALLOWED=NO

ci: format-check lint build test app
```

**Rationale:**
- `swift build` implicitly resolves dependencies, so `swift package resolve` is not a
  separate Makefile target. The CI YAML runs resolve as a separate pre-warm step.
- `arch=arm64` targets GitHub's `macos-14` Apple Silicon runner directly; no Rosetta.
- `-derivedDataPath .build/DerivedData` co-locates DerivedData with the SPM build dir so
  the GitHub Actions cache covers both with a single path glob.
- `swiftformat` paths-before-`--lint` ordering is a known 0.59 bug documented in cerebrum.

### GitHub Actions workflow design

```yaml
name: CI
on:
  push:
    branches: [main, 'epic/**']
  pull_request:
    branches: [main]

jobs:
  ci:
    name: Build & Test
    runs-on: macos-14
    steps:
      - uses: actions/checkout@v4

      - name: Select Xcode
        run: sudo xcode-select -s /Applications/Xcode.app

      - name: Cache SwiftPM and DerivedData
        uses: actions/cache@v4
        with:
          # .build/DerivedData is set by `make app` via -derivedDataPath flag,
          # keeping all build artifacts in one cacheable tree.
          path: .build
          key: ${{ runner.os }}-spm-${{ hashFiles('Package.resolved') }}
          restore-keys: |
            ${{ runner.os }}-spm-

      - name: Install tools
        run: brew install swiftformat swiftlint

      - name: Resolve dependencies
        run: swift package resolve

      - name: Run CI gate
        run: make ci

      - name: Upload xcresult on failure
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: test-results
          path: ~/Library/Developer/Xcode/DerivedData/**/Logs/Test/**/*.xcresult
          if-no-files-found: ignore
```

**Key decisions:**
- `actions/cache@v4`, `actions/checkout@v4`, `actions/upload-artifact@v4` — current stable versions.
- `brew install` — simplest approach; Homebrew is pre-installed on `macos-14` runners.
- `push: branches: ['epic/**']` — catches all epic worktree branches pushed to remote.
- DerivedData cache keyed by `Package.resolved` — deterministic given same source/dep version.
- xcresult artifact upload is `if: failure()` only — avoids bloating successful run artifacts.

### Fix for `testNoRemoveItemCall`

**Problem:** The test constructs an absolute path to a different worktree:
```swift
let worktree = "/Users/aramirez/Code/.epic-worktrees/Stevedore/epic-stevedore-mvp--s25-uninstaller-ui"
let sourcePath = "\(worktree)/Sources/Features/Uninstaller/UninstallExecutor.swift"
```

**Fix:** Derive the path relative to the test file using `#filePath`:
```swift
func testNoRemoveItemCall() throws {
    let testFileURL = URL(fileURLWithPath: #filePath)
    // Navigate up 3 directories: UninstallerTests/ → FeaturesTests/ → Tests/ → repo root
    let repoRoot = testFileURL
        .deletingLastPathComponent()
        .deletingLastPathComponent()
        .deletingLastPathComponent()
    let sourcePath = repoRoot
        .appendingPathComponent("Sources/Features/Uninstaller/UninstallExecutor.swift")
        .path
    let source = try String(contentsOfFile: sourcePath, encoding: .utf8)
    XCTAssertFalse(source.contains("removeItem"), "UninstallExecutor must not call removeItem")
}
```

**Why `#filePath`:** Expands to the absolute source file path at compile time. For a
non-installed test target (SPM `swift test`), this is always the path in the current
checkout directory. `#filePath` (Swift 5.3+) is preferred over `#file` because it
returns only the path without module qualification.

### Fix for `testMountedEventAddsVolume` / `testUnmountedEventRemovesVolume`

**Problem:** Two `Task.yield()` calls are insufficient to propagate an event through the
async chain: `emit()` → `AsyncStream.continuation.yield()` → `for await` loop iteration
on the main actor → `self.volumes.append(...)`.

**Fix:** Replace the two yields with `Task.sleep(for: .milliseconds(50))`:
```swift
fakeVols.emit(.mounted(newVol))
try? await Task.sleep(for: .milliseconds(50))
XCTAssertTrue(vm.volumes.contains(where: { $0.url == newVol.url }))
```

Apply to both `testMountedEventAddsVolume` and `testUnmountedEventRemovesVolume`.

**50ms rationale:** Provides a 5× safety margin over the typical sub-10ms propagation
time, without meaningfully slowing the test suite (adds ~100ms total across both tests).
`try? await Task.sleep` is correct here because the test does not need to handle the
cancellation error.

## Risks & Mitigations

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| `xcodebuild -scheme Stevedore` fails: scheme not found | Medium | Run `xcodebuild -list -package-path .` first. If no scheme, substitute `swift build -c release` in the `app` Makefile target and document the deviation. |
| New format/lint violations in Sessions 26–27 not caught by targeted lint | Low | Both sessions ran targeted lint on their files; the full-tree lint in Phase 1 will surface any misses immediately. |
| `swift test --parallel` exposes additional flaky tests beyond the two known | Low | Run tests twice. Classify failures that appear only once as flaky (document only). Fix only deterministic failures. |
| SwiftFormat/SwiftLint not installed on developer machine for local `make ci` | Low | Document installation prerequisite in `docs/ci-report.md`. CI handles installation via `brew install`. |
| `xcodebuild archive` requires code signing setup | Medium | Pass `CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO`. If archive still fails, document as a known gap (archive requires developer certificate) and classify as a post-MVP item. |
