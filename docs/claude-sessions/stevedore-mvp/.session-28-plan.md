## Known Pre-existing Failures to Fix Before Anything Else

These two failures must be resolved before running the quality-gate matrix.

### BUG-1: `testNoRemoveItemCall` hardcoded worktree path
**File:** `Tests/FeaturesTests/UninstallerTests/UninstallExecutorTests.swift:83`
**Root cause:** The test builds the path to `UninstallExecutor.swift` from a hardcoded
absolute path rooted at the **s25 worktree** (`/Users/aramirez/Code/.epic-worktrees/
Stevedore/epic-stevedore-mvp--s25-uninstaller-ui`). That worktree is gone. The test throws
`String(contentsOfFile:)` error and fails.

**Fix:** Derive the source path from `#file` (the test file's path) by walking up three
parent directories to reach the repo root, then appending the source path:

```swift
func testNoRemoveItemCall() throws {
    let testFileURL = URL(fileURLWithPath: #file)
    let repoRoot = testFileURL
        .deletingLastPathComponent()  // UninstallerTests/
        .deletingLastPathComponent()  // FeaturesTests/
        .deletingLastPathComponent()  // Tests/
        .deletingLastPathComponent()  // repo root
    let sourcePath = repoRoot
        .appending(path: "Sources/Features/Uninstaller/UninstallExecutor.swift")
        .path(percentEncoded: false)
    let source = try String(contentsOfFile: sourcePath, encoding: .utf8)
    XCTAssertFalse(source.contains("removeItem"), "UninstallExecutor must not call removeItem")
}
```

**Session of origin:** Session 25 (FeaturesUninstaller).
**Risk:** None. The path arithmetic is mechanical; `#file` is always an absolute path in
XCTest.

### BUG-2: `testMountedEventAddsVolume` — async timing flakiness
**File:** `Tests/UITests/SidebarTests/SidebarViewModelTests.swift:65`
**Root cause:** The test fires a volume event via the fake provider and then checks
`viewModel.volumes`. With `Task.yield()`, there is no hard guarantee the viewModel's
`for await` loop has processed the event before the assertion runs.

**Fix:** Replace `Task.yield()` with a polling-with-timeout helper (the same
`awaitState` pattern used in `FileOperationQueueTests`):

```swift
func testMountedEventAddsVolume() async throws {
    // ... set up fakes, call start() ...
    fakeProvider.emit(MountEvent.mounted(mockVolume))
    // Poll until the volume appears or 1 s elapses
    let deadline = ContinuousClock.now + .seconds(1)
    while ContinuousClock.now < deadline {
        if self.viewModel.volumes.contains(where: { $0.url == mockVolume.url }) { break }
        try await Task.sleep(for: .milliseconds(20))
    }
    XCTAssertTrue(viewModel.volumes.contains(where: { $0.url == mockVolume.url }))
}
```

Apply the same fix to `testUnmountedEventRemovesVolume` if it uses the same pattern.

**Session of origin:** Session 18 (UISidebar).
**Risk:** If a CI runner is very slow, 1 s may be insufficient; 2 s is safer for CI.

## Design Decisions

### D1 — SwiftFormat `--lint` argument order
Per the cerebrum entry (`[Key Learnings]`), SwiftFormat 0.59 requires paths **before**
`--lint`:
```sh
swiftformat Sources Tests App Package.swift --lint
```
NOT `swiftformat --lint Sources ...`. The Makefile and CI workflow both use the correct
form.

### D2 — xcodebuild without a pre-existing `.xcodeproj`
There is no `App/Stevedore.xcodeproj` in the repo. The operator rules call it "generated,
never hand-edited." Two strategies are available:

**Option A (preferred):** Xcode 14+ can drive `xcodebuild` directly against a Swift
Package from the package root. The executable target `Stevedore` becomes a visible scheme:
```sh
xcodebuild -scheme Stevedore \
  -destination 'platform=macOS,arch=arm64' \
  clean build CODE_SIGNING_ALLOWED=NO
```
Run `xcodebuild -list` first to confirm scheme discovery. If it works, no xcodeproj is
needed and the Makefile uses this form.

**Option B (fallback):** Generate the xcodeproj at session start:
```sh
swift package generate-xcodeproj --output App/
```
Then use `xcodebuild -project App/Stevedore.xcodeproj -scheme Stevedore ...`. This is
deprecated in Xcode 16 but still functional.

**Decision:** Try Option A first. Document the result in `docs/ci-report.md`. Fall back to
Option B only if xcodebuild fails to discover the scheme. Do NOT commit a generated xcodeproj
unless it is needed for the CI gate to pass; if committed, add `App/Stevedore.xcodeproj/`
to `.gitignore` instead and generate it in the CI workflow.

### D3 — xcresult artifact path
The `make app` target passes `-resultBundlePath ./TestResults.xcresult` to `xcodebuild` so
the CI workflow can find it:
```makefile
RESULT_BUNDLE := TestResults.xcresult

app:
	xcodebuild -scheme $(SCHEME) \
		-destination '$(DEST)' \
		-resultBundlePath $(RESULT_BUNDLE) \
		clean build CODE_SIGNING_ALLOWED=NO
```
The GitHub Actions `upload-artifact` step matches `**/*.xcresult`.

### D4 — `make ci` sequencing
The five quality gate targets run in dependency order, stopping on first failure.
`make ci` invokes them in sequence via `$(MAKE)`:
```makefile
ci:
	$(MAKE) format-check
	$(MAKE) lint
	$(MAKE) build
	$(MAKE) test
	$(MAKE) app
```
Using `$(MAKE)` (not bare `make`) passes flags correctly and propagates the correct
exit code.

### D5 — CI caching strategy
Three cache directories are relevant:
- `.build` — SwiftPM artifacts
- `~/Library/Developer/Xcode/DerivedData` — Xcode build products
- `~/.swiftpm/cache` — SwiftPM package download cache

Cache key: `macos-14-spm-${{ hashFiles('Package.resolved') }}`
Restore key: `macos-14-spm-` (prefix match)

This ensures a new cache is created when `Package.resolved` changes (new dependencies).

### D6 — Entitlements audit
Current `App/Stevedore.entitlements`:
```xml
com.apple.security.app-sandbox = false
com.apple.security.files.user-selected.read-write = true
com.apple.security.files.bookmarks.app-scope = true
```

Assessment:
- **Sandbox disabled** — correct for MVP. A file manager needs unrestricted filesystem
  access. Sandboxing would require entitlement additions for every mounted volume.
- **user-selected read-write** — correct. Standard file picker entitlement.
- **app-scope bookmarks** — correct. `SecurityScopedBookmarks.swift` (Session 03) uses
  this to persist folder access across launches.

No unused entitlements. No trimming needed.

### D7 — Placeholder modules
Five UI modules are still placeholder-only: `UIPane`, `UITabs`, `UITransfers`,
`UISyncDialog`, `UIRenameDialog`. They each contain only `Placeholder.swift` with a module
sentinel constant. These are real source files — SwiftFormat and SwiftLint will check them,
but they contain minimal code and should pass both gates cleanly. No action needed unless
the gate run reveals a violation.

### D8 — `swift test --parallel` vs `--parallel` flakiness
Session 10 introduced deadline-based polling in `FileOperationQueueTests`. Running with
`--parallel` may interleave timing-sensitive tests. If `swift test --parallel` shows
spurious failures on clean code, fall back to `swift test` (sequential) for the gate, and
note the limitation in `docs/ci-report.md`. Do NOT relax `--parallel` in CI without
documenting the reason.

## Design Decisions & Rationale

### Makefile targets

```makefile
.PHONY: format-check lint build test app ci

format-check:
	swiftformat Sources Tests App Package.swift --lint

lint:
	swiftlint --strict

build:
	swift build -Xswiftc -warnings-as-errors

test:
	swift test --parallel

app:
	xcodebuild -scheme Stevedore \
	    -destination 'platform=macOS' \
	    clean build \
	    CODE_SIGNING_ALLOWED=NO

ci: format-check lint build test app
```

**Rationale:**
- Each target corresponds 1:1 to the exit-criterion commands.
- `swiftformat` paths precede `--lint` (known SwiftFormat 0.59 argument-parser quirk; cerebrum entry).
- `make ci` is the aggregate gate; all sub-targets must exit 0 before the next runs via `make`'s implicit failure propagation.
- `make app` uses `xcodebuild` directly against the SPM package (no `.xcodeproj`). Modern Xcode 15+ auto-detects the `Stevedore` scheme from `Package.swift`. If scheme detection fails locally, the plan includes a fallback (`swift package generate-xcodeproj`) documented in ci-report.md.

### GitHub Actions workflow (`.github/workflows/ci.yml`)

Key decisions:
- Runner: `macos-14` (Apple Silicon; consistent with operator rules macOS 14.0+ target).
- Install SwiftLint and SwiftFormat via `brew install swiftlint swiftformat` with Homebrew cache.
- Cache keys:
  - `.build` keyed by `Package.resolved` hash — invalidated when dependencies change.
  - `~/Library/Developer/Xcode/DerivedData` keyed by package hash.
  - `~/.cache/Homebrew` for tool install speed.
- Upload `.xcresult` as artifact on failure: `xcodebuild` produces `<scheme>.xcresult` in the DerivedData path; upload with `actions/upload-artifact`.
- The workflow calls `make ci` (not individual steps) so the Makefile is the single source of truth for step ordering.

### xcodebuild without .xcodeproj

The operator rules say `App/Stevedore.xcodeproj` is _optional_ and _generated, never hand-edited_. No `.xcodeproj` exists in the current worktree. Xcode 15 resolves SPM package schemes automatically, so:

```bash
xcodebuild -scheme Stevedore -destination 'platform=macOS' clean build CODE_SIGNING_ALLOWED=NO
```

…should work from the package root because:
1. Xcode auto-synthesises a scheme named after each SPM product/executable.
2. `CODE_SIGNING_ALLOWED=NO` skips all signing steps.

If auto-detection fails (e.g., scheme not resolved), the fallback is:
```bash
swift package generate-xcodeproj --output App/Stevedore.xcodeproj
xcodebuild -project App/Stevedore.xcodeproj -scheme Stevedore ...
```

Document whichever path succeeds in `docs/ci-report.md`.

### xcodebuild archive

```bash
xcodebuild \
    -scheme Stevedore \
    -destination 'generic/platform=macOS' \
    archive \
    -archivePath /tmp/Stevedore.xcarchive \
    CODE_SIGNING_ALLOWED=NO \
    CODE_SIGN_IDENTITY="" \
    SKIP_INSTALL=NO
```

- `generic/platform=macOS` is required for archive builds (vs. `platform=macOS` for regular builds).
- `SKIP_INSTALL=NO` ensures the app lands in the archive.
- Expected result: archive succeeds structurally but notarization/export is not attempted.
- If archive fails due to unsigned entitlements, downgrade the task to confirming `clean build` only and document it as an open issue in `docs/ci-report.md`.

### Entitlements audit (`App/Stevedore.entitlements`)

Current entries:
```xml
com.apple.security.app-sandbox = false
com.apple.security.files.user-selected.read-write = true
com.apple.security.files.bookmarks.app-scope = true
```

Analysis:
- `app-sandbox = false`: Correct for an MVP desktop app not yet submitted to the Mac App Store. When sandbox is disabled, many other entitlements are no-ops, but they can be left in place harmlessly.

## Known Failures to Fix

### 1. `SidebarViewModelTests` — async timing (affects 2–3 tests)

**Root cause**: `testMountedEventAddsVolume` (and siblings) call `await Task.yield()` twice after emitting a volume event. On a loaded CI machine, two yields are insufficient for the `@MainActor` actor task to complete processing.

**Fix approach**: Replace the yield pair with a polling loop capped at 500 ms:
```swift
// Before (flaky):
await Task.yield()
await Task.yield()
XCTAssertEqual(viewModel.volumes.count, 1)

// After (stable):
let deadline = ContinuousClock.now + .milliseconds(500)
while ContinuousClock.now < deadline {
    if viewModel.volumes.count == 1 { break }
    try? await Task.sleep(for: .milliseconds(10))
}
XCTAssertEqual(viewModel.volumes.count, 1)
```

**Scope**: `Tests/UITests/SidebarTests/SidebarViewModelTests.swift` only.

### 2. `UninstallExecutorTests.testNoRemoveItemCall` — hardcoded path

**Root cause**: The test hard-codes the absolute path to the Session 25 worktree to grep the source file for absence of `removeItem`. That path does not exist on any other machine.

**Fix approach**: Rewrite using the current file's directory hierarchy:
```swift
func testNoRemoveItemCall() throws {
    // Locate UninstallExecutor.swift relative to the package root.
    // #file resolves to this test file; navigate up to find Sources/.
    let testURL = URL(fileURLWithPath: #file)
    let packageRoot = testURL
        .deletingLastPathComponent() // UninstallerTests
        .deletingLastPathComponent() // FeaturesTests
        .deletingLastPathComponent() // Tests
        .deletingLastPathComponent() // package root
    let sourceURL = packageRoot
        .appendingPathComponent("Sources/Features/Uninstaller/UninstallExecutor.swift")
    let source = try String(contentsOf: sourceURL, encoding: .utf8)
    XCTAssertFalse(source.contains("removeItem"), "UninstallExecutor must use trashItem, not removeItem")
}
```

**Scope**: `Tests/FeaturesTests/UninstallerTests/UninstallExecutorTests.swift` only.

## `.github/workflows/ci.yml` Full Content

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build-and-test:
    runs-on: macos-14
    timeout-minutes: 45

    steps:
      - uses: actions/checkout@v4

      - name: Select Xcode
        run: sudo xcode-select -s /Applications/Xcode.app

      - name: Cache Homebrew packages
        uses: actions/cache@v4
        with:
          path: ~/.cache/Homebrew
          key: ${{ runner.os }}-brew-swiftlint-swiftformat

      - name: Install tools
        run: |
          brew install swiftlint swiftformat || brew upgrade swiftlint swiftformat

      - name: Cache SPM build artifacts
        uses: actions/cache@v4
        with:
          path: .build
          key: ${{ runner.os }}-spm-${{ hashFiles('Package.resolved') }}
          restore-keys: |
            ${{ runner.os }}-spm-

      - name: Cache Xcode DerivedData
        uses: actions/cache@v4
        with:
          path: ~/Library/Developer/Xcode/DerivedData
          key: ${{ runner.os }}-deriveddata-${{ hashFiles('Package.resolved') }}
          restore-keys: |
            ${{ runner.os }}-deriveddata-

      - name: Format check
        run: make format-check

      - name: Lint
        run: make lint

      - name: Build
        run: make build

      - name: Test
        run: make test

      - name: Xcode build
        run: make app

      - name: Upload test results on failure
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: xcresult
          path: ~/Library/Developer/Xcode/DerivedData/**/Logs/Test/*.xcresult
          if-no-files-found: ignore
```
