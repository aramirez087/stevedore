## Design Decisions

### 1. `FeaturesGitModule.swift` — preserve sentinel

Delete `Placeholder.swift` and create `FeaturesGitModule.swift` with the same sentinel value (`"FeaturesGit"`). The existing smoke test at `Tests/FeaturesTests/Git/FeaturesGitSmokeTests.swift` checks this constant at runtime.

```swift
import Core

public enum FeaturesGitModule {
    public static let moduleName: String = "FeaturesGit"
}
```

### 2. `GitError.swift` — typed errors

```swift
public enum GitError: Error, Sendable, Equatable {
    case gitNotFound               // /usr/bin/git absent
    case timeout                   // process exceeded timeoutSeconds
    case nonZeroExit(code: Int32)  // git returned non-zero; stderr available separately
    case parseFailure(String)      // malformed porcelain v2 line
}
```

Rationale: separate `gitNotFound` from `timeout` from `nonZeroExit` allows tests to skip cleanly on missing git, and callers to distinguish transient failures.

### 3. `GitProcess.swift` — Foundation.Process wrapper

Key design points:
- `public struct GitProcess: Sendable` (all static methods, no stored state)
- `static let executablePath = "/usr/bin/git"` — hardcoded, never derived from `$PATH`
- Environment **whitelist** — never inherit the full shell env. Allowed keys:
  ```
  HOME, USER, TMPDIR, LANG, LC_ALL, GIT_SSH, GIT_SSH_COMMAND, SSH_AUTH_SOCK
  ```
  Always inject: `GIT_TERMINAL_PROMPT=0`, `GIT_PAGER=cat`, `PAGER=cat`.
- `run(arguments:workingDirectory:timeoutSeconds:) async throws -> Result` where `Result` is `Sendable` and carries `exitCode: Int32`, `stdout: Data`, `stderr: Data`.
- Blocking `Process.waitUntilExit()` runs inside `Task.detached(priority: .utility)` to avoid blocking the actor executor.

**Timeout mechanism**: Use `withThrowingTaskGroup`. One task runs the process; a second task sleeps for `timeoutSeconds` then terminates the process and throws `GitError.timeout`. Whichever finishes first wins; the task group is cancelled immediately after.

**Swift 6 `Sendable` issue with `Process`**: `Foundation.Process` is not `Sendable`. Work around by wrapping it in a `final class ProcessBox: @unchecked Sendable` that holds the `Process` instance. Pass the box between tasks via structured concurrency. Add a brief comment justifying `@unchecked Sendable` (single-threaded ownership handed off at process launch).

**Pipe reads**: Read `stdout` and `stderr` with `fileHandleForReading.readDataToEndOfFile()` after `waitUntilExit()`. This is safe because the process has already exited.

**Return type**:
```swift
public struct Result: Sendable {
    public let exitCode: Int32
    public let stdout: Data
    public let stderr: Data
}
```

### 4. `RepositoryDetector.swift` — find git root

```swift
public enum RepositoryDetector: Sendable {
    public static func findRoot(for path: FilePath) -> FilePath?
}
```

Algorithm:
1. Start at `path`, walk toward root one level at a time.
2. At each level, check if `.git` exists:
   - As a **directory** (`isDirectory == true`): this directory is the repo root.
   - As a **file** (worktree linkfile): read its contents; it begins with `gitdir: <path>`. The working tree root is the directory containing the `.git` file (i.e. the current candidate directory).
3. If we exhaust all ancestors without finding `.git`, return `nil`.
4. Only handles `scheme == .local` paths; return `nil` for any other scheme.

**Bare repos**: A bare repo has no working tree (`.git` is the repo itself, not a subdirectory). We detect bare repos by checking if the candidate `.git` is absent and if a `HEAD` file exists directly. For the MVP, bare repos return `nil` (no working-tree status to report).

**Performance**: All I/O is synchronous `FileManager` stat calls. This is fast (< 1ms for typical depths). No async overhead needed; callers wrap in `Task.detached` if required.

### 5. `GitStatusParser.swift` — parse porcelain v2 NUL output

```swift
public enum GitStatusParser: Sendable {
    public static func parse(_ data: Data, repoRoot: FilePath) -> [GitFileStatus]
}
```

**Porcelain v2 format** (with `-z`): NUL-delimited records. Split `data` at every `\0` byte to obtain a flat token array. Process tokens with an integer cursor:

| Token prefix | Record type | Tokens consumed | Notes |
|---|---|---|---|
| `#` | Header/branch info | 1 | Skip |
| `1` | Ordinary changed | 1 | `1 XY sub mH mI mW hH hI path` |
| `2` | Renamed/copied | 2 | `2 XY sub mH mI mW hH hI X<score> path` then `origPath` |
| `u` | Unmerged | 1 | `u XY sub m1 m2 m3 mW h1 h2 h3 path` |
| `?` | Untracked | 1 | `? path` |
| `!` | Ignored | 1 | `! path` |

**Status character mapping** (for `X` and `Y` columns in type `1`, `2`, `u` entries):
```
'.' → .unmodified
'M' → .modified
'T' → .typeChanged
'A' → .added
'D' → .deleted
'R' → .renamed
'C' → .copied
'U' → .conflicted
```

For **untracked** (`?`) entries: `indexState = .untracked`, `worktreeState = .untracked`.
For **ignored** (`!`) entries: `indexState = .ignored`, `worktreeState = .ignored`.
For **renamed/copied** (type `2`): use the *new* path (`path` token) in `GitFileStatus.path`; skip `origPath` token (advance cursor by 2). For the MVP we don't need to surface the original path.

**Paths in output** are relative to the repo root. Construct absolute `FilePath` by appending relative path components to `repoRoot`.

**Submodule handling**: type `1` and `2` entries have a `sub` field. `N...` = not a submodule; `S<c><m><u>` = submodule. Parse the XY columns the same way regardless; the submodule's git state is visible in X/Y.

**Error resilience**: Unknown token prefixes are silently skipped (return empty results for that token, advance cursor by 1). The parser must never throw — any malformed input produces a partial result.

### 6. `GitStatusCache.swift` — actor with FSEvents invalidation

```swift
public actor GitStatusCache {
    // Per-repo cache entries
    private var entries: [FilePath: CacheEntry] = [:]

    struct CacheEntry: Sendable {
        var statuses: [GitFileStatus]
        var watchTask: Task<Void, Never>?
    }

    /// Returns cached statuses or calls `fetch` to populate.
    public func getOrFetch(
        repoRoot: FilePath,
        fetch: @Sendable () async throws -> [GitFileStatus]
    ) async throws -> [GitFileStatus]

    /// Force invalidation (e.g. called from watcher callback).
    public func invalidate(repoRoot: FilePath)
}
```

**FSEvents watcher** (implemented inline, no `FileSystemLocal` dependency):
- Use `CoreServices.FSEventStreamCreate` directly (same technique as `FSEventsWatcher` in Session 03).
- Watch the repo root path with `kFSEventStreamCreateFlagFileEvents | kFSEventStreamCreateFlagUseCFTypes`.
- **Latency: 0.05 seconds** (50ms). This ensures events arrive well within the 200ms exit criterion even accounting for test execution overhead.
- On any FSEvent, call `self.invalidate(repoRoot:)` from a `Task { await ... }` hop.
- The `watchTask` in `CacheEntry` holds a `Task<Void, Never>` that owns the `AsyncStream` iterator for the FSEvent stream. When the entry is removed or replaced, cancel the task.

**Lazy start**: the watcher is started on the first `getOrFetch` call for a given `repoRoot`. This avoids spinning up watchers for repos no one is querying.

**Cache invalidation flow**:
1. FSEvent arrives → actor schedules `invalidate(repoRoot:)`.
2. `invalidate` sets `entries[repoRoot]?.statuses = []` (clears stale data).
3. Next `getOrFetch` call triggers a fresh `git status` run.

**Swift 6 compliance**: The FSEvent C callback captures a `StreamBox: @unchecked Sendable` heap box (same pattern as `FSEventsWatcher`). The actor is re-entered only via `Task { await ... }` hops.

**Rationale for 200ms requirement**: FSEvents latency of 50ms + one git process launch (~50-100ms on a clean repo) + one async hop ≈ 150-200ms worst case. Tests must sleep ≥ 250ms after a file modification before asserting the cache is fresh.

### 7. `GitStatusService.swift` — concrete `GitStatusProvider`

```swift
public actor GitStatusService: GitStatusProvider {
    private let cache: GitStatusCache

    public init(cache: GitStatusCache = GitStatusCache())

    // GitStatusProvider
    public func status(under directory: FilePath) async throws -> [GitFileStatus]
    public func repositoryRoot(for path: FilePath) async -> FilePath?
}
```

**`status(under:)` implementation**:
1. Call `RepositoryDetector.findRoot(for: directory)`. If `nil`, return `[]`.
2. Call `cache.getOrFetch(repoRoot:fetch:)`.
3. In the `fetch` closure: run `GitProcess.run(arguments: ["status", "--porcelain=v2", "-z", "--untracked-files=all", "--ignored=matching"], workingDirectory: ...)`. If `exitCode != 0`, throw `GitError.nonZeroExit(code:)`. Parse with `GitStatusParser.parse(_:repoRoot:)`.
4. Filter results to entries whose `path` is under `directory` (i.e. `directory` is a prefix of `path`).

**`repositoryRoot(for:)` implementation**: Delegate to `RepositoryDetector.findRoot(for:)`.

**Future extension points** (NOT implemented in Session 14, but leave public protocol stubs for):
- `stage(at:)`, `unstage(at:)`, `commit(message:)`, `discard(at:)` — these belong to a later session. The `Core.GitStatusProvider` protocol does not declare these; they would go on a separate `GitCommandProvider` protocol.

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| `Foundation.Process` is not `Sendable` | Wrap in `ProcessBox: @unchecked Sendable`; justify comment |
| FSEvents latency in CI may exceed 200ms | Use 50ms FSEvents latency; test sleeps 250ms; accept flakiness on very slow CI |
| Porcelain v2 `--ignored` output large for big repos | Cache per-repo; not called on every file individually |
| `git status` exit non-zero in detached HEAD | Non-zero exit throws `GitError.nonZeroExit` — callers may treat as empty status |
| Worktree `.git` linkfile path resolution | Read linkfile, take parent dir as working-tree root; document known edge cases |
| `XCTSkip` must be `throw` not `return` | Always use `throw XCTSkip(...)`, never `return` after skip |
| Double-fetch race in cache | Use `inFlight` task tracking in `GitStatusCache` to coalesce concurrent fetches |

## Accuracy Notes vs. Actual Implementation

The implementation diverged from the plan in these minor ways:

1. **`GitStatusCache.CacheEntry`** — the actual implementation adds a `fetchTask`
   field for in-flight coalescing (plan described it but didn't include it in the
   struct definition shown above). The full actual struct:
   ```swift
   private struct CacheEntry {
       var statuses: [GitFileStatus]
       var watchTask: Task<Void, Never>?
       var fetchTask: Task<[GitFileStatus], any Error>?
   }
   ```

2. **`GitStatusCache` FSEvents** — uses a `CallbackPayload` class (not `StreamBox`)
   to carry the `weak var cache` and `repoRoot` across the C callback boundary.
   `StreamBox` holds the `FSEventStreamRef` separately.

3. **`GitProcess` is `public enum`** (not `public struct`) — all static; this is
   equivalent and satisfies SwiftLint's `no_empty_class` preference.

4. **Test `testGitNotFound`** — not present as a standalone test (the guard is
   tested implicitly; no mechanism to shadow `executablePath` at test time without
   making the property mutable). The `skipIfGitMissing()` helper covers absence.

5. **`testStatusFilteredToSubdirectory`** — an 11th integration test was added to
   `GitStatusProviderTests` beyond the plan's 10; it verifies the directory-prefix
   filter returns only entries under the requested subdirectory.
