## Key Design Decisions (for handoff authoring)

### GitProcess — environment isolation
- Whitelisted keys only: `HOME`, `USER`, `TMPDIR`, `LANG`, `LC_ALL`, `GIT_SSH`, `GIT_SSH_COMMAND`, `SSH_AUTH_SOCK`.
- Always injects: `GIT_TERMINAL_PROMPT=0`, `GIT_PAGER=cat`, `PAGER=cat`.
- `Foundation.Process` is not `Sendable`; wrapped in `ProcessBox: @unchecked Sendable` (single-owner, justified comment).
- Two-task `withThrowingTaskGroup`: one runs the process, one sleeps for `timeoutSeconds` and terminates it.

### RepositoryDetector — worktree support
- Walks ancestor chain via `FilePath.parent`.
- `.git` as **directory** → normal repo, containing directory is root.
- `.git` as **file** → git worktree linkfile; containing directory is the working-tree root.
- Bare repos: `.git` absent with no working-tree evidence → `nil` (no status to report).
- Non-`.local` scheme → immediate `nil`.

### GitStatusParser — porcelain v2 NUL-delimited
- Splits data on `\0` (byte 0) into a flat token array; processes with an integer cursor.
- Type-2 (renamed/copied) records consume 2 tokens (new path + orig path); cursor advances by 2.
- Unknown prefixes silently skip (cursor +1); parser never throws.
- All paths in output are relative to repo root; `repoRoot.appending(posix:)` builds absolute `FilePath`.

### GitStatusCache — actor + FSEvents
- `CacheEntry`: `statuses: [GitFileStatus]`, `hasFetched: Bool`, `watchTask: Task<Void, Never>?`, `fetchTask: Task<[GitFileStatus], any Error>?`.
- `hasFetched` sentinel (added in Session 01 bug fix) distinguishes "empty result" from "never fetched".
- FSEvents stream created via `FSEventStreamCreate`; latency 0.05s; `kFSEventStreamCreateFlagFileEvents | kFSEventStreamCreateFlagUseCFTypes`.
- `CallbackPayload` heap class carries `weak var cache: GitStatusCache?` and `repoRoot: FilePath` across the C callback boundary (`@unchecked Sendable`; docs explain ownership).
- `StreamBox` heap class holds `FSEventStreamRef?` for `@Sendable` capture in `onCancel`.
- FSEvent callback dispatches `Task { await cache?.invalidate(repoRoot:) }`.

### GitStatusService — concrete provider
- `status(under:)`: detect repo root → cache `getOrFetch` → filter by directory prefix.
- `git status --porcelain=v2 -z --untracked-files=all --ignored=matching`.
- Non-zero exit → `GitError.nonZeroExit(code:)`.
- `repositoryRoot(for:)`: pure delegation to `RepositoryDetector.findRoot(for:)`.

### Out-of-scope (MVP deferral)
- `stage`, `unstage`, `commit`, `discard`, `push`, `pull` — not in `Core.GitStatusProvider`; would require a separate `GitCommandProvider` protocol.
- Multi-repo (nested git repos within working tree).
- Submodule recursive status — reported at submodule path level only.
- Bare repository status.
- Remote-tracking branch metadata from `# branch.ab +N -N` headers.

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| FSEvents timing in CI may exceed 200ms | 50ms FSEvents latency; test sleeps 250ms; verified by `testFSEventsInvalidation` |
| `Process` not `Sendable` | `ProcessBox: @unchecked Sendable`; single-owner, never accessed concurrently after launch |
| `git status --ignored` slow on large repos | Cache per-repo; not called per-file; cache invalidated on actual change |
| `XCTSkip` must throw, not return | `throw XCTSkip(...)` used everywhere via `skipIfGitMissing()` |
| Concurrent cache miss race | `fetchTask` coalescing in `CacheEntry` ensures single in-flight git process per repo |

### Decisions
- `GitProcess` is `public enum` (all static) — satisfies SwiftLint `no_empty_class`.
- `ProcessBox: @unchecked Sendable` — wraps non-Sendable `Foundation.Process`; single-owner.
- 50ms FSEvents latency — ensures cache invalidation within 200ms exit criterion.
- `hasFetched` sentinel in `CacheEntry` — distinguishes empty result from cold cache (bug fixed in Session 01 carry-over).
- `--untracked-files=all --ignored=matching` — makes untracked/ignored files visible in all subdirectories.
- Parser skips unknown prefixes silently — forward-compatible with future git versions adding new record types.

### Open issues / risks
1. `--ignored=matching` can produce large output on repos with many ignored files. Not a concern for MVP file pane, but consider `--ignored=no` for non-git-decoration use cases.
2. FSEvents timing test (`testFSEventsInvalidation`) may be flaky on heavily loaded CI — inherent to 200ms real-time requirement.
3. Bare repositories return `nil` from `RepositoryDetector` — acceptable for MVP; would need `git rev-parse --is-bare-repository` to distinguish.
4. Submodule status reported at submodule path level only; recursive status deferred.
5. `detectConflicts` / `destinationReadOnly` not in scope.
