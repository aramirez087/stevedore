## Key Design Decisions (already codified)

### 1. Observation via continuation dictionary, not `NotificationCenter`
The spec says "Backed by `NotificationCenter`"; the implementation uses
`[String: [UUID: AsyncStream<Data>.Continuation]]`. This is intentionally
superior:
- No stringly-typed `Notification.Name` coupling.
- No cross-process or cross-suite leakage in tests.
- Fits actor isolation cleanly: no `@objc` bridging required.

Recorded as a deliberate spec divergence in the handoff.

### 2. `UserDefaults` stores JSON-encoded `Data` uniformly
Bool, String, and Double are all JSON-encoded rather than using
`setBool`/`setDouble`. Keeps the encode/decode path isomorphic to
`InMemorySettingsStore`; avoids a type-dispatch matrix; prevents
UserDefaults type-mismatch surprises at the cost of slightly larger plist
entries.

### 3. Atomic write via `.json.tmp` + `replaceItem`/`moveItem`
On APFS both `replaceItem(at:withItemAt:)` (existing destination) and
`moveItem(at:to:)` (new destination) use `renameat(2)`, which is
POSIX-atomic on the same volume. Stale `.tmp` cleanup at `init` ensures a
mid-write crash leaves the last good `.json` intact and returns defaults on
next read.

### 4. Repository cache-on-first-access
`cache: [T]?` is nil until first `all()` / `loaded()` call. Updated before
writing to disk on every `save()` to prevent a re-read race window between
cache population and disk write.

### 5. `allKeys` literal enforces catalog completeness at test time
`SettingsCatalogTests` asserts `allKeys.count == 15` and all-unique. Adding
a setting without updating `allKeys` fails the test. Removing from `allKeys`
without removing the property fails the count. No compile-time enforcement
for adding settings in a rogue type outside `Settings` — enforced by
convention + review.

## Risks and Mitigations

### Risk 1 — SwiftFormat violations in generated files
Prior sessions may have generated code with minor whitespace issues.

**Mitigation:** Run format lint as the very first step. Fix before touching
anything else.

### Risk 2 — SwiftLint strict violations
`private var continuations` is a deeply nested generic type; cyclomatic
complexity in `JSONFileStore.read` could exceed the default limit.

**Mitigation:** Run lint immediately after format. Likely fix: introduce a
private `typealias` for the nested continuation type, or extract a
sub-function in `read()`.

### Risk 3 — `observe()` double-emit under concurrent write
Between `registerObserver` (adds continuation) and the first snapshot read,
a concurrent `set()` can be buffered AND appear in the snapshot. Subscriber
sees the value twice.

**Impact:** Benign — SwiftUI deduplications on re-render; no data corruption.
**Mitigation:** Documented in handoff; do not "fix" without a failing test.

### Risk 4 — `SettingsCatalogTests` count drift
Test asserts `count == 15`. Any catalog addition not paired with a test
update fails.

**Mitigation:** Do not add settings in this session. The count is by design.

### Risk 5 — `JSONFileStore.init` not called with a real Application Support URL
The repositories only receive a pre-constructed `JSONFileStore`; nothing in
`ServicesSettings` creates the `~/Library/Application Support/Stevedore/`
directory. Caller responsibility.

**Mitigation:** Documented in handoff under "Application startup wiring."

### Risk 6 — `swift test --filter SettingsTests` matches zero tests
XCTest class names are `SettingsStoreTests`, `JSONFileStoreTests`, etc.;
the substring `"SettingsTests"` does not appear in any class name.

**Mitigation:** Use `--filter ServicesTests` to run the full services suite,
or the targeted filter:
```
--filter "SettingsStore|JSONFileStore|SettingsCatalog|BookmarksRepo|WorkspacesRepo|RecentConnections|ServicesSettingsSmoke"
```
