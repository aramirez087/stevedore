## 3. Design Decisions in Code — Do Not Change

These are correct and intentional. Fix code only if a quality gate or test fails.

1. **`validateAndSplitEntryPath` is the security gate.** Called in both
   `ZipBackend.listEntriesSync` and `TarBackend.listEntries` before any
   disk write. Rejects absolute paths, `~`-prefixes, `..` components, NUL
   bytes, and empty paths. Lives in `ArchiveEntry.swift`.

2. **Staging-dir pattern in `ArchiveExtractor`.** A UUID-keyed hidden directory
   (`.stevedore-extract-<UUID>`) is created inside `target`. All bytes land
   there first; `defer` blocks remove it on error/cancellation. The test
   `testCancellationLeavesNoStagingArtifacts` pins this guarantee.

3. **`TarProcessRunner` actor owns `Process`.** `Process` is non-`Sendable`;
   actor isolation avoids Swift 6 data-race warnings. The `onCancel`
   handler delivers `process.terminate()` via an unstructured `Task`
   (cannot call actor method synchronously from a `@Sendable` closure).

4. **ZIPFoundation `Archive` confined to `Task.detached`.** Created, used,
   and released in a single detached task; never captured across `await`.
   No `@unchecked Sendable` needed.

5. **`ArchiveProvider.cachedEntries`.** Lazy; populated on first call to
   `loadEntries()`. Actor-isolated, so concurrent calls are safe.

6. **`TarBackend.extractAll` calls `listEntries` again internally.** Redundant
   but safe. Do NOT refactor — it would be a behaviour change outside scope.

7. **Dead guard in `ArchiveProvider.attributes`.** The branch
   `path.components == self.archiveURL.pathComponents.map(\.self)` can never
   fire because `URL.pathComponents` includes `"/"` as the first element
   while `FilePath.components` excludes it. Root attributes are already handled
   by `path.isRoot`. This is a latent dead-code issue; do NOT fix it (it is
   within the session's touch-glob, but fixing it has no test value and risks
   regressions).

8. **Zip-only writes.** `ArchiveCreator` creates only zip archives. Tar
   creation is explicitly out of scope for MVP.

9. **`watch` returns an immediately-finishing stream.** Archives are
   immutable while mounted. Correct and intentional.

10. **Compression level mapping.** ZIPFoundation 0.9.x has only on/off
    DEFLATE. `CompressionLevel.default` and `.best` both map to `.deflate`;
    `.none` maps to `CompressionMethod.none`.

## 5. Known Risks to Verify During Execution

### Risk 1: BSD tar strips `../` in listing
**Concern:** On some macOS versions, `/usr/bin/tar -tf` may sanitise traversal
paths, causing `testMaliciousTarListContainsTraversalPath` to fail.

**Mitigation:** Malicious tar fixture is hand-rolled (no subprocess), guaranteeing
the raw name field is `../escape.txt`. BSD tar (libarchive) outputs raw names in
`-tf` listing mode. If this still fails, assert on extract safety instead.

### Risk 2: `./`-prefixed paths from BSD tar
**Concern:** `tar -tf` on macOS often outputs `./a.txt` rather than `a.txt`.

**Impact:** `validateAndSplitEntryPath("./a.txt")` returns `[".", "a.txt"]` —
passes validation. `URL.appendingPathComponent("./a.txt")` normalises correctly.

`TarBackendTests.testListTarEntries` handles this:
```swift
XCTAssertTrue(paths.contains("a.txt") || paths.contains("./a.txt"))
```

### Risk 3: swiftlint `function_body_length` on `TarProcessRunner.execute`
Default limit is 40 lines (warning) / 50 lines (error). Under `--strict`,
warnings become errors. If this fires, split into `launchProcess` and
`waitForResult` helpers.

### Risk 4: swiftformat `wrapMultilineStatementBraces` conflict
Check that `.swiftformat` has `--disable wrapMultilineStatementBraces` (added
in Session 04). If not present, multi-line closures may trigger violations.

### Risk 5: `@testable import FileSystemArchive` access
Tests use `@testable` to access `ArchiveEntry`, `ArchiveBackend`, `ZipBackend`,
`TarBackend`, and `validateAndSplitEntryPath`. Confirm none are `fileprivate`.

## 9. Module Architecture

### Public surface

```
FileSystemArchive
├── ArchiveProvider        (actor: FileSystemProvider)
├── DefaultArchiveBrowser  (struct: Core.ArchiveBrowser)
├── ArchiveDetector        (enum namespace)
├── ArchiveExtractor       (struct: Sendable)
├── ArchiveCreator         (struct: Sendable)
└── ArchiveExtractionResult (struct: Hashable, Sendable)
```

### Internal types

```
FileSystemArchive (internal)
├── ArchiveBackend       (protocol: Sendable)
├── ArchiveEntry         (struct: Hashable, Sendable)
├── ZipBackend           (struct: ArchiveBackend)
└── TarBackend           (struct: ArchiveBackend)
    └── TarProcessRunner (actor — owns Process)
```

### Concurrency model

- `ArchiveProvider` is an actor — exclusive access to `cachedEntries`.
- All backends are stateless `struct`s with `Sendable` fields.
- ZIPFoundation's `Archive` (a class) is created and released within one
  `Task.detached` — never escapes across `await`. No `@unchecked Sendable`.
- `Process` is non-`Sendable`; encapsulated inside `TarProcessRunner` actor.
- `ArchiveExtractor` and `ArchiveCreator` are `Sendable struct`s (immutable).

### Security model

- All entry paths pass through `validateAndSplitEntryPath` in backend
  `listEntries` **before** any disk write.
- Rejected: absolute paths (`/`-prefix), `~`-prefix, `..` components,
  NUL bytes, empty components.
- Symlink targets are validated separately: reject targets starting with
  `/` or containing `..` components.
- Staging-dir pattern ensures no byte reaches the final target until
  path validation is complete.
