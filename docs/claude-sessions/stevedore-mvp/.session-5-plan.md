# Session 05 — Archive Provider — Implementation Plan

## 1. Goals & exit criteria recap

Implement the `FileSystemArchive` module so the rest of the app can browse,
extract, and create archives uniformly. Concretely:

- A pure-Swift ZIP backend (ZIPFoundation) with listing, single-entry
  extract, full extract, and entry stream reads, preserving POSIX modes
  and modification dates.
- A tar / tar.gz / tar.bz2 backend that shells out to `/usr/bin/tar` for
  extraction with byte-counted progress and cooperative cancellation.
- An `ArchiveProvider` actor implementing `Core.FileSystemProvider` over a
  mounted archive root. Read-only listing for the MVP; write paths return
  `unsupported` and are documented in the handoff.
- A `DefaultArchiveBrowser` implementing `Core.ArchiveBrowser` (extension
  + magic-byte detection, entry listing).
- An `ArchiveExtractor` orchestrator that stages entries into a sibling
  directory, validates every entry against path traversal **before** any
  byte is written, reports per-entry progress, and atomically reconciles
  to the final target. Mid-flight cancellation deletes the staging dir
  and never leaves half-written files in the target.
- An `ArchiveCreator` that produces zip archives from a list of source
  URLs preserving relative paths, with configurable compression.
- Tests covering: detection, round-trip create→extract for zip, extract
  for tar variants, path-traversal rejection (zip + tar), conflict
  resolution, cancellation cleanup.
- `docs/roadmap/stevedore-mvp/session-05-handoff.md` covering supported
  formats, MVP write limitations, and security notes.

## 5. Detailed design

### 5.1 `ArchiveModule.swift`

```swift

/// to compile after `Placeholder.swift` is removed.
public enum FileSystemArchiveModule {
    public static let moduleName: String = "FileSystemArchive"
}
```

### 5.2 `ArchiveDetector.swift`

```swift
public enum ArchiveDetector {
    public static func detect(at url: URL) async throws -> ArchiveFormat?
    public static func isArchive(_ url: URL) async -> Bool
    public static func detectByExtension(_ name: String) -> ArchiveFormat?
    public static func detectByMagic(_ data: Data) -> ArchiveFormat?
}
```

- `detectByExtension` lower-cases the filename and matches multi-suffix
  forms first (`.tar.gz`, `.tar.bz2`) before single-suffix (`.tgz`,
  `.tbz2`, `.tar`, `.zip`).
- `detectByMagic` reads only the first 264 bytes (enough to cover the
  ustar magic at offset 257). Reads via `FileHandle.read(upToCount:)` —
  no full-file slurp.
- `detect(at:)` prefers extension-based detection (cheaper) then falls
  back to magic for ambiguous filenames or extension-less files.
- ZIP magic: `0x50 0x4B 0x03 0x04` (`PK\003\004`).
- GZip magic: `0x1F 0x8B`.
- BZip2 magic: `0x42 0x5A 0x68` (`BZh`).
- Tar (POSIX ustar) magic: bytes `[257..262]` == `"ustar"`.
- Returns `.tarGzip` for gzip+tar guesses; pure `.gzip` (without `.tar`)
  is **not** in scope — record in handoff as a known limitation.

### 5.3 `ArchiveEntry.swift` (internal)

```swift
internal struct ArchiveEntry: Hashable, Sendable {
    let pathComponents: [String]   // relative, never empty, never "."/".."
    let kind: FileKind             // .regularFile / .directory / .symbolicLink
    let sizeInBytes: Int64?
    let modificationDate: Date?
    let permissions: PosixPermissions?
    let symbolicLinkTarget: String?
}
```

A small adapter `func asFileItem(rootScheme: ConnectionScheme)
-> FileItem` rebases components onto a virtual `FilePath` rooted at the
archive's mount root.

### 5.4 `ArchiveBackend.swift` (internal protocol)

```swift
internal protocol ArchiveBackend: Sendable {
    var format: ArchiveFormat { get }
    func listEntries(at archive: URL) async throws -> [ArchiveEntry]
    func extractAll(
        from archive: URL,
        to destination: URL,
        progress: (any OperationProgressReporting)?
    ) async throws
}
```

Backends are stateless `struct`s. The `extractAll` method is responsible
for **its own cancellation propagation**: tar terminates the subprocess;
zip checks `Task.isCancelled` between entries and throws
`CancellationError` (which `ArchiveExtractor` catches and converts into
`StevedoreError.cancelled`).

`listEntries` is required to validate entries and reject any path that
contains a `..` component, starts with `/`, or contains an empty
component. Validation throws `StevedoreError.archive(.corruptedEntry(detail:))`
with a descriptive message naming the offending raw path.

### 5.5 `ZipBackend.swift`

```swift
public struct ZipBackend: ArchiveBackend {
    public let format: ArchiveFormat = .zip
    public init() {}
    public func listEntries(at archive: URL) async throws -> [ArchiveEntry]
    public func extractAll(from:to:progress:) async throws
    public func extractEntry(at relativePath: String, from archive: URL, to file: URL) async throws
    public func streamRead(entryPath: String, from archive: URL) -> AsyncThrowingStream<Data, any Error>
}
```

- Open `Archive(url: archive, accessMode: .read)`. Throws on bad/missing
  archive: convert to `StevedoreError.archive(.corruptedEntry(detail:))`.
  ZIPFoundation does not raise a passwords error explicitly; we treat
  any encrypted entry's failure as `.archive(.passwordRequired)` based
  on `entry.isEncrypted` if available, else `.corruptedEntry`.
- Iterate entries with `for entry in archive`. For each:
  - Reject path traversal upfront.
  - Map `entry.type`: `.file → .regularFile`, `.directory → .directory`,
    `.symlink → .symbolicLink`.
  - `entry.fileAttributes` returns a `[FileAttributeKey: Any]` from
    Foundation; pull `.posixPermissions` (NSNumber) and
    `.modificationDate` (Date).
- `extractAll` iterates entries, computes a per-entry destination URL
  inside `destination`, ensures the parent dir exists with
  `FileManager`, and calls
  `archive.extract(_:to:bufferSize:skipCRC32:progress:)`. Between entries
  it runs `try Task.checkCancellation()`. ZIPFoundation's `Progress`
  callback is bridged to our reporter every ~64 KB processed.
- Buffer size: `64 * 1024` (matches ZIPFoundation default, reduces
  memory footprint).
- `streamRead` wraps an `AsyncThrowingStream` with a continuation;
  inside, opens the archive on a detached task and calls
  `archive.extract(_:bufferSize:skipCRC32:progress:consumer:)` (the
  consumer-closure variant) yielding each chunk to the stream.
- All work is performed on a `Task.detached` (synchronous file I/O off
  any main actor), then results are returned to the caller.

ZIPFoundation API surface used (from version 0.9.20, public):
- `class Archive` — `init(url:accessMode:)`, conforms to `Sequence`,
  `archive.makeIterator()`.
- `struct Entry` — `path: String`, `type: Entry.EntryType`,
  `fileAttributes: [FileAttributeKey: Any]`, `uncompressedSize: Int64`.
- `func extract(_ entry: Entry, to url: URL, bufferSize: Int = 32768,
   skipCRC32: Bool = false, progress: Progress? = nil) throws -> CRC32`
- `func extract(_ entry: Entry, bufferSize: Int = 32768,
   skipCRC32: Bool = false, progress: Progress? = nil,
   consumer: (_ data: Data) throws -> Void) throws -> CRC32`
- For creation: `init(url:accessMode: .create)`, then
  `func addEntry(with relativePath: String, fileURL: URL,
   compressionMethod: CompressionMethod = .deflate, ...) throws`.
- `enum CompressionMethod { case none, deflate }` — only two levels in
  the .zip spec; "compression level" maps to `.none` vs `.deflate` (no
  finer DEFLATE level control in ZIPFoundation 0.9.x). Our public
  `CompressionLevel.best` and `.default` both map to `.deflate`;
  `.none` maps to `CompressionMethod.none`. Documented.

### 5.6 `TarBackend.swift`

```swift
public struct TarBackend: ArchiveBackend {
    public let format: ArchiveFormat   // .tar, .tarGzip, or .tarBzip2
    public init(format: ArchiveFormat) throws  // throws .invalidArgument for non-tar formats
    public func listEntries(at archive: URL) async throws -> [ArchiveEntry]
    public func extractAll(from:to:progress:) async throws
}
```

`/usr/bin/tar` invocations:
- list: `["tar", "-tf", archive.path]` for `.tar`,
  `["-tzf", path]` for `.tarGzip`, `["-tjf", path]` for `.tarBzip2`.
  Output is one entry per line.
- extract: `["-xvf", path, "-C", destination.path]` (or `-xvzf`,
  `-xvjf`). The `-v` flag streams "x <name>" lines to stderr per
  extracted entry.

Process plumbing:
- Wrap each run in a small `actor TarProcessRunner` that owns the
  `Process` and pipes; this gives us a single isolation domain for
  termination. Set `currentDirectoryURL` to `/`. Set
  `qualityOfService = .userInitiated`.
- Stdout pipe → line-reader on a `Task` for streaming progress events
  (count newlines of stdout for list, "x" lines for extract).
- Stderr pipe → captured for error reporting (`tar` writes errors
  there).
- `Task.checkCancellation()` is hooked via `withTaskCancellationHandler`:
  on cancel, call `process.terminate()` then `process.waitUntilExit()`.
  Throw `CancellationError` after termination.
- Non-zero termination status → `StevedoreError.archive(.corruptedEntry(detail:))`
  with stderr included in the detail string.

Path validation (executed for every operation, not just extract):
- After `listEntries` parses raw paths, walk each. Reject if:
  - the path begins with `/` (absolute);
  - any `/`-split component equals `..`;
  - the path begins with `~`;
  - the path contains a NUL byte.
- Throw `StevedoreError.archive(.corruptedEntry(detail:))` immediately;
  do **not** proceed to extract. This is the central defense against
  malicious tarballs and the assertion the path-traversal test pins
  down.

### 5.7 `DefaultArchiveBrowser.swift`

```swift
public struct DefaultArchiveBrowser: ArchiveBrowser {
    public init() {}

    public func isArchive(_ path: FilePath) async -> Bool

    public func entries(in archive: FilePath) async throws -> [FileItem]
}
```

- Backed by `ArchiveDetector` for kind detection.
- `entries(in:)` resolves the `FilePath` to a `URL` (`.local` only for
  MVP — non-local schemes throw `.unsupported`), picks the right backend
  (`ZipBackend` or `TarBackend(format:)`), calls `listEntries(at:)`, and
  maps each `ArchiveEntry` to a `FileItem` rooted at the archive path.
- Result is sorted by `posixString` for deterministic ordering.

### 5.8 `ArchiveExtractor.swift`

```swift
public struct ArchiveExtractor: Sendable {
    public init(
        progress: (any OperationProgressReporting)? = nil,
        conflictPolicy: ConflictPolicy = .overwrite
    )

    public func extract(
        archive: URL,
        to target: URL
    ) async throws -> ArchiveExtractionResult
}

public struct ArchiveExtractionResult: Hashable, Sendable {
    public let entriesExtracted: Int
    public let bytesProcessed: Int64
}
```

Lifecycle:
1. `ArchiveDetector.detect(at: archive)` → `ArchiveFormat`. Throw
   `.archive(.unsupportedFormat)` if `nil`.
2. Pick backend: `ZipBackend()` or `TarBackend(format:)`.
3. `try await backend.listEntries(at: archive)` — runs path-traversal
   validation. If any entry is rejected, the call throws and **no disk
   write has occurred** (this is asserted by the traversal tests).
4. Compute total bytes for progress = sum of regular-file sizes.
5. Create staging dir as `target.appendingPathComponent(".stevedore-extract-\(uuid)", isDirectory: true)`.
   Wrap the rest of the function in:
   ```swift
   let stagingURL = ...
   defer { try? FileManager.default.removeItem(at: stagingURL) }
   ```
   Combined with `withTaskCancellationHandler`, the staging dir is
   reliably removed even on cancellation.
6. Call `try await backend.extractAll(from: archive, to: stagingURL,
   progress: …)` — backend handles its own per-entry progress, which we
   forward verbatim.
7. After successful staging, walk the staging tree depth-first and move
   each entry to its final location under `target`. For each:
   - If destination exists and policy is `.skip`, skip.
   - If destination exists and policy is `.overwrite`, remove the
     destination then move.
   - `.ask` and `.rename` policies are accepted but documented as
     deferred — for MVP they fall back to `.overwrite` (with a logged
     warning) so the function does not deadlock waiting for a UI
     callback.
8. Final progress report: `.completed` phase with full byte count.
9. Return `ArchiveExtractionResult`.

Cancellation guarantees:
- Backends throw `CancellationError` when `Task.isCancelled` is true
  (zip checks between entries; tar terminates the subprocess).
- `extract` catches `CancellationError`, converts to
  `StevedoreError.cancelled`, and rethrows. The `defer` deletes the
  staging dir.
- The reconcile (step 7) checks `Task.checkCancellation()` between
  moves; cancellation there leaves only fully-moved entries in `target`,
  which by definition are not "half-written".
- Test assertion: after a cancelled extract, no file under `target`
  matches the staging-name pattern, and total file count under `target`
  equals the number of items reported as fully reconciled before cancel
  (or zero if cancel hit during phase 6).

### 5.9 `ArchiveCreator.swift`

```swift
public struct ArchiveCreator: Sendable {
    public enum CompressionLevel: Sendable {
        case none
        case `default`
        case best
    }

    public init(compressionLevel: CompressionLevel = .default)

    public func createZip(
        sources: [URL],
        relativeTo base: URL,
        archive: URL,
        progress: (any OperationProgressReporting)? = nil
    ) async throws -> Int64    // bytes of resulting archive
}
```

- Construct `Archive(url: archive, accessMode: .create)`. Throws on
  filesystem errors.
- Walk each source: if directory, recurse with
  `FileManager.default.enumerator`; else add the single file. Add a
  directory entry first for any non-empty directory so the structure
  round-trips on extract.
- Each `addEntry` call passes `relativeTo: base`, so the resulting
  entry path is the source's path *relative to* `base`. The caller is
  expected to choose `base` as the common parent; we do **not** auto-
  compute a longest-common-prefix in MVP.
- Compression: `.none → .none`, `.default → .deflate`,
  `.best → .deflate`. (ZIPFoundation 0.9.x has no DEFLATE level knob.)
- Progress: ZIPFoundation's `Progress` is observed via KVO; we sample
  every 64 KB and post a `.transferring` `Stevedore Progress`.
- Returns archive file size on disk.
- Tar creation is **out of scope**, documented in handoff.

### 5.10 `ArchiveProvider.swift`

```swift
public actor ArchiveProvider: FileSystemProvider {
    public nonisolated let scheme: ConnectionScheme

    public init(
        archiveURL: URL,
        scheme: ConnectionScheme = .local
    ) async throws

    public func attributes(at path: FilePath) async throws -> FileAttributes
    public nonisolated func enumerate(
        at path: FilePath,
        options: EnumerationOptions
    ) -> AsyncThrowingStream<FileItem, any Error>
    public func execute(
        _ operation: OperationDescriptor,
        progress: (any OperationProgressReporting)?
    ) async throws -> OperationResult
    public nonisolated func watch(_ path: FilePath) -> AsyncStream<FilePathChange>
}
```

State (actor-isolated):
- `archiveURL: URL`
- `format: ArchiveFormat`
- `backend: any ArchiveBackend`
- Cached `[ArchiveEntry]` entry list (lazily initialized on first
  call). Key insight: we list entries once per provider lifetime; the
  archive contents are immutable for read-only mounts.
- Synthetic-root marker so `attributes(at: .root(scheme))` returns a
  directory item even when the archive's listing has no top-level
  directory entry.

`init`:
- Validate the URL exists and is a regular file
  (`try FileManager.default.attributesOfItem(atPath:)`). Throw
  `StevedoreError.fileSystem(.notFound(...))` or `.notAFile`.
- Detect format via `ArchiveDetector.detect(at:)`. Throw
  `.archive(.unsupportedFormat)` if `nil`.
- Pick backend.

`enumerate(at:options:)`:
- Builds an `AsyncThrowingStream` whose closure runs
  `Task { await self.snapshot(matching: path, options: options) }`.
- `snapshot` loads (and caches) the entry list, then filters entries
  whose `pathComponents` start with `path.components` and whose depth
  matches the recursion option (same logic as
  `InMemoryFileSystemProvider.snapshotChildren`).
- Hidden-file filter: an entry is hidden iff its last component starts
  with `.`.
- Ordered by `posixString` for determinism.

`attributes(at:)`:
- Root → synthetic directory attributes derived from the archive file's
  on-disk attributes.
- Match cached entry by `pathComponents`. Throw `.notFound` otherwise.

`execute(_:progress:)`:
- `.extract`:
  - Source = the virtual entry path inside the archive (or the archive
    root, meaning "extract everything").
  - Destination = the operation's `destination`, expected to have
    `scheme == .local`. Validate; throw `.invalidArgument` if not local.
  - For "extract everything" delegate to `ArchiveExtractor`.
  - For "extract one entry" use `ZipBackend.extractEntry` (zip only;
    for tar, fall back to staged extract+move-only-the-requested
    entries).
- All other operations (`.copy`, `.move`, `.delete`, `.mkdir`,
  `.rename`, `.symlink`, `.archive(...)`, `.trash`) → throw
  `StevedoreError.unsupported("ArchiveProvider is read-only in MVP")`.
  Documented in handoff.

`watch`:
- Returns an `AsyncStream` whose continuation immediately calls
  `finish()`; archives don't change while mounted in the MVP.

`scheme`:
- `nonisolated let` set in `init` from the parameter (default `.local`).

### 5.11 Sendable / concurrency posture

- `ArchiveProvider` is an actor — exclusive access to mutable cache.
- All backends are stateless `struct`s with `Sendable` fields.
- ZIPFoundation's `Archive` is a class; we only construct it inside the
  detached task that performs the I/O and never escape the reference.
  No `@unchecked Sendable` annotations are added — the unsafe references
  are isolated to a single task.
- `Process` is non-`Sendable`; we encapsulate it inside an actor so the
  reference never crosses isolation boundaries.
- `ArchiveExtractor` and `ArchiveCreator` are `Sendable struct`s
  (immutable stored values).
- `progress` callbacks are `await`ed; never invoked synchronously while
  holding any actor.

### 5.12 Test fixtures (programmatic generation)

`ArchiveTestSupport.swift` exposes:
- `enum Fixtures` namespace with:
  - `static func zipFixture(at root: URL) async throws -> URL` —
    creates a small dir tree (`a.txt`, `dir/b.txt`, `dir/c.bin`) under
    `root`, then uses `ZIPFoundation.Archive(accessMode: .create)` to
    package it into `root.appendingPathComponent("fixture.zip")`. No
    dependency on our own `ArchiveCreator` — keeps the round-trip test
    honest.
  - `static func tarFixture(format: ArchiveFormat, at root: URL) async throws -> URL` —
    creates the same source tree, then runs `/usr/bin/tar` with the
    matching flags (`-cf`, `-czf`, `-cjf`).
  - `static func maliciousZipFixture(at root: URL) async throws -> URL` —
    uses ZIPFoundation directly to add an entry whose `relativePath`
    is `../escape.txt`; then a second variant with `/abs/path`.
  - `static func maliciousTarFixture(at root: URL) async throws -> URL` —
    hand-rolls 512-byte tar headers with `name = "../escape.txt"` and
    a tiny body; appends the trailing two zero-blocks. Pure Foundation
    (`Data`, `withUnsafeBytes`) — no `Process` dependency. Keeps the
    fixture deterministic and `tar`-creator-independent.
- `RecordingProgressReporter` is an actor implementing
  `OperationProgressReporting`; `await report(_:)` appends to an
  `[Progress]` array. Tests inspect the array after the operation.

All fixtures are written into a per-test temp dir created via
`FileManager.default.url(for: .itemReplacementDirectory, ...)`, removed
in `tearDown`. Each fixture is <10 KB.

### 5.13 Cancellation-mid-extract test plan

Pseudocode (in `ArchiveExtractorTests.swift`):

```swift
let archive = try await Fixtures.zipFixture(at: rootURL)  // 30+ entries
let target = rootURL.appendingPathComponent("out", isDirectory: true)
try FileManager.default.createDirectory(at: target, withIntermediateDirectories: true)

let progress = RecordingProgressReporter()
let extractor = ArchiveExtractor(progress: progress, conflictPolicy: .overwrite)

let task = Task {
    try await extractor.extract(archive: archive, to: target)
}
// give the loop time to enter staging
try await Task.sleep(for: .milliseconds(50))
task.cancel()

do {
    _ = try await task.value
    XCTFail("expected cancellation")
} catch let StevedoreError.cancelled {
    // expected
}

// post-condition: target dir contains no staging artifacts.
let kids = try FileManager.default.contentsOfDirectory(atPath: target.path)
XCTAssertFalse(kids.contains(where: { $0.hasPrefix(".stevedore-extract-") }))
// And no half-written file: every present file equals the original byte for byte.
for kid in kids {
    let copy = target.appendingPathComponent(kid)
    let original = sourceTreeRoot.appendingPathComponent(kid)
    XCTAssertEqual(try Data(contentsOf: copy), try Data(contentsOf: original))
}
```

The 50 ms sleep is an empirical compromise — long enough for the
extractor to begin staging, short enough not to flake. If flake risk
materializes, fall back to a custom backend that suspends after each
entry on a semaphore the test owns; the test then signals the semaphore
once, cancels, and signals again. Plan A is the simpler default.

## 6. Risks & mitigations

| Risk | Likelihood | Mitigation |
|------|-----------|-----------|
| ZIPFoundation 0.9.20 has API surface drift relative to my recollection (e.g., `Entry.fileAttributes` shape, `.symlink` case spelling, `Archive` being throwing-init) | medium | First implementation pass: make the smallest working zip listing, build, observe any compiler errors, adjust. The implementation session will rely on the actual headers. The plan keeps backend boundaries narrow so a single-file refactor can absorb naming differences. |
| `/usr/bin/tar` differs across macOS versions (BSD tar with various flags) | low | Use only POSIX-portable flags (`-tf`, `-xvf`, `-C`). Verify with `tar --version` on the build agent if a quirk appears. Tests run on the same darwin binary so behavior is consistent across local + CI. |
| BSD `tar` may auto-strip `..` components on extract, masking our validation logic | medium | We validate via `listEntries` *before* invoking extract. The test relies on `listEntries` rejecting the malicious path; it does **not** rely on `tar` itself rejecting. The hand-rolled malicious tar guarantees the bad path is present in the listing. |
| Hand-rolled tar header checksum miscomputed → fixture not parseable by `tar` | medium | Tar header checksum is the unsigned-byte sum of the 512-byte header with the 8 checksum bytes treated as spaces. `ArchiveTestSupport` includes a `tarHeader(name:size:)` helper with a unit-test of its own (assert `/usr/bin/tar -tf` lists the malicious entry). |
| `Process` Sendable warnings under Swift 6 strict concurrency | high | Encapsulate inside an actor; never store the Process across `await`. Pipes' file handles are accessed only on the actor. |
| KVO-based `Progress` observation in ZIPFoundation runs on an unspecified thread | medium | We bridge into our reporter via `await reporter.report(...)` from a `Task { @MainActor in ... }`-free context; the reporter is `Sendable`. If KVO callbacks turn out to fire on a per-archive run-loop thread, we sample the progress object from a polling task on the extract Task instead of relying on KVO. |
| 50 ms cancellation timing is flaky on slow CI | low | Generate a fixture with 50+ entries (still <10 KB compressed) so there's plenty of work. If still flaky in execution, swap to the semaphore-controlled backend described in §5.13. |
| Conflict policies `.ask` / `.rename` are not fully supported | accepted | Documented in handoff. MVP falls back to `.overwrite` for these cases. |
| Extract-one-entry from `tar` cannot easily be done without re-extracting a subset; for MVP it's a niche path | low | `ArchiveProvider.execute(.extract)` for a single tar entry uses `tar -xvf <archive> -C <staging> <entryName>`, then moves only that file. |
| Archive password support (encrypted zip) is excluded | accepted | Surface `ArchiveError.passwordRequired` if ZIPFoundation reports an encrypted entry; document in handoff. |
| Symbolic link entries inside archives could point outside the target dir | medium | At extract time, when the entry is a symlink, validate that the link target does not begin with `/` and does not contain `..`. Reject as `.corruptedEntry` if it does. Tests cover this via the malicious zip variant. |
| `Tests/Fixtures/Archive/` deviation may surprise downstream sessions | low | Recorded explicitly in the handoff; the test support file is named `ArchiveTestSupport.swift` so future sessions can adopt the same generator pattern. |
