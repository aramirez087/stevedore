## Issues to Fix Before Quality Gates

### Issue #1 — `@discardableResult` missing on `TempDirectoryFixture.makeFile`

`TempDirectoryFixture.makeFile` returns `URL` with no `@discardableResult`. Multiple
test functions call it as a side-effect without capturing the result:

```swift
// LocalDirectoryEnumeratorTests.swift — lines 24-25, 32-33, 42-43, 50, etc.
try self.fixture.makeFile(name: "a.txt")   // ← "Result of call is unused" warning
```

With `-Xswiftc -warnings-as-errors` this becomes a compile error.

**Fix:** Add `@discardableResult` to `TempDirectoryFixture.makeFile`:

```swift
@discardableResult
func makeFile(name: String, content: String = "x") throws -> URL {
```

`makeSubdirectory` is always captured at call sites (`let sub = try fixture.makeSubdirectory(name:)`)
so it does not need the annotation.

**File:** `Tests/FileSystemTests/LocalTests/Support/TempDirectoryFixture.swift`

---

### Issue #2 — `Unmanaged.passRetained` in `VolumeDiscovery.startIfNeeded` is never balanced

`startIfNeeded()` calls:
```swift
let boxedSelf = Unmanaged.passRetained(DACallbackBox(actor: self))
```
…and passes the raw pointer as the DA callback context. The DA callbacks use
`takeUnretainedValue()` (non-consuming), and no explicit `.release()` call exists.
The comment claims "Released inside `diskReleasedCallback`" but that callback is
never defined. The `DACallbackBox` leaks permanently.

**Fix:** Store a strong ARC reference to the box on the actor and use
`passUnretained` for the raw context pointer — the actor's stored property keeps
the box alive, so ARC manages the lifetime without manual retain/release:

```swift
// Add stored property to VolumeDiscovery:
private var daCallbackBox: DACallbackBox?

// In startIfNeeded(), replace:
//   let boxedSelf = Unmanaged.passRetained(DACallbackBox(actor: self))
// with:
let box = DACallbackBox(actor: self)
self.daCallbackBox = box                       // strong ref; actor is the owner
let boxedSelf = Unmanaged.passUnretained(box)  // borrow; does NOT retain
```

When `VolumeDiscovery` deinits, `daCallbackBox` and `daSession` are released
together. DA stops calling our callbacks when the session is released, so the
borrowed pointer is never used after the box is freed.

**File:** `Sources/FileSystem/Local/VolumeDiscovery.swift`

## Key Design Decisions (for handoff doc)

### Concurrency boundaries

- `LocalFileSystemProvider` is an `actor`. `attributes` and `execute` are actor-isolated.
- `enumerate` and `watch` are `nonisolated` — callers get the stream handle synchronously
  without awaiting actor isolation. Actual I/O runs in `Task.detached(priority: .utility)`.
- **Actor reentrancy:** `execute` suspends at `Task.detached` boundaries. Concurrent
  `execute` calls are interleaved at those suspension points; callers must not assume
  ordered serialisation across concurrent invocations.
- **Cancellation:** `enumerate` checks `Task.isCancelled` between yields; `FSEventsWatcher`
  calls `FSEventStreamStop/Invalidate/Release` in `continuation.onTermination`; the DA
  session for volume events is torn down when `VolumeDiscovery` deinits.

### `LocalFileOperations` — fresh `FileManager()` per call

`FileManager` is not `Sendable`. Creating a new instance inside each `Task.detached`
closure (rather than sharing a singleton or storing one on the actor) is the Apple-
recommended pattern for thread-safe use of `FileManager`.

### Conflict detection as a separate preflight API

`Core.FileSystemProvider.execute` returns `OperationResult` — no slot for conflict
metadata. The session-spec requirement ("returns a typed `ConflictDescriptor` rather than
throwing") is satisfied via `detectConflicts(for:) async -> [ConflictDescriptor]`, a
non-protocol method on `LocalFileSystemProvider`. The operations engine (Session 10) calls
it before presenting a conflict dialog.

### FSEvents C-callback bridge

`FSEventStreamContext.info` carries a `Unmanaged<StreamBox>` retained pointer.
The context's `release` closure calls `Unmanaged.release()` to balance `passRetained`.
`StreamRef` is a heap-boxed `FSEventStreamRef?` that is captured `@Sendable` inside
`onTermination` without violating strict concurrency.

### VolumeDiscovery — passUnretained + stored strong reference (post-fix)

After Issue #2 fix, the actor owns the `DACallbackBox` via a stored property. DA
callbacks borrow the raw pointer via `passUnretained` — safe because the box lives
at least as long as the actor (and therefore at least as long as the DA session).

### `.archive` / `.extract` delegated

`LocalFileOperations.dispatch` throws `StevedoreError.unsupported` for `.archive` and
`.extract`. These are handled by `FileSystemArchive` in Session 05.

### macOS quirks to document in handoff

- APFS supports copy-on-write clones; `FileManager.copyItem` uses them automatically.
- Case-insensitive HFS+ rename (same path, different case) is a move, not a no-op.
- `.DS_Store` is hidden by macOS at the `FileManager` level; skipped when
  `includesHiddenFiles: false`.
- `trashItem(at:resultingItemURL:)` returns the trashed URL — not used by the current
  implementation but available for future "reveal in Trash" features.

| `FSEventsWatcherTests.testWatcherDeallocatesAfterStreamEnds` flakey | Test sleeps 200ms after break to let `onTermination` run. Actors hold a brief executor reference; 200ms should be sufficient. If it flakes, increase to 500ms — the test is correct. |
