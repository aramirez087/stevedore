## Key Design Decisions

### Actor + nonisolated streams
`LocalFileSystemProvider` is a `public actor`. `enumerate` and `watch` are `nonisolated`
so callers receive stream handles synchronously without awaiting actor isolation. `attributes`
and `execute` are actor-isolated but immediately hop to `Task.detached(priority: .utility)`
to avoid pinning the actor executor during blocking `FileManager` calls.

### Actor reentrancy
`execute` and `attributes` suspend at `Task.detached` boundaries. Two concurrent `execute`
calls on the same provider are not serialized by the actor — callers must not assume ordering
across concurrent invocations. This is documented in both the source and the handoff.

### `FileManager` — fresh instance per call
`FileManager` is not `Sendable`. Each operation creates a fresh `FileManager()` inside a
`Task.detached` closure. This follows Apple's threading guidance and avoids `@unchecked Sendable`.

### VolumeDiscovery memory management (already applied)
`startIfNeeded()` stores the `DACallbackBox` as `private var daCallbackBox: DACallbackBox?`
on the actor. DA C callbacks borrow the raw pointer via `Unmanaged.passUnretained`; ARC on
the actor's stored property keeps the box alive. No manual `retain`/`release` needed.

### FSEvents C-callback bridge
`FSEventStreamContext.info` carries a `Unmanaged<StreamBox>` retained pointer; the context
`release` closure balances with `Unmanaged.release()`. `FSEventStreamRef` is boxed in a
heap-allocated `StreamRef` class (`@unchecked Sendable`) so it can be captured in the
`@Sendable onTermination` closure.

### Conflict detection as a separate preflight API
`Core.FileSystemProvider.execute` returns `OperationResult` with no slot for conflict
metadata. The spec requirement ("returns a typed `ConflictDescriptor` rather than throwing")
is satisfied by `detectConflicts(for:) async -> [ConflictDescriptor]` on
`LocalFileSystemProvider` directly. The operations engine (Session 10) calls it before
showing a conflict dialog.

### `.archive` / `.extract` delegated
`LocalFileOperations.dispatch` throws `StevedoreError.unsupported` for `.archive` and
`.extract`. Covered by `FileSystemArchive` (Session 05). Tested by
`testExecuteArchiveThrowsUnsupported` in `LocalFileSystemProviderTests`.

## Potential Failure Causes and Targeted Fixes

These are the most plausible reasons a gate could fail given the current code. Read the gate
output first — do not apply a fix without confirming the error matches.

### Gate 1 / Gate 5 — Compile failure

- **Cause A:** A new macOS SDK version changed an API signature (e.g., `FileManager.trashItem`
  return type, `DASession` linkage). **Fix:** Adjust the call site to the new API; do not
  change the Operator-rules stack settings.
- **Cause B:** Swift 6 stricter `Sendable` checking in a new toolchain. **Fix:** Narrow the
  `@unchecked Sendable` scope or add an explicit `nonisolated` annotation where needed. Never
  remove `@unchecked Sendable` on `StreamBox` or `StreamRef` without understanding the
  FSEvents callback threading model.

### Gate 2 — Test failure

- **Cause A:** `testEncodeDecodeRoundTrip` fails because `URL.resolvingSymlinksInPath()` on
  the temp dir resolves `/private/var/folders/…` differently across macOS versions.
  **Fix:** Compare `standardizedFileURL.path` instead of `resolvingSymlinksInPath().path`.
- **Cause B:** `testCurrentVolumesReturnsBootVolume` fails because `url.path == "/"` does not
  match; the boot volume URL may be `/Volumes/…` on some configurations.
  **Fix:** Relax assertion to check `url.path == "/" || url.path.hasPrefix("/Volumes/")`.
- **Cause C:** `testWatcherEmitsEventOnFileCreation` fails because `Task.sleep` duration
  before file creation was insufficient for the stream to start.
  **Fix:** Increase initial sleep from 200ms to 500ms.

### Gate 4 — SwiftLint violation

- **Cause:** A new SwiftLint version adds a rule not previously enabled.
  **Fix:** Add the narrowest inline `// swiftlint:disable:next <rule>` directive to the
  offending line. Do not weaken `.swiftlint.yml`.
