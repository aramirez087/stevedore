## 2. Key design decisions and rationale

### 2.1 Provider is an `actor`, but stream factories are `nonisolated`

The session prompt mandates `actor`-based isolation. We follow the same
pattern the in-memory fake established
(`Sources/Core/Testing/InMemoryFileSystemProvider.swift`):

- `enumerate(at:options:)` and `watch(_:)` are `nonisolated` so callers
  receive the stream handle synchronously and don't have to await actor
  isolation just to begin iteration.
- The actor's serial state is limited to (a) the watcher registry and
  (b) bookmark access bookkeeping. All blocking I/O happens off-actor in
  `Task.detached` blocks or via `withCheckedThrowingContinuation` over a
  dedicated `DispatchQueue` (used by `FSEvents` and `DiskArbitration`).

### 2.2 Blocking `FileManager` I/O hops to a detached executor

`FileManager.default.copyItem(at:to:)`, `removeItem`, `trashItem`, etc. are
synchronous and may block on disk for long periods. Calling them directly
from an actor method pins the actor's executor and breaks the cancellation
story. The provider funnels every blocking call through

```swift
try await Task.detached(priority: .utility) { try work() }.value
```

so cancellation propagates naturally and the actor remains responsive.

### 2.3 Conflict detection via a separate preflight API

`Core.FileSystemProvider` is fixed and `OperationResult` cannot carry
conflict metadata. The session prompt requires "Conflict detection returns
a typed `ConflictDescriptor` rather than throwing." We satisfy that with
a new public method on `LocalFileSystemProvider`:

```swift
public func detectConflicts(for op: OperationDescriptor) async -> [ConflictDescriptor]
```

`execute(_:progress:)` honors the descriptor's `ConflictPolicy`:
- `.skip` → conflicting items are skipped, returning
  `OperationResult(status: .partiallyFailed)` if any were skipped.
- `.overwrite` → existing destinations are removed (or replaced) before the
  copy/move proceeds.
- `.rename` → destination receives a unique " 2", " 3"… suffix per Finder
  conventions.
- `.ask` → returns `OperationResult(status: .skipped)` when conflicts
  exist; the caller is expected to have queried `detectConflicts(for:)`
  first.

### 2.4 `URLResourceValues` keys

The mapper requests this set of keys per URL (passed to
`FileManager.enumerator(at:includingPropertiesForKeys:options:)` and to
`url.resourceValues(forKeys:)`):

```
.nameKey, .isDirectoryKey, .isRegularFileKey, .isSymbolicLinkKey,
.fileResourceTypeKey, .fileSizeKey, .totalFileSizeKey,
.contentModificationDateKey, .creationDateKey,
.fileSecurityKey, .isHiddenKey, .isPackageKey
```

`.fileSecurityKey` is converted to `PosixPermissions` by extracting the
mode bits from the underlying `NSFileSecurity` /
`CFFileSecurityGetMode(_:_:)` call. If `.fileSecurityKey` is not available
on a given URL (rare on macOS APFS), `permissions` falls back to `nil` so
the missing-but-not-failed contract on `FileAttributes` holds.

### 2.5 `FilePath` ↔ `URL` bridging

`FilePath` for `.local` schemes maps 1:1 to a POSIX file URL:

- `FilePath → URL`: `URL(fileURLWithPath: filePath.posixString, isDirectory: ...)`
  We don't try to resolve `..`/`.`; `FilePath.normalize` already collapses
  these, and the components are POSIX-safe.
- `URL → FilePath`: split `url.path` on `/`, omit empty subsequences, build
  `FilePath(scheme: .local, components: ...)`.

`scheme != .local` paths fed to the local provider raise
`StevedoreError.invalidArgument("LocalFileSystemProvider received non-local FilePath: \(scheme)")`.

### 2.6 `FSEventsWatcher` lifetime

Each call to `events(for:recursive:)` creates a fresh `FSEventStreamRef`.
We could pool streams keyed by path, but that adds reentrancy hazards we
don't need yet. Stream teardown happens in `continuation.onTermination`:

```swift
continuation.onTermination = { _ in
    FSEventStreamStop(streamRef)
    FSEventStreamInvalidate(streamRef)
    FSEventStreamRelease(streamRef)
}
```

The C-callback uses `Unmanaged.passUnretained(self).toOpaque()` for
`FSEventStreamContext.info`; we balance with a `passRetained` /
`takeRetainedValue` pair to keep the actor alive for the duration of the
stream and release it on termination.

### 2.7 `DiskArbitration` for ejectability + mount events

We use `DASessionCreate`, `DASessionSetDispatchQueue`, and
`DARegisterDiskAppearedCallback` / `DARegisterDiskDisappearedCallback`.
The session is held by the `VolumeDiscovery` actor; we do not expose the
session across the API boundary. `currentVolumes()` enumerates via
`FileManager.default.mountedVolumeURLs(includingResourceValuesForKeys:options:)`
with `.skipHiddenVolumes` and reads `.volumeIsEjectableKey`,
`.volumeIsRemovableKey`, `.volumeIsLocalKey`, `.volumeNameKey`.

### 2.8 Security-scoped bookmarks

We encode with `URL.bookmarkData(options: [.withSecurityScope, .securityScopeAllowOnlyReadAccess])`
when read-only access is needed; default flavor is read-write. The
`withAccess(to:)` helper:

```swift
let didStart = url.startAccessingSecurityScopedResource()
defer { if didStart { url.stopAccessingSecurityScopedResource() } }
return try await body(url)
```

This balances start/stop even on throw or early return. The actor tracks
nested calls via a simple counter so re-entrant `withAccess` on the same
URL doesn't drop access prematurely. (This counter is only exercised when
the same URL is accessed concurrently from different tasks — not the
common path, but cheap insurance.)

### 2.9 Deletion of `Placeholder.swift` + sentinel preservation

The existing smoke test at `Tests/FileSystemTests/Local/FileSystemLocalSmokeTests.swift`
asserts `FileSystemLocalModule.moduleName == "FileSystemLocal"`. That file


- `CoreServices.FSEvents`
- `DiskArbitration`

No SPM dependency edits.

## 3. Risks and mitigations

| Risk | Mitigation |
|---|---|
| **`NSFileManager.trashItem` writes to user's Trash during tests.** | Tests stub via a wrapper protocol (`Trasher`) injected into `LocalFileOperations`; the default impl forwards to `FileManager`, the test impl just records calls + removes the source. The `Trasher` indirection is internal-only. |
| **`FSEventStreamCreate` callbacks run on a dispatch queue, not an actor.** | The watcher uses `FSEventStreamSetDispatchQueue` with a dedicated serial queue. The C callback hops onto an `AsyncStream.Continuation.yield(_:)` (continuations are `Sendable`), so we never await across the boundary. |
| **`DiskArbitration` session can deadlock if the dispatch queue blocks.** | Use a dedicated serial queue for the DA session, never call back into the `VolumeDiscovery` actor synchronously from DA callbacks — emit straight to a continuation. |
| **Permission-denied tests can leave a `chmod 0` directory that defeats `tearDown`.** | `TempDirectoryFixture.tearDown()` always `chmod`s the tree back to `0o755` before recursive remove. Test bodies use `addTeardownBlock` to restore mode if they exit early. |
| **`FSEventStream` retain cycle leaks the watcher.** | `FSEventStreamContext.info` uses `Unmanaged.passRetained(self).toOpaque()`. The `release` callback in the context performs `Unmanaged.fromOpaque(_:).takeRetainedValue()`. Leak test asserts a weak reference is nil after the iterator deinitializes. |
| **`URL.bookmarkData(options:.withSecurityScope, …)` requires the app-sandbox entitlement.** | In the unit test we exercise the no-security-scope path (plain bookmark) plus a feature-flag for security-scope encoding behind `#if canImport(...)`. The full sandboxed path is exercised at integration time (out of scope for Session 03). The API surface itself is implemented and unit-tested for round-trip + start/stop balance. |
| **`Conformance.swift` becoming a kitchen-sink that's hard to factor later.** | We structure it as one `XCTestCase` whose `func makeProvider() async throws -> any FileSystemProvider` is overridable. Subclasses (one per scheme) reuse the body verbatim. Session 03 ships the local subclass; remote/archive sessions can adopt the base in their own targets later. |
| **Swift 6 strict-concurrency: closures captured by `FSEventStream` callbacks must be `@Sendable`.** | We use only `@Sendable` closures and pass the `AsyncStream.Continuation` directly (it is `Sendable`). No captured `self` of a non-`Sendable` type. |
| **Existing smoke test breaking.** | Confirmed `Tests/FileSystemTests/Local/FileSystemLocalSmokeTests.swift` is read-only for this session. Sentinel preserved via `FileSystemLocalModule.swift`. Verified by running smoke test before deleting the placeholder during Step 2 (see §5). |
| **SwiftLint `file_length` (>600 warn / >1000 error).** | Each new file scopes one major type with helpers in extensions. `LocalFileSystemProvider.swift` ≤ ~250 lines; `LocalFileOperations.swift` ≤ ~400 lines; `FSEventsWatcher.swift` ≤ ~200 lines. |
| **SwiftLint `cyclomatic_complexity` on the operation dispatcher.** | The `execute(_:progress:)` switch dispatches one case per `OperationKind`. We split each case body into a `private func performXxx(...)`. |
| **SwiftLint `force_unwrapping` rule.** | Only optionals are URL.resourceValues fetches; we always use guard-let / nil-coalesce. No force-unwraps in production code. Tests are exempted only in `XCTUnwrap`-style assertions. |
