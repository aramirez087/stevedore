## Key Design Decisions (already in place)

### 1 — LogCategory extended, not re-declared
`Core.LogCategory` already declares all 14 cases (app, fileSystem, remote, archive,
credentials, settings, operations, sync, rename, preview, git, uninstaller, ui, unknown).
`LogCategory.swift` in ServicesLogging adds only a module-internal extension with
`var osLogger: Logger`. No shadow type is introduced, so the `AppLogger` protocol contract
is never broken.

### 2 — `nonisolated(unsafe)` for regex constants
Swift 6 strict concurrency requires `static let` on `Sendable` types, but
`Regex<Output>` is not yet marked `Sendable` in Apple's SDK. The project forbids
`@unchecked Sendable` without justification. `nonisolated(unsafe)` is the correct Swift 6
suppression for a provably safe (write-once, never-mutated) global regex constant.
Each property in `Redaction.swift` carries a justification comment.

### 3 — LogLevel mapping (7 → 6 os.Logger methods)
Core defines seven levels: trace, debug, info, notice, warning, error, critical.
`os.Logger` exposes six: debug, info, notice, warning, error, fault.
`OSLogger` collapses trace → debug and critical → fault.

### 4 — `ServicesLoggingModule` sentinel in OSLogger.swift
Deleting `Placeholder.swift` would break `Tests/ServicesTests/Logging/ServicesLoggingSmokeTests.swift`,
which is outside this session's `touches:` scope. The sentinel is re-declared in
`OSLogger.swift` under a `// MARK: - Module marker` comment. This is an explicit,
documented exception to the one-public-type-per-file convention.

### 5 — `swift-log` dependency declared but unused at runtime
`Package.swift` (frozen) includes `.product(name: "Logging", package: "swift-log")` as
an extraDependency for `ServicesLogging`. The product is not imported in any source file.
All runtime logging goes through `os.Logger` directly. The dependency stays for a future
structured-logging backend session.

### 6 — `privacy: .auto` for all os.Logger writes
Messages are scrubbed by `Redaction.redact` before reaching `os.Logger`, so `.auto`
(developer-visible on development devices) is appropriate. No `.private` suppression
is needed at the log-site level.

### 7 — Ring buffer write cursor vs. resizing
`LogRingBuffer` pre-allocates `storage.reserveCapacity(capacity)` and uses a rolling
`writeIndex` cursor once full. The alternative (removing the oldest element) would be O(n)
per push and create unnecessary ARC traffic. The current approach is O(1) push, O(n)
snapshot — appropriate for the diagnostics use case where snapshots are infrequent.

## Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| `Regex<Output>` becomes `Sendable` in a future SDK — `nonisolated(unsafe)` annotations become obsolete but harmless | Remove annotations when the SDK change ships; tracked in handoff open issues |
| Burst test (`testBurstWriteRespectsBounds`) relies on a 1-second wall-clock limit — may flake on CI under heavy load | Limit is generous (10k actor pushes in <1s); if it flakes, raise to 5s or gate with `#if !CI` |
| `OSLogger.ringBuffer` is `private` — Diagnostics panel cannot call `snapshot(minLevel:)` directly | `OSLogger.events` returns the unfiltered snapshot; add `func events(minLevel:) async -> [LogEvent]` in a future session (tracked in handoff) |
| `LogCategory.osLogger` is module-internal — can only be called within ServicesLogging | Intentional: prevents call sites from constructing ad-hoc `os.Logger` instances; routing through `OSLogger` ensures redaction always applies |

## Handoff Summary

Session 09 is complete. The `ServicesLogging` module provides the production `AppLogger`
implementation that all downstream sessions (10–28) must use. Key entry points:

- **`OSLogger`** — inject as `any AppLogger`; construct once at app startup and pass via
  dependency injection
- **`LogCategory`** — import `Core`; always pass a typed case, never a raw string
- **`Redaction.redact(_:)`** — call explicitly when building log messages outside of
  `OSLogger` that may contain user-controlled input
- **`SignpostHelper.withSignpost(_:_:)`** — wrap slow async operations (large copies,
  directory listings, FTP transfers) for Instruments tracing
- **`LogRingBuffer`** — the Diagnostics panel should read `await osLogger.events`
