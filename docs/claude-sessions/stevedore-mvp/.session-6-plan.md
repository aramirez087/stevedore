## Spec deviation: awsKeyCredential

The session brief listed `Sources/Services/Credentials/Credential.swift` with a
fourth case `awsKeyCredential`. The implementation chose NOT to add this:

**Reason (from handoff Decisions section):**
> `CredentialMaterial` not duplicated. The awsKeyCredential variant from the
> brief can be represented as `oauthToken` with a tagged service name — no
> type-system change required.

**Current S3 auth path** (`Sources/FileSystem/Remote/Common/RemoteAuth.swift`):
```swift
private static func s3Strategy(...) -> RemoteAuthStrategy {
    guard let cred = credential else { return .anonymous }
    let keyID = cred.username ?? ""
    if case .password(let secret) = cred.material {
        return .awsSig4(accessKeyID: keyID, secretAccessKey: secret, region: region)
    }
    return .anonymous
}
```
AWS credentials are stored as `Credential(username: accessKeyID, material: .password(secretAccessKey))`.
This is a type-system pragmatism: the credential stores the secret correctly; only
the type name is imprecise. The `RemoteAuthStrategy.awsSig4` case (in FileSystemRemote) is
properly typed.

**Risk:** If a future session adds `awsCredential(accessKeyID:secretAccessKey:)` to
`CredentialMaterial`, `RemoteAuth.s3Strategy` must be updated to match. Document
in handoff if unchanged.

**Decision for this session:** Accept the existing approach as-is. No `awsKeyCredential`
case will be added unless a build failure or lint error forces a change.

## Key design decisions (already made, recorded for context)

1. **`Credential`/`CredentialMaterial` stay in `Core`.**
   Session 1 placed these types in `Sources/Core/Types/Credential.swift`. The
   Services module uses them via `import Core`. No duplicate `Credential.swift`
   exists in `Sources/Services/Credentials/`.

2. **`redactedDescription` is an extension method, not `CustomStringConvertible`.**
   Retroactive protocol conformances on types from another module produce compiler
   warnings under `-warnings-as-errors`. Plain extension properties avoid this.

3. **`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` with no access group.**
   Device-local, survives sleep/wake, never iCloud-synced. Cross-process sharing
   is a future concern (add `accessGroup:` param to `KeychainCredentialStore.init`).

4. **`SSHKeyImporter` is a parser, not a decryptor.**
   Decrypting AES-256-CTR blobs requires Citadel. `ServicesCredentials` does not
   depend on Citadel (`Package.swift` is frozen). Importer stores PEM + passphrase
   together; Citadel decrypts at connect time.

5. **`PrivateModeCredentialStore` (not `InMemoryCredentialStore`) naming.**
   Core's testing fake already uses `InMemoryCredentialStore`. Naming the
   services-level variant `PrivateModeCredentialStore` clarifies purpose and
   prevents type-name collision.
