## Key design decisions

1. **`@Entry` macro for `EnvironmentValues` extension.**
   SwiftFormat's `environmentEntry` rule rewrites the classic `struct ThemeKey: EnvironmentKey`
   pattern to `@Entry var theme: Theme` automatically. Write it with `@Entry` from the start
   to avoid a SwiftFormat diff.

2. **`textOnAccent` as the 10th `ColorTokens` field.**
   `SDButton` needs white foreground on `.primary` (accent background) and `.destructive` (danger
   background). A raw `Color.white` literal would violate the exit criterion "no public API exposes
   raw Color literals." Adding `textOnAccent: Color(nsColor: .white)` keeps the button's
   foreground always sourced from a token.

3. **Dictionary for `IconRegistry.symbolName(forExtension:)`.**
   A switch statement with 30+ extension cases exceeds SwiftLint's `cyclomatic_complexity` limit
   (default 10, strict mode). A `private static let extensionSymbols: [String: String]` dictionary
   reduces cyclomatic complexity to 1 (one branch: lookup vs. fallback).

4. **`SDListRow` uses `Color.clear` for unselected background.**
   `Color.clear` is a transparency utility, not a hard-coded design color; SwiftLint does not flag
   it. This is an intentional exception documented in the handoff.

5. **`NSHostingView` smoke tests, no ViewInspector.**
   `ViewInspector` is not in `Package.swift` (frozen). `NSHostingView(rootView: view)` is non-nil
   iff the view body compiles and initialises without a crash. All component tests are `@MainActor`
   because `NSHostingView` requires the main thread.

6. **Preview files ship in the production binary.**
   `Package.swift` is frozen and has no separate preview target. Preview code is small; binary
   size is not a concern at MVP stage. A `canImport(DeveloperToolsSupport)` guard or
   `#if DEBUG` block would be the mitigation path if this becomes a problem in later sessions.

7. **Supporting enums are top-level files.**
   Consistent with Session 01's pattern: `SDButtonStyle`, `SDLabelVariant`, `SDListRowContent`,
   `IconSize` each live in their own file to avoid the SwiftLint `nesting` rule violation.

8. **`@discardableResult` not needed on `View.theme(_:)`.**
   `some View` return is always consumed by the call chain — the `@discardableResult` attribute
   is not applicable here.

## Risks and mitigations

| Risk | Likelihood | Mitigation |
|------|-----------|-----------|
| SwiftLint `cyclomatic_complexity` violation in `IconRegistry` | High | Use dictionary, not switch; complexity stays at 1 |
| `@State` in `#Preview` generates a warning under `-warnings-as-errors` | Medium | Always use `@Previewable @State` for stateful previews |
| `EnvironmentValues.@Entry` not available on macOS 14 | Low | `@Entry` is a compile-time Swift macro with no runtime OS constraint; available in Xcode 16+/Swift 6 |
| Placeholder deletion breaks smoke tests | Low | Re-declare `DesignSystemModule.moduleName` in `DesignSystemModule.swift` immediately after deletion |
| `NSHostingView` tests fail if run off main actor | Medium | Annotate entire test class `@MainActor`; all NSHostingView calls are then guaranteed on main thread |
| SwiftFormat `extensionAccessControl` rewrite moves `public` to extension declaration | Low | Write `public extension View { func theme(...) }` rather than `extension View { public func theme(...) }` to avoid a format diff |
| `trailing_comma` conflicts between SwiftFormat and SwiftLint | None | Already resolved in Session 01: `.swiftlint.yml` has `mandatory_comma: true` |
