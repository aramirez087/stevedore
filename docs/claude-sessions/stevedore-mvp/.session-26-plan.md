# Session 26 Implementation Plan — Main Window Shell

## Context

Session 26 wires everything the user sees on launch: a dual-pane window with sidebar, draggable
splitter, per-pane toolbar+tabs+file-pane, a docked Transfers panel, and a DI root that
constructs all singletons once. Window state (split fraction, per-pane tabs, last sidebar
selection) persists across relaunches via WorkspacesRepository + UserDefaults.

**Critical gap**: Sessions 16 (UIPane/FilePane), 17 (UITabs/TabStrip), and 20 (UITransfers) are
not yet merged into this worktree — those modules only have `Placeholder.swift`. Session 26 must
create minimal stub views in each so the shell can compile and the exit criteria can be verified.
The stubs will be replaced by the real implementations when those sessions merge.

**`PaneSession.swift`** — `@MainActor @Observable final class PaneSession`
- Properties:
  - `currentPath: FilePath` (observed)
  - `tabs: [Tab]` (observed)
  - `activeTabID: Tab.ID?` (observed)
  - `@ObservationIgnored let provider: any FileSystemProvider`
  - `let toolbarViewModel: PaneToolbarViewModel`
  - `@ObservationIgnored weak var operationQueue: FileOperationQueue?`
    _(actors can't be `weak`; use `var operationQueue: FileOperationQueue?` — non-weak, non-retained beyond window close via AppEnvironment ownership)_
- `init(provider:initialPath:operationQueue:)`
  - Seeds `tabs = [Tab(path: initialPath)]`, `activeTabID = tabs[0].id`
  - Creates `toolbarViewModel = PaneToolbarViewModel(initialPath: initialPath)`
  - Wires `toolbarViewModel.onNavigate = { [weak self] path in self?.navigate(to: path) }`
  - Wires `toolbarViewModel.onRefresh = { [weak self] in self?.refresh() }`
  - Wires `toolbarViewModel.onNewFolder = { [weak self] in self?.addTab(at: self?.currentPath) }`
- `func navigate(to path: FilePath)` — updates `currentPath`, updates active tab's path in `tabs`
- `func addTab(at path: FilePath?)` — appends new `Tab` and sets it active
- `func closeTab(_ id: Tab.ID)` — removes from `tabs`; if active, activate adjacent tab
- `func refresh()` — no-op stub (FSEvents handles auto-refresh in real FilePane)
- `func handleDrop(sourcePaths: [FilePath], sourceProvider: any FileSystemProvider)` async
  - Constructs `OperationDescriptor(kind: .copy, sources: sourcePaths, destination: currentPath, conflictPolicy: .ask)`
  - Calls `await operationQueue?.enqueue(descriptor)` — this is where the pane-to-pane copy lands

**`WindowState.swift`** — persistence helpers:

## Design Decisions and Rationale

### 1. `@Observable` AppEnvironment over `@EnvironmentObject`
Swift 6 `@Observable` macro + `.environment(appEnv)` / `@Environment(AppEnvironment.self)` is
the idiomatic Swift 6 pattern. `ObservableObject` + `@EnvironmentObject` requires a `Combine`
import and has weaker concurrency guarantees. The `@Observable` macro works cleanly with `@MainActor`.

### 2. AppEnvironment in executable, not MainWindow library
Placing `AppEnvironment.swift` under `App/Stevedore/` keeps concrete production types (Keychain, OSLogger, etc.) out of the reusable `MainWindow` library. The library receives typed environment values; the executable wires them. This matches the session prompt's "Repository anchors".

### 3. `FileOperationQueue` passed via environment key (not `@EnvironmentObject`)
`FileOperationQueue` is an actor, not a class conforming to `ObservableObject`. SwiftUI `@Entry` environment keys accept `Sendable` values, and actors are `Sendable`. The key holds an optional to avoid forcing a default shared instance in every context (test vs. prod).

### 4. `WorkspacesRepository` for per-pane tab state; `Settings.splitRatio` for split fraction
`WorkspacesRepository` already stores `[Workspace]` with `WorkspacePane` (tabs + activeTabID) — perfect for tab persistence. Split fraction maps directly to the existing `Settings.splitRatio` UserDefaults key (default `0.5`). No new schema needed.

### 5. Pane-to-pane drop via `UTType.fileURL` drag
SwiftUI's `.onDrop(of: [.fileURL], …)` and `.draggable` accept file URLs and file-URL arrays. This is the simplest compliant mechanism for macOS 14. The source pane's `FilePane` stub delivers `[URL]`; the destination pane's `onDrop` converts URL → `FilePath` and calls `PaneSession.handleDrop`. Full NSFilePromiseProvider drag (for cross-app support) is a post-MVP concern.

### 6. Minimal stubs for UIPane / UITabs / UITransfers
Sessions 16, 17, 20 are not yet merged in this worktree. Creating stubs in-place (rather than waiting) lets Session 26 satisfy all exit criteria. The stubs export the same public type names the real implementations will use (`FilePane`, `TabStrip`, `TransfersPanel`), so Session 26 code will compile without modification once the real implementations land via git merge.

### 7. `VolumeDiscoveryAdaptor` in executable, not MainWindow
The adaptor references both `FileSystemLocal.VolumeDiscovery` and `UISidebar.SidebarVolume`. MainWindow already depends on UISidebar. Adding FileSystemLocal to MainWindow's dependencies would make a UI module depend on a FS implementation — a layering violation. Keeping the adaptor in the executable is clean.

### 8. Window close → save via `NSWindow.willCloseNotification`
SwiftUI `WindowGroup` has no `onClose` modifier before macOS 15. `NotificationCenter.default.publisher(for: NSWindow.willCloseNotification)` fires on `@MainActor` and lets MainWindowView save WindowState synchronously (async Task is spawned).

### 9. `TransfersPanel` auto-shows via `transferOperations` state
`MainWindowView` subscribes to `operationQueue.operationStream()` in a `.task` modifier. When the stream yields a non-empty array, `transferOperations` is updated and `TransfersPanel` becomes visible. No special "show/hide" boolean needed.

### 10. Active pane border indicator
A simple `@State private var activePane: PaneSide` in `MainWindowView` drives an `.overlay(isActive ? RoundedRectangle(cornerRadius: 2).stroke(Color.accentColor, lineWidth: 1) : nil)` on `PaneHost`. All interactions inside a pane call `onActivate()` which sets `activePane`. Sidebar selection calls `navigate` on the session of the active pane.

## Risks and Mitigations

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| `OperationExecutor` constructor changes between Session 10 handoff and actual code | Low | Read `Sources/Features/Operations/OperationExecutor.swift` before writing `AppEnvironment.init` — the constructor is `init(providers:conflictResolver:progressTracker:)` (confirmed) |
| `JSONFileStore` constructor signature unknown | Medium | Read `Sources/Services/Settings/JSONFileStore.swift` before writing `AppEnvironment.init`; check `init(directory:)` or `init(directory:filename:)` signature |

| `@Observable` classes not accessible across module boundaries without correct visibility | Low | All `@Observable` classes are `public` or `internal` with `@testable import` |
| Swift 6 strict concurrency: `FilePane.onDrop` closure captures `PaneSession` (MainActor) from a `Sendable` closure | Medium | Use `Task { @MainActor in await session.handleDrop(…) }` inside the drop handler; this satisfies region isolation |
| `NSHostingView` requires display connection for UI tests on headless CI | Medium | The smoke test (test 8) only asserts non-nil init, not rendering; CI is headless-safe at the init level |
| Sidebar selection driving the active pane requires `SidebarViewModel.selection` to be observed from `MainWindowView` | Low | `SidebarViewModel` is `@Observable @MainActor`; passing as `@State` from `MainWindowView` ensures SwiftUI observes changes |

| Session 26 `touches:` glob doesn't explicitly list `Sources/UI/Pane/`, `Sources/UI/Tabs/`, `Sources/UI/Transfers/`, `Sources/UI/Menus/` | Medium | These touch-list gaps are unavoidable given that Sessions 16/17/20 haven't run.
