  nil repository means no persistence (not a crash).

  where `Foundation.NSOperation` ambiguity could arise in test files.
- **`ConnectionStatus` has no `.disconnected` case** — only `.idle`, `.connecting`, `.connected`,
  `.error(String)`. The stub provider returns `.idle`.

## 3. Design Decisions and Rationale

### `DualPaneLayout` uses custom `GeometryReader` + `DragGesture`, not `HSplitView`

`HSplitView` wraps AppKit's `NSSplitView`, which manages divider position internally and does
not expose a `@Binding`. Persisting `splitFraction` via `WindowState` requires the divider to
be fully binding-driven. Solution: `GeometryReader` computes pixel widths from `splitFraction`;
an 8 pt transparent `PaneDividerStrip` responds to `DragGesture` and pushes/pops
`NSCursor.resizeLeftRight` on hover.

`DualPaneLayout` references `WindowState.minFraction` (0.2) and `WindowState.maxFraction` (0.8)
directly; the divider clamps the fraction to this range on every drag event.

### `navigate(to:)` vs `updatePath(to:)` reentrancy guard in `PaneSession`

`PaneSession.navigate(to:)` delegates to `toolbarViewModel.navigate(to:)`. The toolbar's
`onNavigate` closure calls `PaneSession.updatePath(to:)` — a private method that mutates
`currentPath` and the active tab WITHOUT calling back to the toolbar. This breaks the cycle:

```
navigate(to:) → toolbarViewModel.navigate → onNavigate → updatePath(to:)   ← terminates here
```

Rule: all external navigations (sidebar, double-click, bookmark activation) must call
`PaneSession.navigate(to:)`. Never write `currentPath` directly.

### `WindowStateSnapshot` omits `selectedSidebarItem`

`SidebarItemID` is not `Codable`. Adding a retroactive conformance from `MainWindow` would be
fragile and would change semantics owned by `UISidebar`. Sidebar selection is ephemeral — it
is not persisted across relaunches.

### `@ObservationIgnored` on protocol existentials in `@Observable` classes

`@Observable` wraps stored properties in observation accessors. Applying this to `any BookmarksProviding`
and `any FileSystemProvider` emits Swift 6 non-`Sendable` warnings because protocol existentials
may not be `Sendable`. `@ObservationIgnored` suppresses the macro expansion for these properties;
changes to their internal state are propagated through the concrete types' own observation
machinery (established in Session 18 for `SidebarViewModel`).

### Private adapters in `App/Stevedore/AppEnvironment.swift`

Placing concrete adapters (`BookmarksProviderAdapter`, `VolumeDiscoveryAdaptor`, etc.) in the
`Stevedore` executable rather than in the `MainWindow` library preserves the architectural rule
that UI library targets depend only on `Core` protocols, not concrete service implementations.
The executable layer is the only place where both `FileSystemLocal` and `UISidebar` are imported
simultaneously.

### `BookmarksProviderAdapter` optimistic write pattern

`BookmarksRepository.all()` is `async`; `BookmarksProviding.bookmarks` is synchronous on
`@MainActor`. The adapter holds a `var bookmarks: [Bookmark]` cache. On `init`, a `Task`
populates the cache asynchronously. On `add`/`remove`/`move`, the cache is mutated immediately
(optimistic) and persisted via `Task { try? await repo.save(snapshot) }`. This avoids stale UI
without blocking the main actor.

### `activeOperations` driven by background observation task

`FileOperationQueue.operationStream()` is `async`. `MainWindowModel` holds
`var activeOperations: [FeaturesOperations.Operation] = []` updated from a background `Task`
started by `startObserving()`. The task is idempotent (`guard streamTask == nil`) and cancelled
in `deinit`.

### `MainWindowModel.handleDrop` enqueues a `.copy` operation

```swift
let descriptor = OperationDescriptor(
    kind: .copy,
    sources: paths,
    destination: dest
)
Task { await operationQueue.enqueue(descriptor) }
```

The `Task { }` is fire-and-forget from `@MainActor`; `enqueue` is actor-isolated on
`FileOperationQueue` and safe to call this way.

### MW-prefix for test fakes

All `UITests` target tests share one Swift namespace. `SidebarTestSupport.swift` already
defines `FakeBookmarksProvider`, etc. Prefixing with `MW` (e.g. `MWFakeBookmarksProvider`)
avoids "invalid redeclaration" build errors in the shared target.

## 4. Risks and Mitigations

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| `Core.Tab` / `SwiftUI.Tab` ambiguity on macOS 15 SDK | **High** | Qualify as `Core.Tab` in every file that imports both; noted in `Do-Not-Repeat` cerebrum |
| `@Observable didSet` infinite recursion on `splitFraction` | **Medium** | Guard: `guard clamped != self.splitFraction else { return }` before re-assigning; covered by `WindowStateTests` |
| Test fake name collision with `SidebarTestSupport` | **High** | Prefix all `MainWindowTests` fakes with `MW` |
| `JSONFileStore` init throws at first launch (missing app support dir) | **Low** | Wrap with `try?`; nil repository handled gracefully (no restore/save) |
| `DragGesture` position calculation drift on resize | **Medium** | `value.location.x + totalWidth * splitFraction` formula; test by verifying fraction stays in bounds |
| `swiftlint --path` flag does not exist | **High** | Use positional path args: `swiftlint --strict App Sources/UI/MainWindow` (cerebrum Do-Not-Repeat) |
| `swiftformat --lint` arg-parser bug (0.59) | **High** | Paths before flag: `swiftformat App Sources/UI/MainWindow Tests/... --lint` (cerebrum Key Learnings) |
| `xcodebuild -scheme Stevedore` gate may fail if Xcode project not generated | **Medium** | `Package.swift`-based `swift build` is authoritative; note in handoff that Xcode project requires `xcodegen` or opening in Xcode |
| `MainWindowView.onChange` API — one-param vs two-param form | **Low** | Use `.onChange(of: model.sidebarViewModel.selection) { _, newValue in ... }` (two-param form, Swift 5.9+) |
| `SidebarViewModelTests.testMountedEventAddsVolume` is a pre-existing failure | **N/A** | Do not attempt to fix; outside touch glob |
