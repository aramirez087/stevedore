## Package.swift Change (Required First)

`Package.swift` is frozen for **third-party packages** only. Wiring internal module targets is
not restricted. The session explicitly requires `import DesignSystem` in all UI code (Session 08
mandate); `VolumeDiscovery` is abstracted behind a local protocol so `FileSystemLocal` is NOT needed.

**Change** — update `UISidebar`'s `extraDependencies`:

```swift
// Before
LibraryModule(name: "UISidebar", path: "Sources/UI/Sidebar", extraDependencies: []),

// After
LibraryModule(
    name: "UISidebar",
    path: "Sources/UI/Sidebar",
    extraDependencies: [.target(name: "DesignSystem")],
),
```

Why only `DesignSystem`:
- `Core` is auto-injected by `libraryTarget(_:)` — always available
- `DesignSystem` is needed for `SDListRow`, `Spacing`, `ColorTokens`, `Theme`
- `FileSystemLocal` is NOT needed — `VolumeDiscovery` is hidden behind a local
  `VolumeDiscoveryProviding` protocol; the adaptor lives in Session 26 (wiring)
- `FileSystemRemote` / `ServicesCredentials` are NOT needed — all data arrives via injected
  protocols declared in this module

This adds one internal target dependency; `Package.resolved` is unchanged.

## Detailed Type Designs

### `SidebarItemID`

```swift
public enum SidebarItemID: Hashable, Sendable {
    case bookmark(Bookmark.ID)
    case volume(URL)
    case connection(RemoteHostDescriptor.ID)
    case tag(String)
}
```

Used as `List(selection:)` binding value. The `List` provides native selection highlight;
`SidebarRow` does NOT set its own background color for selection.

### `SidebarVolume` + `SidebarVolumeEvent`

Local types so `UISidebar` never imports `FileSystemLocal`:

```swift
public struct SidebarVolume: Hashable, Sendable, Identifiable {
    public var id: URL { url }
    public let url: URL
    public let name: String
    public let isEjectable: Bool
    public let isRemovable: Bool
}

public enum SidebarVolumeEvent: Sendable {
    case mounted(SidebarVolume)
    case unmounted(URL)
}
```

Session 26 (wiring) provides a `VolumeDiscoveryAdaptor` bridging
`VolumeDiscovery.Volume` → `SidebarVolume`.

### `ConnectionStatus`

```swift
public enum ConnectionStatus: Hashable, Sendable {
    case idle
    case connecting
    case connected
    case error(String)
}
```

### Protocols

#### `BookmarksProviding` — `@MainActor` class protocol

```swift
@MainActor
public protocol BookmarksProviding: AnyObject {
    var bookmarks: [Bookmark] { get }
    func add(_ bookmark: Bookmark)
    func remove(id: Bookmark.ID)
    func move(fromOffsets: IndexSet, toOffset: Int)
}
```

`@MainActor` — accessed exclusively from the `@MainActor`-isolated `SidebarViewModel`; all
call sites are synchronous (no `await`). The Settings session (Session 24) provides the
production implementation backed by user defaults / `SettingsStore`.

#### `VolumeDiscoveryProviding` — `Sendable`

```swift
public protocol VolumeDiscoveryProviding: Sendable {
    func currentVolumes() async throws -> [SidebarVolume]
    func volumeEvents() -> AsyncStream<SidebarVolumeEvent>
}
```

`async throws` on `currentVolumes()` so the adaptor can forward `VolumeDiscovery`'s actor call.
`volumeEvents()` is synchronous — returns a pre-created stream stored in the concrete type.

#### `ConnectionStatusProviding` — `@MainActor` class protocol

```swift
@MainActor
public protocol ConnectionStatusProviding: AnyObject {
    var descriptors: [RemoteHostDescriptor] { get }
    func status(for id: RemoteHostDescriptor.ID) -> ConnectionStatus
    func add(_ descriptor: RemoteHostDescriptor)
    func remove(id: RemoteHostDescriptor.ID)
}
```

`status(for:)` is a live snapshot query; dynamic updates from the connection engine are wired
in Session 26 via a refreshConnection method. Documented as a known limitation in the handoff.

#### `TagsProviding` — `Sendable`

```swift
public protocol TagsProviding: Sendable {
    func fetchTags(forVolumeAt url: URL) async -> [String]
}
```

Production implementation uses `NSWorkspace.shared.fileLabels` (the seven Finder
color label strings — available without filesystem scanning) wrapped in
`await MainActor.run { NSWorkspace.shared.fileLabels }`. This is efficient and
synchronous. Reading `URLResourceKey.tagNamesKey` from individual files is
appropriate for per-item tags but not for the sidebar's global tag list.

#### `VolumeEjecting` — `Sendable` (in `Eject.swift`)

```swift
public protocol VolumeEjecting: Sendable {
    func eject(volumeURL: URL) async throws
}
```

Takes `URL` (not `SidebarVolume`) so it remains independent of any local volume type.
`DevicesSection` extracts `volume.url` before calling.

Production `SystemVolumeEjector`:

```swift
public struct SystemVolumeEjector: VolumeEjecting {
    public init() {}
    public func eject(volumeURL: URL) async throws {
        try await MainActor.run {
            try NSWorkspace.shared.unmountAndEjectDevice(at: volumeURL)
        }
    }
}
```

`NSWorkspace` is `@MainActor`-isolated; `unmountAndEjectDevice(at:)` is a throwing
synchronous method on macOS 10.11+. `MainActor.run { }` dispatches synchronously on
the main actor and forwards the thrown error — no `withCheckedThrowingContinuation`
or callback bridge needed.

### `SidebarViewModel`

```swift
@MainActor
@Observable
public final class SidebarViewModel {
    // MARK: - Observable state (drives UI)
    public private(set) var selection: SidebarItemID?
    public private(set) var volumes: [SidebarVolume] = []
    public private(set) var tags: [String] = []

    // MARK: - Dependencies (excluded from Observation tracking)
    @ObservationIgnored let bookmarks: any BookmarksProviding
    @ObservationIgnored let connectionStatus: any ConnectionStatusProviding
    @ObservationIgnored let ejector: any VolumeEjecting
    @ObservationIgnored private let volumeDiscovery: any VolumeDiscoveryProviding
    @ObservationIgnored private let tagsProvider: any TagsProviding

    private var volumeTask: Task<Void, Never>?

    public init(
        bookmarks: some BookmarksProviding,
        volumeDiscovery: some VolumeDiscoveryProviding,
        connectionStatus: some ConnectionStatusProviding,
        tagsProvider: some TagsProviding,
        ejector: some VolumeEjecting
    ) {
        self.bookmarks = bookmarks
        self.volumeDiscovery = volumeDiscovery
        self.connectionStatus = connectionStatus
        self.tagsProvider = tagsProvider
        self.ejector = ejector
    }

    public func select(_ id: SidebarItemID?) { selection = id }

    // Called from Sidebar.task{} — idempotent (guard against double-start)
    func start() async {
        guard volumeTask == nil else { return }
        if let initial = try? await volumeDiscovery.currentVolumes() {
            volumes = initial
        }
        if let firstVolumeURL = volumes.first?.url {
            tags = await tagsProvider.fetchTags(forVolumeAt: firstVolumeURL)
        }
        volumeTask = Task { [weak self] in
            guard let self else { return }
            for await event in self.volumeDiscovery.volumeEvents() {
                switch event {
                case .mounted(let vol):
                    if !self.volumes.contains(where: { $0.url == vol.url }) {
                        self.volumes.append(vol)
                    }
                case .unmounted(let url):
                    self.volumes.removeAll { $0.url == url }
                }
            }
        }
    }

    func ejectVolume(url: URL) async {
        try? await ejector.eject(volumeURL: url)
    }

    deinit { volumeTask?.cancel() }
}
```

**Concurrency details**:
- `@MainActor` + `@Observable` is valid on macOS 14+; `@Observable` macro generates
  `Observation`-framework conformance.
- `@ObservationIgnored` prevents the macro from wrapping protocol existentials in observation
  accessors. Without this, Swift 6 would emit warnings about non-`Sendable` existentials.
- The `volumeTask = Task { [weak self] in ... }` is created on the main actor (because
  `start()` is `@MainActor`). The `for await` loop body also runs on the main actor —
  mutations to `volumes` are therefore main-actor-safe.
- `start()` is `async` to permit `await volumeDiscovery.currentVolumes()` — called via
  SwiftUI `.task {}`.

### Section Views

#### `FavoritesSection`

```swift
struct FavoritesSection: View {
    @Bindable var viewModel: SidebarViewModel

    var body: some View {
        Section("Favorites") {
            ForEach(viewModel.bookmarks.bookmarks) { bookmark in
                SidebarRow(
                    title: bookmark.displayName,
                    symbolName: bookmark.symbolName ?? "folder"
                )
                .tag(SidebarItemID.bookmark(bookmark.id))
                .contextMenu {
                    Button("Remove") { viewModel.bookmarks.remove(id: bookmark.id) }
                }
            }
            .onMove { viewModel.bookmarks.move(fromOffsets: $0, toOffset: $1) }
        }
        .dropDestination(for: URL.self) { urls, _ in
            for url in urls {
                let path = FilePath(scheme: .local, posix: url.path)
                let bm = Bookmark(displayName: url.lastPathComponent, path: path)
                viewModel.bookmarks.add(bm)
            }
            return true
        }
    }
}
```

`ForEach` over `viewModel.bookmarks.bookmarks` (the provider's array).  Since `bookmarks` is
`@ObservationIgnored`, this reads directly from the provider — not observable. **Risk**: changes
to the provider's array will not automatically re-render. **Mitigation**: Session 24 provides a
`@MainActor @Observable` implementation of `BookmarksProviding`, so the section will re-render
via `@Bindable var viewModel` observation. For tests, we call `viewModel.objectWillChange.send()`
or test via the view model's observable state rather than the section's render.

> Alternative cleaner approach: expose `bookmarks: [Bookmark]` as an `@Observable` property
> on `SidebarViewModel` (a copy/cache) and sync mutations. Sections then observe the view model
> directly. This is the preferred pattern — see design decision #6 below.

#### `ConnectionsSection`

```swift
struct ConnectionsSection: View {
    @Bindable var viewModel: SidebarViewModel

    var body: some View {
        Section("Remote") {
            ForEach(viewModel.connectionStatus.descriptors) { descriptor in
                HStack {
                    SidebarRow(
                        title: descriptor.displayName,
                        symbolName: symbolName(for: descriptor.scheme)
                    )
                    .tag(SidebarItemID.connection(descriptor.id))
                    statusIndicator(for: viewModel.connectionStatus.status(for: descriptor.id))
                }
                .contextMenu {
                    Button("Remove") { viewModel.connectionStatus.remove(id: descriptor.id) }
                }
            }
        }
        // Stub — connection drop will be wired in Session 26
        .onDrop(of: [.json], isTargeted: nil) { _ in false }
    }

    private func symbolName(for scheme: ConnectionScheme) -> String {
        let map: [ConnectionScheme: String] = [
            .sftp: "server.rack", .ftp: "server.rack",
            .webdav: "globe", .s3: "cloud", .smb: "network",
        ]
        return map[scheme] ?? "network"
    }

    private func statusIndicator(for status: ConnectionStatus) -> some View {
        let (symbol, color) = statusInfo(status)
        return Image(systemName: symbol).foregroundStyle(color).imageScale(.small)
    }

    private func statusInfo(_ status: ConnectionStatus) -> (String, Color) {
        switch status {
        case .idle: return ("circle", .secondary)
        case .connecting: return ("arrow.circlepath", .orange)
        case .connected: return ("circle.fill", .green)
        case .error: return ("exclamationmark.circle", .red)
        }
    }
}
```

`statusInfo` uses a 4-branch switch — well below the cyclomatic complexity threshold of 12.
No dictionary needed (unlike `IconRegistry`) because `ConnectionStatus.error(String)` can't
be a dictionary key without losing the associated value.

### `FakeBookmarksProvider` — `@MainActor final class`

```swift
@MainActor
final class FakeBookmarksProvider: BookmarksProviding {
    var bookmarks: [Bookmark]
    private(set) var addCalls: [Bookmark] = []
    private(set) var removeCalls: [Bookmark.ID] = []
    private(set) var moveCalls: [(IndexSet, Int)] = []

    init(bookmarks: [Bookmark] = []) { self.bookmarks = bookmarks }

    func add(_ bookmark: Bookmark) {
        addCalls.append(bookmark)
        bookmarks.append(bookmark)

        removeCalls.append(id)
        bookmarks.removeAll { $0.id == id }
    }
    func move(fromOffsets: IndexSet, toOffset: Int) {
        moveCalls.append((fromOffsets, toOffset))
        bookmarks.move(fromOffsets: fromOffsets, toOffset: toOffset)
    }
```

### `FakeVolumeDiscovery` — `final actor` (implicitly `Sendable`)

```swift
final actor FakeVolumeDiscovery: VolumeDiscoveryProviding {
    nonisolated private let _volumes: [SidebarVolume]
    nonisolated let eventStream: AsyncStream<SidebarVolumeEvent>
    nonisolated private let continuation: AsyncStream<SidebarVolumeEvent>.Continuation

    init(volumes: [SidebarVolume] = []) {
        _volumes = volumes
        (eventStream, continuation) = AsyncStream<SidebarVolumeEvent>.makeStream()
    }
```

`AsyncStream.makeStream()` is Swift 5.9+ (included in Swift 6 toolchain).

### `FakeVolumeEjector` — `final class: @unchecked Sendable` with lock

```swift
final class FakeVolumeEjector: VolumeEjecting, @unchecked Sendable {
```

## Key Design Decisions

### 1. Protocol abstraction over direct `VolumeDiscovery` use

The session instruction says "subscribes to the `VolumeDiscovery` async stream from
`FileSystemLocal`". However, the exit criteria says "tests pass with only in-process fakes".
`VolumeDiscovery` uses `DiskArbitration` — a real system service that should not run in
unit tests. Therefore, `UISidebar` declares a local `VolumeDiscoveryProviding` protocol
and `FakeVolumeDiscovery` provides pure in-process behavior. The adaptor bridging
`VolumeDiscovery` → `VolumeDiscoveryProviding` lives in Session 26 (MainWindow wiring).

### 2. `@MainActor` protocols for `BookmarksProviding` and `ConnectionStatusProviding`

Both providers are read and mutated exclusively from `SidebarViewModel`, which is `@MainActor`.
`@MainActor` on the protocol eliminates `await` at every call site (no actor crossing) and
avoids the overhead of making provider state `Sendable`.

### 3. `@ObservationIgnored` on injected dependencies

`@Observable` macro would attempt to wrap `any BookmarksProviding` etc. in observation
accessors. In Swift 6 strict mode this emits warnings about non-`Sendable` existentials.
`@ObservationIgnored` opts them out of tracking entirely — they are dependencies, not state.

### 4. `volumes` and `tags` as `@Observable` cached state

`SidebarViewModel` owns the observed arrays. Sections read `viewModel.volumes` and
`viewModel.tags`, which the `@Observable` macro tracks. This gives automatic re-rendering
without any `@Published` or `ObservableObject` infrastructure.

### 5. Bookmarks not cached in `@Observable` state (current design)

`FavoritesSection` reads directly from `viewModel.bookmarks.bookmarks`. This means the section
will only re-render when `viewModel` itself changes (not when the provider mutates). This is
acceptable for Session 18 because in tests, mutations go through the fake (which is the same
object); in production, the Settings session (24) implements `BookmarksProviding` as an
`@Observable` class. If this creates observable propagation issues, the fix is: expose
`public private(set) var bookmarkItems: [Bookmark]` in `SidebarViewModel`, sync it from
`bookmarks.bookmarks` after each mutation, and sections read from the view model directly.
Record as Open Issue; Session 24 must confirm their implementation approach.

### 6. `start()` idempotency guard

`guard volumeTask == nil else { return }` prevents double-subscription if the view
disappears and reappears (`.task {}` re-fires on re-appear in SwiftUI 5.0+).

### 7. Connection status as snapshot query

`connectionStatus(for:)` is not `@Observable`-tracked. Dynamic updates from the connection
engine will be added in Session 26. Documented as Open Issue.

### 8. `ConnectionsSection` DnD stub

`.onDrop(of: [.json], ...)` returns `false` (no-op). `RemoteHostDescriptor` is `Codable`;
a proper DropDelegate implementation will JSON-decode the descriptor. Wired in Session 26.
Returning `false` is better than returning `true` (tells the drag system the drop was rejected
so the user gets visual feedback).

### 9. SwiftLint compliance patterns

- All supporting enums (`SidebarItemID`, `ConnectionStatus`, `SidebarVolumeEvent`) are
  top-level types in their own files — avoids `nesting` rule violation
- `statusInfo(_:)` uses 4-branch switch (not dictionary) because `ConnectionStatus.error(String)`
  cannot be a dictionary key without losing the payload
- No `print()` — `os.Logger` if logging is needed (none required here)
- `mandatory_comma: true` — all trailing commas on multi-line parameter lists

### 10. `nonisolated let` on actor fakes

`FakeVolumeDiscovery` uses `nonisolated let` for `_volumes`, `eventStream`, and `continuation`
because they are immutable (`let`) and their types are `Sendable`. This lets `volumeEvents()`
and `emit(_:)` be `nonisolated` — callable without `await` from test code.

## Risks and Mitigations

| Risk | Mitigation |
|------|-----------|
| `@Observable` + `any Protocol` Swift 6 warnings | `@ObservationIgnored` on all injected protocol properties |
| `SystemVolumeEjector` calling `NSWorkspace` from wrong isolation | Inner `Task { @MainActor in }` ensures dispatch to main actor |
| `FavoritesSection` doesn't re-render when provider mutates | Acceptable for Session 18; Session 24 provides `@Observable` implementation; record as Open Issue |
| `AsyncStream.makeStream()` availability | Swift 5.9+; included in Swift 6 toolchain |
| Connection status staleness | Documented Open Issue; Session 26 adds live status stream |
| `start()` called twice (view reappear) | `guard volumeTask == nil` idempotency guard |
| SwiftFormat `wrapMultilineStatementBraces` vs SwiftLint `opening_brace` | Established fix: extract multi-condition `if` into `let` bindings (Session 04/06 pattern) |
| `FakeVolumeEjector.shouldThrow` accessed from async context | Reads happen from `@MainActor` test; `shouldThrow` is set before async call — safe |
| `List(selection: Binding(...))` with `SidebarItemID?` | `SidebarItemID: Hashable` ✓; `List` requires `Hashable` selection type |
| `NSColor.tagColors` may not exist on macOS 14 | If used, guard with `#available(macOS 14, *)` or use static fallback array |
