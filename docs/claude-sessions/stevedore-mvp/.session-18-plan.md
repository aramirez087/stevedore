#### `SidebarViewModel.swift`
```swift
@MainActor
@Observable
public final class SidebarViewModel {
    // MARK: - Published state
    public var selection: SidebarItemID?
    public private(set) var volumes: [VolumeDiscovery.Volume] = []
    public private(set) var availableTags: [String] = []

    // MARK: - Injected dependencies
    let bookmarks: any BookmarksProviding
    let volumeDiscovery: VolumeDiscovery
    let ejector: any VolumeEjecting
    let connections: any ConnectionStatusProviding
    let tags: any TagsProviding

    private var volumeTask: Task<Void, Never>?

    public init(
        bookmarks: some BookmarksProviding,
        volumeDiscovery: VolumeDiscovery,
        ejector: some VolumeEjecting,
        connections: some ConnectionStatusProviding,
        tags: some TagsProviding
    ) { ... }

    public func select(_ id: SidebarItemID?) { self.selection = id }

    public func startVolumeUpdates() {
        // 1. Synchronous initial load
        self.volumes = (try? self.volumeDiscovery.currentVolumes()) ?? []
        // 2. Async event stream
        self.volumeTask = Task { [weak self] in
            guard let self else { return }
            for await event in self.volumeDiscovery.events() {
                switch event {
                case let .mounted(vol): self.volumes.append(vol)
                case let .unmounted(url): self.volumes.removeAll { $0.url == url }
                }
            }
        }
    }

    public func ejectVolume(url: URL) async {
        try? await self.ejector.eject(volumeURL: url)
    }

    public func addFavorite(path: FilePath, displayName: String) {
        let bookmark = Bookmark(displayName: displayName, path: path)
        self.bookmarks.add(bookmark)
    }

    public func removeFavorite(id: Bookmark.ID) {
        self.bookmarks.remove(id: id)
    }

    public func reorderFavorites(fromOffsets: IndexSet, toOffset: Int) {
        self.bookmarks.move(fromOffsets: fromOffsets, toOffset: toOffset)
    }

    public func addConnection(_ descriptor: RemoteHostDescriptor) {
        self.connections.add(descriptor)
    }

    deinit { self.volumeTask?.cancel() }
}
```

**Concurrency note**: `volumeTask` is a `@MainActor`-isolated `Task`. The `for await` loop inherits MainActor isolation. `VolumeDiscovery.events()` is `nonisolated` and its continuation yields are thread-safe via `AsyncStream`. No `await MainActor.run` needed inside the task body.

## Key Design Decisions

### 1. VolumeDiscovery Used Directly (Not Behind Protocol)
Rationale: `VolumeDiscovery` is already a concrete actor in FileSystemLocal; the task explicitly says "subscribes to the VolumeDiscovery async stream from FileSystemLocal". Introducing a `VolumeDiscoveryProviding` protocol would require either a retroactive conformance (Swift 6 warning) or a second protocol with identical shape. Tests use a real `VolumeDiscovery` — `currentVolumes()` calls `FileManager` which is fine in unit tests (returns real system volumes).

### 2. `VolumeEjecting` Takes `URL` Not `VolumeDiscovery.Volume`
Rationale: Keeps `VolumeEjecting` decoupled from FileSystemLocal's `Volume` struct. Any caller extracts the URL before calling. This matches the principle that protocols declared in UISidebar should not have dependencies leaking outward to other modules they don't own.

### 3. `BookmarksProviding` and `ConnectionStatusProviding` Are `@MainActor` Protocols
Rationale: Both are read and mutated exclusively on the main actor (by SidebarViewModel which is @MainActor). Making them @MainActor eliminates any need for `await` at call sites within the VM and avoids actor-hopping overhead for simple property reads.

### 4. `@Observable` Used Over `ObservableObject`
Rationale: Session instructions require `@Observable`. This is the Observation framework (macOS 14+, which is our deployment target). SwiftUI automatically tracks property access; no `@Published` needed. `@Bindable var vm: SidebarViewModel` in view initializers enables two-way bindings.

### 5. Sections as Separate Views (Not Single Giant Body)
Rationale: Satisfies "each section is independently testable (its own preview, its own test class)". Each section view is a `public struct` that takes `@Bindable var viewModel: SidebarViewModel`. They share the same VM instance but are tested in isolation via NSHostingView.

### 6. ConnectionStatus Rendering via Dictionary (Not Switch)
Rationale: A `switch` on ConnectionStatus with symbol names + colors in 4+ cases would hit `cyclomatic_complexity` warning threshold (12 in `.swiftlint.yml`). Following Session 08's pattern for `IconRegistry`, we use a `private let` dictionary:
```swift
private let statusSymbol: [ConnectionStatus: String] = [.idle: "circle", .connecting: "arrow.circlepath", .connected: "circle.fill", ...]
```
But `ConnectionStatus.error(String)` is not `Hashable` as a dictionary key in this form. Alternative: use a `func statusInfo(_ status: ConnectionStatus) -> (symbol: String, color: Color)` helper that stays simple enough (4 branches) without violating the threshold.

### 7. Drag and Drop Implementation
- Favorites: `.dropDestination(for: URL.self)` — macOS provides file URLs when dragging from Finder
- Connections: `.onDrop(of: [.json], delegate:)` with a `DropDelegate` that JSON-decodes `RemoteHostDescriptor` — avoids custom UTType registration that requires Info.plist

### 8. Tag Colors
macOS Finder tag colors are standardized (gray, green, purple, blue, yellow, red, orange). Map tag name → color via `NSColor.tagColors` if available (macOS 14+) or a static fallback array indexed by `tagName.hashValue & 7`. No UIKit/SwiftUI `Color` literals — use `theme.colors.*` tokens where applicable and `Color(nsColor: NSColor.tagColors[...])` for tag dots.

### 9. Module Sentinel Preservation
`Placeholder.swift` is deleted; `SidebarModule.swift` preserves `UISidebarModule.moduleName = "UISidebar"`. The existing smoke test (`UISidebarSmokeTests.swift`) will continue to pass.

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| `@Observable` + `@MainActor` concurrency errors in Swift 6 | Use `nonisolated(unsafe)` only if forced; prefer `@Observable` direct access which Swift 6 handles natively |
| `VolumeDiscovery.events()` starts DA session — might log or cause issues in tests | Tests never consume the event stream; they only call `currentVolumes()` directly. The DA session is lazy and only starts when `events()` is called. |
| `NSColor.tagColors` may not exist on macOS 14 | Guard with `#available` or use a static fallback `[NSColor]` array |
| `List(selection:)` with `SidebarItemID?` — requires `SidebarItemID` to be `Hashable` | Confirmed: `SidebarItemID` is `Hashable` and `Sendable` |
| `ConnectionStatus.error(String)` breaks simple dictionary dispatch | Use helper function with 4-branch switch (under cyclomatic_complexity threshold of 12) |
| D&D JSON decode for RemoteHostDescriptor requires `Decodable` | `RemoteHostDescriptor: Codable` from Session 01 ✓ |
| swiftformat `--self insert` rule | All property/method accesses explicitly use `self.` prefix |
| swiftformat `--commas always` | All trailing commas added to multi-line parameter lists |
| `startVolumeUpdates()` called from `.onAppear` — must be idempotent (called again on view re-appear) | Guard with `guard volumeTask == nil else { return }` |
