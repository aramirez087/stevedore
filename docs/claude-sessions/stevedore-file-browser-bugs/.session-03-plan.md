## Design decisions and rationale

### D1. Run gates exactly in the order specified by the operator
The session prompt fixes the order: SwiftPM build → Xcode build →
scoped tests → full tests → SwiftFormat → SwiftLint. Following the
prescribed order means failures surface at the cheapest stage that can
detect them (compile errors before test failures before style errors).

### D2. Treat pre-existing failures as non-blockers, but document them
Gate 4 (full `swift test`) and Gate 6 (full `swiftlint --strict`) sweep
modules outside this epic's scope. The S02 handoff already flagged 4
pre-existing swiftlint violations in `Package.swift`. The exit
criteria from the operator explicitly allow these:

> Gate 4 may have pre-existing failures from other modules; document
> them but do not treat them as blockers if they existed before this
> epic.

The same logic applies to Gate 6's known `Package.swift` violations.

To distinguish "pre-existing" from "introduced this epic", verify
each failure also reproduces on `main` (or the epic-base commit) by
running the same gate against a `git stash`-cleaned working tree if
needed. Record the reproduction in the handoff.

### D3. If a gate fails for a reason inside scope, fix root cause and re-run from Gate 1
The operator rule is explicit:

> If a gate fails, fix the root cause in the modified files only,
> then re-run that gate **and all subsequent gates from scratch**.

Re-running from scratch (not just the failing gate) ensures a fix for
gate N does not silently regress gates 1..N-1.

### D4. Capture verbatim output for each gate
The handoff must contain the actual tail of each command's output so
a human reviewer can verify the verdict without re-running. Use the
exact `tail -N` slices from the operator prompt — they were sized
deliberately to capture summary lines without flooding the doc.

### D5. Xcode build is run via `xcodebuild`, not via XcodeBuildMCP
The operator prompt prescribes a specific `xcodebuild` invocation.
Use it verbatim. XcodeBuildMCP would offer richer telemetry but
introduces a different command shape that the handoff template
doesn't account for, and risks driving a different scheme/destination
than the gate intends.

### D6. Go/No-Go verdict is binary, with named blockers
The handoff verdict is one of:
- **GO** — Gates 1, 2, 3, 5, 6 pass; Gate 4 either passes or only has
  documented pre-existing failures from outside the epic.
- **NO-GO** — Any in-scope gate fails after the allowed retries, or a
  Gate 4 failure was introduced by this epic.

The verdict line must name every blocker (or state "no blockers").

## Risks and mitigations

| # | Risk | Mitigation |
|---|---|---|
| 1 | Gate 1 (`swift build -Xswiftc -warnings-as-errors`) may surface a warning in a sibling module that compiles transitively but wasn't built in S02's scoped `--target MainWindow` invocation. | If the warning is in a file outside `touches:`, document as pre-existing (verify on base commit) and proceed. If in scope, fix in `PaneHost.swift` only. |
| 2 | Gate 2 (`xcodebuild`) may fail due to stale `DerivedData` or signing issues unrelated to the code change. | First retry with `xcodebuild clean`. If still failing, capture the exact error and check if it reproduces on the epic-base commit; if so, document as environmental, not a code blocker. |
| 3 | Gate 4 (full `swift test`) likely includes long-running or environment-dependent tests (network, filesystem, simulator). Pre-existing flakes could be misread as new failures. | Run the gate twice if any failure appears. Compare failure set to a baseline run on the epic-base commit. Only fail-block when a *new* failure traces to the S02 diff. |
| 4 | Gate 5 (SwiftFormat lint, **paths before `--lint`**) — easy to invert flag order and get a confusing error. | Use the literal command from the prompt: `swiftformat Sources Tests --lint`. Do not improvise flag positions. |
| 5 | Gate 6 (SwiftLint strict) will report the 4 known `Package.swift` violations. Re-fixing these is forbidden by scope. | Verify count == 4 and that all 4 are in `Package.swift`; quote them in the handoff. Any violation count > 4 OR any violation in a different file is a real blocker until proven pre-existing. |
| 6 | Re-running gates after a fix could mask a regression by hitting a build cache. | The operator says "from scratch" — interpret this as re-running every gate command in order, not as `swift package clean`. The Swift driver re-checks invariants on each invocation; that is sufficient. Only invoke `swift package clean` if a stale build is *suspected*. |
| 7 | Writing the handoff before all gates pass risks a stale verdict. | Write the handoff **only after** the final gate completes. Keep gate output in scratch buffers / shell history during execution; assemble the doc in one Write call at the end. |
| 8 | OpenWolf bookkeeping forgotten. | Last action of the session: append the `.wolf/memory.md` line. Add to TodoWrite as the final task. |

## Verification steps

The verification *is* the work of this session. Each command below is
a gate; gate verbatim text is from the operator prompt.

### Gate 1 — SwiftPM build (full package, warnings-as-errors)
```bash
swift build -Xswiftc -warnings-as-errors 2>&1 | tail -15
```
**Pass criterion**: exit 0; final line contains "Build complete!" or
equivalent; no warning lines in the tail.

### Gate 2 — Xcode app build (macOS)
```bash
xcodebuild -project Stevedore.xcodeproj -scheme Stevedore -configuration Debug \
  -destination 'platform=macOS' build 2>&1 | tail -10
```
**Pass criterion**: exit 0; final line "** BUILD SUCCEEDED **".

### Gate 3 — Scoped MainWindow tests
```bash
swift test --filter MainWindowTests 2>&1 | tail -20
```
**Pass criterion**: exit 0; "Executed N tests, with 0 failures"; N ≥ 16
(S02 handoff reports 11 prior + 5 new = 16).

### Gate 4 — Full test suite
```bash
swift test 2>&1 | tail -20
```
**Pass criterion**: exit 0 (preferred). If non-zero, every failure
must be reproducible on the epic-base commit; otherwise it's a blocker.

### Gate 5 — SwiftFormat lint
```bash
swiftformat Sources Tests --lint 2>&1 | grep -v "^$" | tail -20
```
**Pass criterion**: exit 0; "0/N files require formatting."

### Gate 6 — SwiftLint strict
```bash
swiftlint --strict Sources Tests 2>&1 | tail -20
```
**Pass criterion**: exit 0 OR exactly the 4 known pre-existing
`Package.swift` line-length violations — and nothing else. Note:
`Package.swift` is **not** under `Sources/` or `Tests/`, so a strict
read of this gate scope should *not* surface those 4 violations.
Verify and document the actual count.

### Bookkeeping verification
- `.wolf/memory.md` has a new line dated today with the session-03
  marker.
- `docs/roadmap/stevedore-file-browser-bugs/session-03-handoff.md`
  exists and contains the verdict, every gate's tail output, and an
  epic summary.

## Exact order of operations

1. **Orient** — Read `docs/roadmap/stevedore-file-browser-bugs/session-02-handoff.md`
   (already loaded into context per the prompt's "Previous Session
   Handoffs" block, but re-read from disk to confirm no drift).
2. **Sanity check working tree** — `git status` to confirm only
   expected modified files (the S02 changes to `PaneHost.swift`,
   `MainWindowTests.swift`, plus OpenWolf bookkeeping). Any
   unexpected file is a flag — investigate before running gates.
3. **TodoWrite** the six gates + handoff write + memory append as
   tasks; mark them off as completed.
4. **Run Gate 1** (`swift build -Xswiftc -warnings-as-errors`).
   - Capture tail. Record pass/fail.
   - On fail: diagnose. If root cause in `touches:` scope, fix
     minimally and **restart from Gate 1**. If outside scope and
     pre-existing, document and continue.
5. **Run Gate 2** (`xcodebuild`).
   - Same protocol: capture, evaluate, fix-or-document, restart from
     Gate 1 if the fix touches source.
6. **Run Gate 3** (`swift test --filter MainWindowTests`).
7. **Run Gate 4** (`swift test`).
   - On any failure: re-run once to filter flakes. For surviving
     failures, compare against epic-base by checking out the
     epic-base commit in a git worktree (preferred) or
     `git stash`-ing local changes (if no other option) — never
     destructive against the working branch. Document the comparison.
8. **Run Gate 5** (`swiftformat … --lint`).
9. **Run Gate 6** (`swiftlint --strict Sources Tests`).
   - Confirm violation count matches the S02 baseline (expected: 0
     for `Sources Tests`, since the 4 `Package.swift` violations live
     outside this scope).
10. **Compute verdict**:
    - GO if Gates 1, 2, 3, 5, 6 are clean and Gate 4 is either clean
      or only pre-existing failures.
    - NO-GO otherwise; the verdict line names each blocker.
11. **Write handoff** to
    `docs/roadmap/stevedore-file-browser-bugs/session-03-handoff.md`
    in one `Write` call, structured per the convention:
    - `## Scope` — one paragraph: "verification of S01+S02 deliverables".
    - `## What changed` — list of files touched this session
      (handoff + `.wolf/memory.md`; conditionally the touches files
      if a fix was needed).
    - `## Decisions` — verdict, rationale, treatment of pre-existing
      failures, any fixes applied.
    - `## Open issues / risks` — carry forward S02's Open Issues 1–4
      with status; add anything new the gates surfaced.
    - `## Next-session inputs` — for any GO: nothing required;
      epic is shippable. For NO-GO: list exact files to read for the
      remediation session.
    - `## Verification` — verbatim tail of each gate, in order, with
      pass/fail label.
    - **Epic summary** — appendix: cumulative diff stats across S01
      → S03, list of bugs closed (`bug-049`, `bug-050`), list of
      open issues remaining.
12. **OpenWolf bookkeeping**:
    - Append one line to `.wolf/memory.md`:
      `| HH:MM | session-03 ci-gate | docs/roadmap/.../session-03-handoff.md | <GO|NO-GO> | ~XXXX |`
    - If a new defect was uncovered, append to `.wolf/buglog.json`.
    - Update `.wolf/cerebrum.md` `## Key Learnings` *only if* the
      gates surfaced a non-obvious pattern (e.g., a flaky test that
      future sessions need to know about). Low threshold, but no
      forced entry.
13. **Stop.** Do not commit. Do not push. The epic-runner harness
    handles git plumbing.
