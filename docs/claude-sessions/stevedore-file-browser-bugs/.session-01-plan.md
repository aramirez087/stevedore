**Verified in `Sources/UI/MainWindow/PaneHost.swift` (FileBrowserView row body):**

The `List(self.items, id: \.path)` row is an `HStack` (icon, name, size, date) carrying only:

Grep `Sources/UI/MainWindow/` for `contextMenu` returns zero hits inside `FileBrowserView`. **Confirmed: no `.contextMenu` modifier is registered on the row.**

### bug-050 — Single tap navigates; double-click goes two levels deep

**Verified in `Sources/UI/MainWindow/PaneHost.swift` (FileBrowserView row body):**

```swift
.onTapGesture {
    if item.kind == .directory {
        self.session.navigate(to: item.path)
    }
}
```

This is the only tap handler. Default `count` is 1, so a single click navigates immediately. A subsequent rapid second click hits whatever item now occupies that pixel position in the freshly loaded listing — typically the first directory of the new listing — producing a second navigation. **Confirmed.**

The view's `@State` declarations are `items`, `isLoading`, `errorMessage`. **No `selectedItemPath` exists.**

## 4. Design decisions and rationale

### 4.1 Context menu item set (bug-049 fix in S02)

| Item | Real or stub? | Disabled when… | Action |
|---|---|---|---|
| **Open** | Real | `item.kind != .directory && item.path.scheme != .local` | Directory → `session.navigate(to: item.path)`; local file → `NSWorkspace.shared.open(URL(fileURLWithPath:))` |
| **Reveal in Finder** | Real, **local-only** | `item.path.scheme != .local` | `NSWorkspace.shared.activateFileViewerSelecting([URL(fileURLWithPath: item.path.posixString)])` |
| **Move to Trash** | Real (delegates to provider) | `item.path.scheme != .local` for MVP | `Task { _ = try? await session.provider.execute(OperationDescriptor(kind: .trash, sources: [item.path]), progress: nil) }` |

**Optional placeholder set (kept disabled, visible) — recommend for visual parity with Finder:**

| Item | Always disabled in S02 |
|---|---|
| **Rename** | Yes |
| **Get Info** | Yes |

**Rationale:**
- "Open" and "Reveal in Finder" are trivial and self-contained — no new wiring required.
- "Move to Trash" must use the existing `provider.execute(_:progress:)` API; there is no convenience `trash` method on `FileSystemProvider`. `OperationKind.trash` exists; `LocalFileOperations.performTrash` already implements it.
- The S02 prompt requires placeholders to be **visually present but disabled**, not omitted, so the menu surface communicates planned scope without misleading the user.
- The menu attaches to the **row HStack** after `.contentShape` so the entire row is the right-click anchor (matches the bug-046 lesson: tag/menu must live on the outermost container of a composed row).

### 4.2 Selection + navigation gesture split (bug-050 fix in S02)

**State to add:**

```swift
@State private var selectedItemPath: FilePath?
```

**Gesture wiring on the row HStack (sketch):**

```swift
.background(self.rowBackground(for: item))
.contentShape(Rectangle())
// Double-tap MUST be declared before single-tap so SwiftUI gives it priority.
.onTapGesture(count: 2) { self.handleDoubleTap(item) }
.onTapGesture(count: 1) { self.selectedItemPath = item.path }
.contextMenu { self.contextMenu(for: item) }
```

Helpers (sketch):

```swift
private func rowBackground(for item: FileItem) -> Color {
    self.selectedItemPath == item.path
        ? self.theme.colors.accent.opacity(0.15)
        : Color.clear
}

private func handleDoubleTap(_ item: FileItem) {
    if item.kind == .directory {
        self.session.navigate(to: item.path)
    } else if item.path.scheme == .local {
        NSWorkspace.shared.open(URL(fileURLWithPath: item.path.posixString))
    }
}
```

**Selection-clear policy:**

```swift
.onChange(of: self.session.currentPath) { _, _ in
    self.selectedItemPath = nil
}
```

**Rationale:**
- SwiftUI dispatches the higher-`count` tap handler first when both are present on the same view **and** the higher-count is declared first. Reversing the order causes single-tap to fire on every click and double-tap to never register.
- Highlight is applied via `.background(...)` rather than swapping foreground tokens — keeps text/icon untouched and avoids an `if … else` in the row body that would re-render the entire `HStack`.
- Clearing selection on `currentPath` change ties selection state to the **listing** the user is viewing. We do not need a separate clear on tab switches because `activateTab → navigate → currentPath` already fires.

### 4.3 Why not use `List`'s built-in selection binding?

`List(_:id:selection:)` is tempting, but:
1. It would force a `Hashable` selection ID and the binding's behaviour interacts poorly with our existing `.onTapGesture` semantics.
2. The current row composition (`HStack` + `.contentShape`) is built for free-form gestures; switching to selection-driven `List` requires keyboard-nav handlers that aren't in scope.
3. Per the cerebrum learning around `SwiftUI List selection with .tag()`, List + selection has subtle hit-target requirements that already bit us in DevicesSection (bug-046). Manual gestures keep behavior local to FileBrowserView.

**Decision:** keep the manual `onTapGesture` model; do not introduce `List(selection:)` in S02.

6. **Gesture sketch** — §4.2 code blocks copied verbatim.
7. **Tests S02 must add** — §5 table.
8. **SwiftUI gotchas to watch:**
   - **Gesture priority:** declare `.onTapGesture(count: 2)` *before* `.onTapGesture(count: 1)`; reversed order silently breaks the double-tap.
   - **`.contextMenu` placement:** apply on the row `HStack` after `.contentShape(Rectangle())` so the entire row is the menu's anchor (bug-046 lesson).
   - **`.onChange(of:)` 2-arg form:** macOS 14+ uses `(oldValue, newValue) -> Void`. The single-arg form is deprecated; using it triggers a warning under `-warnings-as-errors`.
   - **`@State` and `FilePath?`:** `FilePath` is `Hashable` + `Sendable`; safe for `@State`. FileBrowserView body runs on `MainActor` already.
   - **`NSWorkspace.shared.open(_:)` returns `Bool`:** discarding the return value is fine; if S02 wants to surface failure, route through `os.Logger` (no `print`).
   - **`provider.execute(...)` is async + throwing:** must be called from a `Task { try? await … }` inside the menu button action. The operation engine surfaces failures through its own progress channel; ignoring the optional-try is acceptable for MVP.
9. **Open issues / risks:**
   - `FileBrowserView` is `private` — S02 will likely promote it to `internal` to let tests reach in via `@testable import MainWindow`.
   - No keyboard navigation, no Quick Look (Space), no Cmd+Delete shortcut. Out of scope for this epic.
   - Remote schemes: "Reveal in Finder" and "Move to Trash" are disabled for non-`.local` paths in MVP. The operation engine reports remote-trash failure; do not hand-roll a pre-disable beyond the scheme check.
10. **Next-session inputs** — files S02 must read (this handoff + `PaneHost.swift` + `MainWindowTestSupport.swift`).
11. **Verification** — exact commands run + outcomes (see §7).
