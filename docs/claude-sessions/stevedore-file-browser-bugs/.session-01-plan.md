## 3. Confirmed root-cause findings (to be recorded in handoff)

### bug-049 — Missing right-click context menu

**Verified in `Sources/UI/MainWindow/PaneHost.swift:210–243`:**

The `List(self.items, id: \.path)` row is an `HStack` containing icon, name, size, and date. It has **only**:

- `.contextShape(Rectangle())`
- `.onTapGesture { … }`

A grep for `.contextMenu` across `Sources/UI/MainWindow/` returns zero hits inside `FileBrowserView`. **Confirmed: no context menu is registered on the row.**

### bug-050 — Single tap navigates; double-click goes two levels deep

**Verified in `Sources/UI/MainWindow/PaneHost.swift:238–242`:**

```swift
.onTapGesture {
    if item.kind == .directory {
        self.session.navigate(to: item.path)
    }
}
```

This is the only tap handler. Default `count` is 1, so a single click navigates immediately. A subsequent rapid second click hits whatever item now occupies that pixel position in the freshly loaded listing — typically the first row of the new directory — and navigates again. **Confirmed.**

The view's `@State` declarations are `items`, `isLoading`, `errorMessage`. **There is no `selectedItemPath`** anywhere in `FileBrowserView`.

## 4. Design decisions and rationale

### 4.1 Context menu item set (bug-049 fix in S02)

| Item | Real or stub? | Disabled when… | Action |
|---|---|---|---|
| **Open** | Real | `item.kind != .directory` (MVP scope: directories navigate; file open is stub) | `session.navigate(to: item.path)` |
| **Reveal in Finder** | Real, **local-only** | `session.currentPath.scheme != .local` | `NSWorkspace.shared.activateFileViewerSelecting([URL(fileURLWithPath: item.path.posixString)])` |
| **Move to Trash** | Real (delegates to provider) | always shown enabled for local; we route through `provider.execute(OperationDescriptor(kind: .trash, sources: [item.path]), progress: nil)` inside a `Task` | descriptor above |
| **Rename** | Stub (disabled) | always disabled in S02 | `{}` |
| **Get Info** | Stub (disabled) | always disabled in S02 | `{}` |

**Rationale:**
- "Open" and "Reveal in Finder" are trivial and self-contained — no new wiring required.
- "Move to Trash" must use the existing `provider.execute(_:progress:)` API; there is no convenience `trash` method on `FileSystemProvider`. `OperationKind.trash` exists; `LocalFileOperations.performTrash` already implements it (per anatomy.md:536).
- Rename and Get Info are intentionally **shown but disabled** so the menu surface communicates planned scope without misleading the user. The S02 prompt explicitly says "All placeholder items must be visually present but disabled, not omitted."
- The menu attaches to the **row HStack**, after `.contentShape` and **before** the tap gestures, matching the bug-046 fix pattern (modifier order matters for hit-testing on composed rows).

### 4.2 Selection + navigation gesture split (bug-050 fix in S02)

**State to add:**

```swift
@State private var selectedItemPath: FilePath?
```

**Gesture wiring on the row HStack:**

```swift
.contentShape(Rectangle())
.contextMenu { /* §4.1 items */ }
// Double-tap MUST be declared before single-tap so SwiftUI gives it priority.
.onTapGesture(count: 2) {
    if item.kind == .directory {
        self.session.navigate(to: item.path)
    } else {
        let url = URL(fileURLWithPath: item.path.posixString)
        NSWorkspace.shared.open(url)
    }
}
.onTapGesture(count: 1) {
    self.selectedItemPath = item.path
}
.background(
    self.selectedItemPath == item.path
        ? self.theme.colors.accent.opacity(0.15)
        : Color.clear
)
```

**Selection-clear policy:**

```swift
.onChange(of: self.session.currentPath) { _, _ in
    self.selectedItemPath = nil
}
```

**Rationale:**
- SwiftUI dispatches the higher-`count` tap handler first when both are present on the same view *and the higher-count is declared first*. Reversing the order causes single-tap to fire on every click and the double-tap never to register.
- Highlight is applied via `.background(...)` rather than swapping the row's foreground tokens — keeps the row's text color and icon untouched and avoids a `if … else` in the row body that would re-render the entire `HStack`.
- Clearing selection on `currentPath` change keeps state semantically tied to the **listing** the user is viewing. We do not clear on tab switches because `activateTab → navigate` already triggers `currentPath` change.

### 4.3 Why not use `List`'s built-in selection binding?

`List(_:id:selection:)` is tempting, but:
1. It would force us to add a `Hashable` selection ID (`item.path` works, but the binding then disables our existing `.onTapGesture` semantics).
2. The current row composition (HStack with `.contentShape`) is built for free-form gestures; switching to selection-driven `List` requires also introducing keyboard-nav handlers that aren't in scope for this epic.
3. Per cerebrum learning (`SwiftUI List selection with .tag()`), List + selection has subtle hit-target requirements that already bit us in DevicesSection (bug-046). Manual gestures keep behavior local to FileBrowserView.

**Decision:** keep manual `onTapGesture` model; do not introduce `List(selection:)`.

8. **SwiftUI gotchas to watch:**
   - **Gesture priority:** declare `.onTapGesture(count: 2)` *before* `.onTapGesture(count: 1)`; reversed order silently breaks the double-tap.
   - **`.contextMenu` placement:** apply on the row `HStack` after `.contentShape(Rectangle())` so the entire row is hit-testable as the menu's anchor (matches bug-046 lesson: tag/menu must be on the outermost container of a composed row).
   - **`.onChange(of:)` 2-arg form:** macOS 14+ uses `(oldValue, newValue) -> Void`. The single-arg form is deprecated; using it triggers a warning under `-warnings-as-errors`.
   - **`@State` and `FilePath?`:** `FilePath` is `Hashable` + `Sendable`, safe for `@State`. No actor hop required since FileBrowserView body runs on `MainActor` already.
   - **`NSWorkspace.shared.open(_:)` returns `Bool`:** discarding the return value is fine; if S02 wants to surface failure, route through a logger (no `print`).
   - **`provider.execute(...)` is async + throwing:** must be called from a `Task { try? await … }` inside the menu button action. Suppress the optional-try with logging only if needed; for MVP, ignore — the operation engine surfaces failures through its own progress channel.
9. **Open issues / risks:**
   - `FileBrowserView` is `private` — S02 will likely promote it to `internal` to let tests reach in via `@testable import MainWindow`.
   - No keyboard navigation, no Quick Look (Space), no Cmd+Delete shortcut. Out of scope for this epic.
   - Remote schemes: "Reveal in Finder" is correctly disabled, but "Move to Trash" on remote will fail at execute-time. Acceptable for MVP because the operation engine reports failure; S02 should not pre-disable based on scheme.
10. **Next-session inputs** — files S02 must read (this handoff + PaneHost.swift + MainWindowTestSupport.swift).
11. **Verification** — exact commands run + outcomes (see §7).
