# Session 03 Implementation Plan — Bug #055: Home Sidebar Wrong Path

## Problem Statement

The sidebar "home" row (labeled "home" in the Devices section) navigates to
`/System/Volumes/Data/home` (the macOS autofs firmlink) instead of the user's
actual home directory (`FileManager.default.homeDirectoryForCurrentUser`, e.g.
`/Users/aramirez`).

## Root Cause (from Session 01 audit)

`VolumeDiscovery.currentVolumes()` calls
`FileManager().mountedVolumeURLs(includingResourceValuesForKeys:options:[.skipHiddenVolumes])`
which includes the autofs mount at `/System/Volumes/Data/home` with
`volumeName == "home"`. This entry flows directly into
`SidebarViewModel.start()` → `self.volumes` → `DevicesSection` row →
`MainWindowView.filePath(for: .volume(url))` → `session.navigate(to:)`.

There is no synthetic Home sidebar item anywhere. The bug is that the autofs
`/home` volume is displayed as if it were the user's home directory.

The autofs mount may be reported by the OS as either:
- `/System/Volumes/Data/home` (the actual mount point, as returned by
  `mountedVolumeURLs`)
- `/home` (a firmlink pointing to the above)

Both must be filtered.

## Design Decisions

### Option A — Filter at `SidebarViewModel` (chosen)

Filter and replace the autofs entry inside `SidebarViewModel.start()` and the
`.mounted` event branch. Inject a synthetic `SidebarVolume` whose
`url = FileManager.default.homeDirectoryForCurrentUser`.

**Why:** Entirely in scope (`SidebarViewModel.swift`). Satisfies the operator
rule: "Always use `FileManager.default.homeDirectoryForCurrentUser`." Leaves
the lower layers (`VolumeDiscovery`, `VolumeDiscoveryAdaptor`) untouched.

### Option B — Filter at `VolumeDiscoveryAdaptor` (rejected)

Would require editing `App/Stevedore/AppEnvironment.swift`, which is outside
Session 03's declared `touches:`.

### TODO note

Leave a comment `// TODO(orchestrator): consider moving filter to VolumeDiscoveryAdaptor`
adjacent to `normalizeVolumes` so a future session can promote this to the
right architectural layer without re-auditing.

### Unmounted event

No special handling needed. If the OS sends `.unmounted` for
`/System/Volumes/Data/home`, the existing `removeAll { $0.url == url }` is a
no-op because we never insert that URL into `self.volumes`. The synthetic Home
volume uses `homeDirectoryForCurrentUser` as its URL (e.g. `/Users/aramirez`),
which is a different URL.

### Mounted event

Add a `guard !Self.isAutofsHome(vol.url) else { break }` at the top of the
`.mounted` case so a re-mount of the autofs entry after login doesn't slip
back in.

## Code — `SidebarViewModel.swift` Changes

### Add two private static helpers (after `deinit`)

```swift
// Returns true for the macOS autofs /home firmlink — never the user's real home.
private static func isAutofsHome(_ url: URL) -> Bool {
    url.path == "/System/Volumes/Data/home" || url.path == "/home"
}

// Strips the autofs entry and prepends a synthetic Home volume.
// TODO(orchestrator): consider moving filter to VolumeDiscoveryAdaptor
private static func normalizeVolumes(_ raw: [SidebarVolume]) -> [SidebarVolume] {
    let home = SidebarVolume(
        url: FileManager.default.homeDirectoryForCurrentUser,
        name: "Home",
        isEjectable: false,
        isRemovable: false
    )
    return [home] + raw.filter { !Self.isAutofsHome($0.url) }
}
```

### Update `start()` — lines 55–57

Before:
```swift
if let initial = try? await volumeDiscovery.currentVolumes() {
    self.volumes = initial
}
```

After:
```swift
if let raw = try? await volumeDiscovery.currentVolumes() {
    self.volumes = Self.normalizeVolumes(raw)
}
```

### Update `.mounted` branch — lines 68–72

Before:
```swift
case .mounted(let vol):
    if !self.volumes.contains(where: { $0.url == vol.url }) {
        self.volumes.append(vol)
    }
```

After:
```swift
case .mounted(let vol):
    guard !Self.isAutofsHome(vol.url) else { break }
    if !self.volumes.contains(where: { $0.url == vol.url }) {
        self.volumes.append(vol)
    }
```

### Add `testStartFiltersAutofsHome`

```swift
func testStartFiltersAutofsHome() async {
    let autofs = SidebarVolume.fake(path: "/System/Volumes/Data/home", name: "home")
    let fakeVols = FakeVolumeDiscovery(volumes: [autofs])
    let vm = makeSidebarViewModel(volumes: fakeVols)
    await vm.start()
    XCTAssertFalse(vm.volumes.contains(where: { $0.url.path == "/System/Volumes/Data/home" }))
    XCTAssertFalse(vm.volumes.contains(where: { $0.url.path == "/home" }))
}
```

### Add `testStartPrependsRealHomeVolume`

func testStartPrependsRealHomeVolume() async {

### Add `testMountedEventIgnoresAutofsHome`

```swift
func testMountedEventIgnoresAutofsHome() async {
    let fakeVols = FakeVolumeDiscovery(volumes: [])
    let vm = makeSidebarViewModel(volumes: fakeVols)
    await vm.start()
    let countAfterStart = vm.volumes.count

    let autofs = SidebarVolume.fake(path: "/System/Volumes/Data/home", name: "home")
    fakeVols.emit(.mounted(autofs))
    try? await Task.sleep(for: .milliseconds(50))

    XCTAssertEqual(vm.volumes.count, countAfterStart)
    XCTAssertFalse(vm.volumes.contains(where: { $0.url.path == "/System/Volumes/Data/home" }))
}
```

## Risks and Mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| Existing count assertions break | Certain — expected | Update `testStartPopulatesVolumes` (2→3) and `testStartIdempotent` (1→2) as part of step 3 |
| OS reports autofs mount via a third path variation | Low | Both known paths covered; add a note in the handoff to re-check if new macOS versions report differently |
| `homeDirectoryForCurrentUser` returns a firmlink path itself | Very low | Not possible by design; this API resolves via user database, not mount table |
| `normalizeVolumes` inserts a duplicate if `/Users/aramirez` is also a mounted volume | Negligible | Would require a separate `/Users` volume mount, which doesn't occur on standard macOS |
