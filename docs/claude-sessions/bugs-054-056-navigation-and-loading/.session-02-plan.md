# Session 02 Implementation Plan — Fix Back Navigation (Bug #054)

> Generated: 2026-05-03. Read-only planning session. No source changes made.

---

## 1. Root Cause

The history stack itself is correct and fully populated. `PaneSession.navigate(to:)` delegates to
`PaneToolbarViewModel.navigate(to:)` which calls `history.navigate(to:)` on every forward
navigation (`PaneSession.swift:39-41`, `PaneToolbarViewModel.swift:58-61`). The toolbar back
chevron (`PaneToolbar.swift:44`) calls `viewModel.goBack()` directly on `@Bindable var viewModel`,
so it works.

**The actual bug lives in the FocusedValue delivery path:**

`PaneHost.body:50` registers the proxy with SwiftUI's focused-value system:

```swift
.focusedValue(\.paneCommandProxy, self.isActive ? self.buildProxy() : nil)
```

`@FocusedValue` only propagates to the Commands tree when keyboard focus is **inside the
PaneHost subtree**. After a sidebar click, a double-click that navigates, or on first launch,
SwiftUI keyboard focus sits on the Sidebar `List` or is elsewhere. No element inside `PaneHost`
ever calls `.focusable()`, so the proxy resolves to `nil` in `GoMenuCommands`:

```swift
// GoMenu.swift:5
@FocusedValue(\.paneCommandProxy) private var proxy
```

`proxy` is nil, so `Button("Back") { proxy?.goBack() }` is disabled and ⌘[ is a no-op.
The toolbar chevron bypasses this path entirely (it calls `viewModel` directly) so it works.

## 3. Design Decisions and Rationale

### Decision A — Use `.focusedSceneValue` / `@FocusedSceneValue` (THE ROOT FIX)

`.focusedSceneValue` makes the value available throughout the entire window scene regardless of
which element holds keyboard focus. This is the correct semantic for menu-bar Commands: they
should be reachable whenever the window is key, not only when a specific responder has focus.

`@FocusedSceneValue` on the consumer side (`GoMenuCommands`) is the matching API. The
`FocusedValues` key (`paneCommandProxy`) is shared between both; no key type change needed.

**Multi-writer ordering concern**: Both `PaneHost` instances (left and right) will call
`.focusedSceneValue(\.paneCommandProxy, …)` simultaneously — one with a real proxy, one with
`nil`. SwiftUI resolves competing scene values for optional keys by preferring the non-nil value.
This is the standard merge behavior for `FocusedSceneValues` and means `isActive ? buildProxy() :
nil` works correctly regardless of which pane is active or which appears first in the view tree.

**macOS version**: `.focusedSceneValue` / `@FocusedSceneValue` are available macOS 12+.
`Package.swift:194` declares `platforms: [.macOS(.v14)]` — no compatibility risk.

### Decision B — Add first-class navigation methods to `PaneSession`

Session-01 handoff explicitly recommends this. Callers (PaneHost's `buildProxy()`, and any future
caller) should not reach into `session.toolbarViewModel` for navigation — that leaks the internal
delegation contract. Adding:

```swift
public var canGoBack: Bool    { self.toolbarViewModel.canGoBack }
public var canGoForward: Bool { self.toolbarViewModel.canGoForward }
public func goBack()          { self.toolbarViewModel.goBack() }
public func goForward()       { self.toolbarViewModel.goForward() }
public func goUp()            { self.toolbarViewModel.goUp() }
public func goHome() {
    self.navigate(to: FilePath(
        scheme: .local,
        posix: FileManager.default.homeDirectoryForCurrentUser.path
    ))
}
public func goToComputer() {
    self.navigate(to: FilePath(scheme: .local, posix: "/"))
}
```

Note: use `FileManager.default.homeDirectoryForCurrentUser.path` — not `NSHomeDirectory()` —
per operator rule. The existing `buildProxy()` in `PaneHost.swift:75` uses `NSHomeDirectory()`;
update it to use the session method after adding `goHome()`.

`goBack()` and `goForward()` delegate to `toolbarViewModel` (not to `navigate(to:)`) because
the toolbar view model manages `history` mutation and fires `onNavigate?`. Calling `navigate(to:)`
here would push a new history entry instead of popping back — breaking the history model.

### Decision C — Scope widening

The declared `touches:` for Session 02 is `[PaneSession.swift, PaneCommandProxy.swift]`. The
root fix requires `PaneHost.swift` (`.focusedValue` → `.focusedSceneValue`) and `GoMenu.swift`
(`@FocusedValue` → `@FocusedSceneValue`). Session 02 **must** include these files; fixing only
the declared scope files would leave the menu/shortcut path broken.

### Step 4 — `MainWindowTests.swift` (new tests)

```swift
// MARK: - PaneSession navigation convenience methods

func testPaneSessionCanGoBackIsFalseAtInit() {
    let session = makeTestPaneSession()
    XCTAssertFalse(session.canGoBack)
}

    let session = makeTestPaneSession()
    session.navigate(to: FilePath(scheme: .local, posix: "/Users/test/Desktop"))
    XCTAssertTrue(session.canGoBack)
}

func testPaneSessionGoBackRestoresPreviousPath() {
    let session = makeTestPaneSession()
    let original = session.currentPath
    session.navigate(to: FilePath(scheme: .local, posix: "/Users/test/Desktop"))
    session.goBack()
    XCTAssertEqual(session.currentPath, original)
}

func testPaneSessionGoBackIsNoOpWhenNoPriorHistory() {
    let session = makeTestPaneSession()
    let original = session.currentPath
    session.goBack()
    XCTAssertEqual(session.currentPath, original)
}

func testPaneSessionGoForwardAfterGoBackRestoresForwardPath() {
    let session = makeTestPaneSession()
    let forward = FilePath(scheme: .local, posix: "/Users/test/Desktop")
    session.navigate(to: forward)
    session.goBack()
    session.goForward()
    XCTAssertEqual(session.currentPath, forward)
}
```

## 8. Do-Not-Repeat Cross-Check

From `.wolf/cerebrum.md` — constraints that apply to this session:

- **PaneSession reentrancy contract** (`cerebrum.md`): `goBack()` and `goForward()` on `PaneSession`
  MUST delegate to `toolbarViewModel.goBack()` / `toolbarViewModel.goForward()` — never call
  `navigate(to:)` directly for back/forward. Calling `navigate(to:)` would push a new history
  entry instead of popping, breaking the stack.
- **`@Observable` `didSet` infinite recursion** (`cerebrum.md`): No new stored properties with
  didSet that set themselves.
- **`Tab` ambiguous on macOS 15+** (`cerebrum.md`): Any new code importing both `Core` and
  `SwiftUI` in the same file must qualify `Core.Tab` — not relevant here since no `Tab` is used.
- **`swift build 2>&1 | tee file; echo "EXIT: $?"`** (`cerebrum.md`): Use
  `swift build; echo "EXIT:$?"` (no pipe) to get the true build exit code.
