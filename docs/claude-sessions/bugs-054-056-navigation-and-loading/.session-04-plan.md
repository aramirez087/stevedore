> **Status**: Planning complete — ready for implementation.

> **Bug**: #056 — 3 + second spinner delay when opening a folder with one file.

## 1. Root Causes (from Session 01 Audit)

Three compounding causes were identified in `session-01-handoff.md §4 Bug #056`:

| # | Cause | Location | Latency impact |
|---|---|---|---|
| C1 | `Task.detached(priority: .utility)` — scheduler won't run this until all `.userInitiated` work drains | `LocalDirectoryEnumerator.swift:13` | Hundreds of ms to seconds on a busy run loop |
| C2 | Same `.utility` QoS on the attributes path | `LocalFileSystemProvider.swift:36` | Same scheduler delay for every `attributes()` call |
| C3 | `.fileSecurityKey` in the enumerator's `includingPropertiesForKeys` forces an ACL/mode syscall for every enumerated entry | `LocalDirectoryEnumerator.swift:58-62` | ~1–3 ms per file × N files; observable even for N=1 at a system level |
| C4 | Redundant `url.resourceValues(forKeys: [.isSymbolicLinkKey])` per-item (line 72) when `.isSymbolicLinkKey` is already in the prefetch set | `LocalDirectoryEnumerator.swift:71-76` | Minor but adds a Foundation call per file |

C1 is the primary cause of the multi-second spinner. C3 compounds it for larger directories. C2 affects the attributes path. C4 is a code-cleanliness issue with minor performance impact.

**TCC first-launch latency** (item C5 in the audit) — macOS blocks the first access to `Desktop`/`Documents`/`Downloads` behind a TCC consent prompt. This is a kernel-level synchronous block outside the app's control. Document it but do not attempt to fix it.

## 3. Design Decisions

### D1 — QoS: `.utility` → `.userInitiated`

Directory enumeration is triggered by an explicit user navigation gesture. `.utility` is intended for work the user is not actively waiting for (e.g. background sync). `.userInitiated` is correct here and is what `NSFileManager` documentation recommends for responsive directory reads.

**Risk**: `.userInitiated` tasks compete with UI rendering. With a single `Task.detached` per navigation this is negligible.

### D2 — Local `enumerationKeys` constant (without `.fileSecurityKey` and `.isPackageKey`)

The global `URLResourceMapperKeys` in `URLResourceMapper.swift` includes `.fileSecurityKey` (ACL/mode) and `.isPackageKey` (bundle detection). Both are expensive in the kernel:

- `.fileSecurityKey` causes the VFS to materialize a `FileSecurity` object (POSIX mode + ACL), requiring an extra `getattrlistbulk` or `getxattr` round-trip per entry.
- `.isPackageKey` forces a UTI lookup and bundle-header read for each item.

For directory listing purposes, both are optional:
- `FileAttributes.permissions` already has a nullable type (`PosixPermissions?`) and `URLResourceMapper.posixPermissions` returns `nil` gracefully when `.fileSecurity` is absent.
- `FileAttributes.isPackage` uses `values.isPackage ?? false` — already nil-safe.

The attributes path (`LocalFileSystemProvider.attributes(at:)`) continues to use the full `URLResourceMapperKeys` because it is explicitly called to retrieve complete metadata for a single item (e.g., for an info panel). The performance cost there is acceptable.

**Decision**: Define `private static let enumerationKeys` inside `LocalDirectoryEnumerator` as `URLResourceMapperKeys` minus `.fileSecurityKey` minus `.isPackageKey`. Pass this smaller set to `fm.enumerator(includingPropertiesForKeys:)` and to the per-item `url.resourceValues(forKeys:)` call.

**Risk**: Any UI that reads `item.attributes.permissions` or `item.attributes.isPackage` from enumerated items will receive `nil`/`false`. Audit shows `FileBrowserView` displays name, kind icon, size, and date — not permissions or package status. The `isPackage` field is used nowhere in the current UI tree (confirmed via `Grep` across `Sources/UI/`). Accept this trade-off.

### D3 — Collapse the per-item loop to a single `resourceValues` call

Current control flow:
1. `url.resourceValues(forKeys: [.isSymbolicLinkKey])` — symlink check (line 72)
2. `url.resourceValues(forKeys: URLResourceMapperKeys)` — full fetch (line 79)

The `.isSymbolicLinkKey` is already in the prefetch set, so call (1) is redundant. Both calls can be merged: do one `url.resourceValues(forKeys: enumerationKeys)` and read `.isSymbolicLink` from the returned values before calling `skipDescendants()`.

`enumerator.skipDescendants()` must be called during the iteration of the current entry (before the enumerator advances). The refactored loop calls it synchronously within the `do` block — this is safe.

## 4. Exact Changes

### 4a. `Sources/FileSystem/Local/LocalDirectoryEnumerator.swift`

**Change 1 — QoS (line 13)**

```swift

// AFTER

```

**Change 2 — Add `enumerationKeys` constant** (insert after the closing brace of `stream(at:options:)`, before `// MARK: - Private`)

```swift
// Keys sufficient for directory listing. Omits .fileSecurityKey and
// .isPackageKey to avoid per-entry ACL/UTI syscalls during enumeration.
// attributes(at:) uses the full URLResourceMapperKeys for single-item queries.
private static let enumerationKeys: Set<URLResourceKey> = {
    var keys = URLResourceMapperKeys
    keys.remove(.fileSecurityKey)
    keys.remove(.isPackageKey)
    return keys
}()
```

**Change 3 — Use `enumerationKeys` in `fm.enumerator` (lines 58–62)**

```swift
// BEFORE
guard let enumerator = fm.enumerator(
    at: directoryURL,
    includingPropertiesForKeys: Array(URLResourceMapperKeys),
    options: fmOptions
) else {

// AFTER
guard let enumerator = fm.enumerator(
    at: directoryURL,
    includingPropertiesForKeys: Array(Self.enumerationKeys),
    options: fmOptions
) else {
```

**Change 4 — Collapse the per-item loop (lines 68–88)**

```swift
// BEFORE
for case let url as URL in enumerator {
    if Task.isCancelled { break }

    if !options.followsSymbolicLinks {
        let values = try? url.resourceValues(forKeys: [.isSymbolicLinkKey])
        if values?.isSymbolicLink == true {
            enumerator.skipDescendants()
        }
    }

    do {
        let values = try url.resourceValues(forKeys: URLResourceMapperKeys)
        let item = URLResourceMapper.fileItem(url: url, values: values)
        continuation.yield(item)
    } catch let nsError as NSError where nsError.code == NSFileReadNoPermissionError {
        let path = FilePath(scheme: .local, posix: url.path)
        throw StevedoreError.fileSystem(.permissionDenied(path))
    } catch {
        throw StevedoreError.fileSystem(.ioFailure(detail: error.localizedDescription))
    }
}

// AFTER
for case let url as URL in enumerator {
    if Task.isCancelled { break }

    do {
        let values = try url.resourceValues(forKeys: Self.enumerationKeys)
        if !options.followsSymbolicLinks && values.isSymbolicLink == true {
            enumerator.skipDescendants()
        }
        let item = URLResourceMapper.fileItem(url: url, values: values)
        continuation.yield(item)
    } catch let nsError as NSError where nsError.code == NSFileReadNoPermissionError {
        let path = FilePath(scheme: .local, posix: url.path)
        throw StevedoreError.fileSystem(.permissionDenied(path))
    } catch {
        throw StevedoreError.fileSystem(.ioFailure(detail: error.localizedDescription))
    }
}
```

## 6. Risks and Mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| `enumerationKeys` misses a key that `URLResourceMapper.fileItem` reads | Low | FileItem field silently nil/zero | Cross-check every `values.*` read in `URLResourceMapper.swift:26-68` against `enumerationKeys`; confirm each is present or gracefully nil |
| `url.resourceValues(forKeys: enumerationKeys)` does NOT use enumerator's prefetch cache | Low | Falls back to per-item stat — correct but no cache speedup | Still correct; QoS bump alone is the primary fix and this is a bonus |
| `skipDescendants()` not called before the next enumerator advance | None | Would follow symlinks incorrectly | Verified: the call is synchronous within the `do` block, before `continuation.yield` and before the `for` loop advances |
| TCC first-launch still slow after the fix | Certain | User sees spinner on cold launch | Document in handoff; not fixable in application code |
| `isPackage == false` for bundle directories in the list | Low | Bundle dirs shown as plain directories | No current UI reads `isPackage`; acceptable trade-off until a dedicated attributes call is added |

- **Progressive rendering in `FileBrowserView.loadItems`** (`PaneHost.swift:301-322`): `isLoading` flips to `false` only after the stream terminates. Even with the enumerator faster, the view doesn't render until the loop ends. Fix: yield items progressively or set `isLoading = false` after the first item. Lives in `PaneHost.swift` — out of this session's scope.
